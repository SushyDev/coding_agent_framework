# F-183: one clear, the first remedy on the healer (`absent_main`), and `Remedies.tla`

F-182 built the healer's one shape and stopped before its remedies. This unit builds the one
clear (item 1), the `absent_main` remedy (item 3), the flaky test's wait (item 5) and the model
of both new remedies (item 6). It stops on item 2 (`stuck_background`) and item 4
(`mcp_dropped`, `hooks_silent`), whose readings the design and the recorded logs do not settle
(new-1, new-2). No test or step of it started the real Claude Code.

## What was built

- **One clear** (item 1, F-182's new-2). `Watch.clear/3` (id, by): a person's clear of a
  symptom state that waits on one, the `remedy` prompt's answer `"leave"`; `answer/5` with either
  choice clears it the same way, and its `answered_at` is the clear's time. `Watch.read/3` takes
  a `state:` filter. `Recoveries.clear/2` is gone. Each check of `Recoveries` first reads its
  rows that wait for a person (a loss that repeated, an end that settled unknown, never
  cleared), looks up each one's symptom state in the `Watch`, and copies the answer's time (or,
  for a prompt that passed with its target, the pass's time: new-3) onto the row as `cleared_at`
  (`Acts.clear/3`'s new `at:`), where its keys and counts read it. So those reads stay narrow,
  and the rest of `Recoveries` is unchanged. `Recoveries` reads the `watch` cue too, so an answer
  is acted on at once. A state whose claim already ended badly (failed, unknown, interrupted)
  and whose symptom is still `open` is now asked (`Heal.tla`'s `Ended`): an ask the healer's
  own step lost, as a crash between its settle and its ask would lose it, is not lost.
- **`absent_main`** (item 3; `CodingAgentFramework.AbsentMains`, in `caf_recoveries`, one per
  instance, after `Mains` in the tree, reading `sessions` and `watch`). An absence is a main
  session's agent row `stopped` with reason `exited` (its process ended by itself, as `Sessions`
  settles it by pid and start time and a dead socket). An ended, an imported or a moving main is
  not absent. One state per process that went: `absent_main:<name>:<started_at>`. On F-182's
  shape: recorded in the `Watch` first; decided by a row in `Acts` if one exists; asked when off
  the list, past the kind's cap, or when the main was already resumed within the bound (a second
  absence in it, `again_within`); else claimed in `Acts` (act `resume`, actor
  `absent_mains:<host>`) and resumed once by `Mains.resume_main/3`, which takes the
  `Scheduler`'s lease. An ok is verified at once from the row (running or starting is recovered;
  otherwise the remedy leaves the list and the state is asked); refused and unknown are asked
  and never tried again in that state; a claim a restart cut is asked at `init`. The default
  allow-list has `absent_main` by `resume`, 10 per bound.
- **The flaky test** (item 5, F-155's new-12). `sessions_options_test.exs` now reads `Stream`'s
  fold until the start's first line is delivered and its turn is idle before it stops the
  session, as the headless tests do (new-6).
- **`model/tla/Remedies.tla`** (item 6). It instances `Heal.tla` as `H`, beside `Boxes.tla`'s
  stuck turn, with two kinds: `stuck_background` (a delegate; its remedy hands the parent a
  `partial` report under the claim and ends the hung group, and the delegate's own report comes
  later) and `absent_main` (a main; its remedy is one resume, and a second absence in the bound
  is asked). New properties: `PartialOnce` (one state's partial is handed once),
  `ResumeOncePerBound`, and, as liveness, `ReportTaken` (the delegate's own report, once
  written, is taken: a partial never stands in for it). Every property of `Heal.tla` is checked
  through `H`. Three breaks, each failing: `PartialStands` (`ReportTaken`), `PartialTwice`
  (`PartialOnce`), `ResumeTwice` (`ResumeOncePerBound`). `Heal.tla` changed only in its header;
  `Boxes.tla` is unchanged (new-4).
- **Docs**: `docs/design.md` ("Metrics and healing": the one clear and what F-183 built; "The
  delegate protocol": the `partial` report's properties and what is not built; the parts table;
  B8), the README.

## What I ran into

- `Boxes.tla` instances `Heal.tla` with every variable by name, so a variable added to `Heal.tla`
  must be added to or substituted in `Boxes.tla`, which F-181 is changing (new-4).
- `SessionsSetup` starts `Stream` with no `notify:`, so a test has no cue that announces a
  headless turn's end (new-6).
- `Remedies.tla`'s `ReportTaken` with a bound and a restart costs minutes; the fast design drops
  both, which `Heal_Design` already checks for the shape.

## Findings

### new-1. `stuck_background`'s "turn ended with its report owed" is not a state the code reads

What happened: the symptom is a delegate whose turn ended with its report owed while a
background command of it hangs. As the code stands, that state does not arise. A headless
delegate's report is taken at the `result` that names its brief (`Delegates.Turn.next/2`), even
while its fold's `tasks` holds a running background command (`Sessions.Turn` then reads
`:running`, but nothing waits on that for the report). An interactive delegate's is taken at
its turn's end. So the report is not owed while a command hangs, unless Claude Code withholds
the `result` until its background commands end. No recorded log shows which: the stream's
task events are Claude Code's own types, not yet checked against a log (F-171's new-4). No
code reads a process tree or CPU time either. Why: F-180's new-6 named the symptom from what a
hung `cat` did before F-180 gave background commands end of file, not from a recorded run.
What I did: nothing of its detector or remedy. Its model is in `Remedies.tla`, ready. What the
design should change: the pinned release's check records a headless session that runs
`sleep 300` with `run_in_background: true`, and writes down the order of `task_started`,
`result` and `task_notification`. If `result` comes while the command runs, the report is not
held up, and the symptom is a delegate whose report was taken while a background command of
its turn has used no CPU time for a bound. It holds the cap, and `Sessions.stop/2` refuses it
`turn_running`. Then the remedy is only the group's end by its record, with no partial report.
If `result` is withheld, the detector reads "brief delivered, no result, `tasks` not empty, the
transcript's last assistant message ended", and the partial report is a `Mailbox` row of kind
`reply` with subtype `partial`, keyed `partial:<state>` (so `Mailbox` takes it once), and
framed `report (partial)` for the parent. Either way the CPU time is read from
`/proc/<pid>/stat` of the group's members on Linux and is `unknown` on macOS.

### new-2. `mcp_dropped` and `hooks_silent` need readings no one has recorded

What happened: `mcp_dropped` reads the framework's MCP server gone from an agent's tools, from
the transcript's tool errors or the MCP log in the home's XDG cache. Neither shape is recorded
for the pinned release (the log's path and lines, and the error text of a call to a server
that went). `hooks_silent` reads no hook event for a bound while a turn runs. A turn with no tool
call fires no `PreToolUse`, so silence alone is no symptom. Why: both are readings of Claude
Code's own files, which this repository takes only from the pinned release, never from a
stand-in. What I did: nothing; with no detector, an entry on the list shows nothing. What the
design should change: the release check captures an MCP server ended during a session (its
log lines and the next call's error). `hooks_silent` is a tool call the transcript shows with
no `Intake` row of its session within a bound. Then both are one detector that records into
the `Watch`, with nil remedies on the list.

### new-3. A `remedy` prompt that passed clears its state

What happened: an asked state passes when its target no longer shows the kind (F-182). A
repeating viewer's prompt passes once a person or another part opens the viewer. No answer can
come to it then. If only an answer cleared it, the socket would stay blocked for ever, and its
later losses would not even be recorded, since `Recoveries` leaves a repeating socket out
before the `Watch` sees it. Why: the design says the answer clears, and is silent on a pass.
What I did: the healer takes a pass's time as the clear, as it takes an answer's. What the
design should change: confirm. The design's text says so now.

### new-4. The model of these remedies is a spec of its own, not text in `Heal.tla`

What happened: the brief asks to keep this unit's model in `Heal.tla` and leave `Boxes.tla` as
it is. The partial report and the per-main bound need state of their own (the partials handed,
the delegate's own report, the resumes in the bound). `Boxes.tla` instances `Heal.tla` by
variable name, so that state in `Heal.tla` would change `Boxes.tla`. What I did:
`Remedies.tla` instances `Heal.tla`, as `Boxes.tla` does, and adds that state and its three
properties. `Heal.tla` changed only in its header. What the design should change: nothing,
unless a property must hold across both instances. Then `Boxes.tla` composes `Remedies.tla`
after F-181 lands.

### new-5. A main a person left by `/exit` reads as absent

What happened: `Sessions` settles any process that ended by itself as `stopped`, reason
`exited`: a crash, a kill and a person's `/exit` alike. So the healer resumes a main its person
left on purpose, once. A second time within the bound, it asks. Why: no reading tells a
person's exit from a crash. The exit dialog's reading is not built (F-180's new-2). What I did:
nothing more. What the design should change: once that reading is built, `Sessions` records an
exit a person confirmed (reason `exit`, say), and `AbsentMains` does not take it as an absence.

### new-6. A test has no announced event for a headless turn's end

What happened: the rules say tests wait on announced events. `SessionsSetup` gives `Stream` no
`notify:`, so the `stream:<host>` cue never reaches the test. The options test, like the
headless tests, reads `Stream`'s fold through `await` until the turn reads ended. That is a
check of the read state, not a timer, but it is not an announced event. What I did: the same
wait as the headless tests. What the design should change: `SessionsSetup` hands `Stream` a
`notify:` that sends the test its cue, and the tests that wait for a turn's end receive it.
That is a small unit across `caf_sessions`' tests.

Also: `AbsentMains` resumes through `Mains.resume_main/3` directly, not through
`Team.operate/4`, as F-182's new-1 says of `Recoveries`; its test uses a stand-in resume
function, since `MainsTest` checks the resume's own contract.
