# F-73: `Grants`: who may act on whom

Two parts: a model change to `Team.tla`, its own commit, then a new app, `caf_grants`, with
the checks of who may act on whom. The claim table the brief also asked for did not fit in 500
lines and is left for the next unit (new-1).

## What was built

**`Team.tla` follows the design on a message to an ended delegate.** F-69 sent it back to its
sender (`Redirected`, which turned the row's `dest` to the delegate's main session). The design
now says it is not delivered: its row says the delegate ended before it went in, and the sender
learns that in place of `delivered`, from a settled row.

- `EndedFirst(i)` marks a settled (`"queued"`) row whose addressee has ended `"ended"`. The
  row loses `dest`; every step types into `msgs[i].to`.
- `AlongEdges` is now "to its addressee", with no case for the main session.
- New invariant `EndedNotDelivered`: an `"ended"` row's message is in no transcript.
- `MessageDelivered` reads the addressee only. New property `EndedMarked`: a message still
  waiting when its delegate has ended settles, `"delivered"` or `"ended"`.
- `NoRedirect` is now `NoEndedMark` (`EndedMarked` fails), and `RedirectUnsettled` is now
  `EndedUnsettled` (`EndedNotDelivered` fails: a restart after the write, the delegate ends,
  and an unsettled row is marked `"ended"` while the message is in the transcript). Their
  configuration files are renamed to match.
- The header drops `Redirected`'s defense in depth, which no longer exists.
- `READING.md` says the same.

**`caf_grants`: `CodingAgentFramework.Grants`**, a pure module with no process and no other
umbrella app.

- **The tree** is a function the embedding app hands `Grants.new/1`. It answers one map per
  delegate, `%{name, project, parent}` (for now, `Delegates`' rows). `Grants` calls it at each
  check and keeps nothing. Main sessions are the parents no entry names as a delegate.
- **The checks**, one per kind of act in the tools table's "Who" column, each `:ok` or
  `{:refused, reason}`, the reason named for the rule: `may_message?/3` (`:along_edges`),
  `may_read?/3` for `look` and `transcript` (`:close_read_along_edges`), `may_fix?/3`
  (`:no_self_fix`, `:main_never_fixed`, `:only_parent_fixes`), `may_fix_service?/3`
  (`:service_fixed_by_owner_or_parent`), `may_hand?/4` (`:handed_by_owner`,
  `:handed_along_edge`). A name the tree does not hold is `{:unknown_agent, name}`; a delegate
  two entries give different parents is `{:two_parents, name}`, for every check.
- **Tests**: four properties over generated trees (two projects, one to three delegates per
  main session), each named for the `Team.tla` invariant it checks: `AlongEdges` (messages and
  close reads), `OnlyParentFixes`/`NoSelfFix`/`MainNeverFixed`, `ServiceFixedByOwnerOrParent`,
  `HandedAlongEdge`. Each property checks every pair (or triple) of agents against what the
  generator says each agent is, stated apart from `Grants`. Three tests: unknown names, two
  parents, and the tree read again at each check. No processes, no tmux.
- The README's app graph names `caf_grants`.

## Findings

### new-1. The claims table is the next unit

What happened: the claims (one row per claim on a target's state, written before the fix
acts, `{:claimed, by}` for a second claim, verified or not at the end, closed as interrupted
by a restart, never retried) did not fit in this unit's 500 lines. Why: the table, its rules'
tests and a property over random claims came to about 290 lines. What I did: left them out of
the branch. A working draft, with tests that passed, is in this worktree's ignored
`tmp/f-73-claims/`. What the design should change: nothing. The order of the units should give
the claims a unit of their own. That unit has to settle new-2.

### new-2. What closes a claim as interrupted

What happened: the design says "a claim a restart of the framework cut off is closed as
interrupted, never retried", and `Team.tla`'s `ClaimSettled` closes a claim whose call is not
under way (`r \notin calls`), which after a restart is every open one. The code cannot see
`calls`. The draft closes every `claimed` row when the table is opened, which is right only if
the framework opens it once as it starts, before any call. A second open while calls run, by a
reader or a second instance on the same home, would close live claims. Why: `Grants` is a pure
module with no process, so nothing marks which start a claim belongs to. What I did: nothing in
this branch. What the design should change: say how a cut claim is told from a live one. I
recommend that each claim row carry the id of the framework start that wrote it (a value the
embedding app makes once per start and hands to `Grants`). A row with another start's id that
is still `claimed` is then cut off. This needs no process and makes the close safe on any open.

### new-3. A main session with no delegate is not in the tree

What happened: "Main sessions are the parents no row names as a delegate" means a main session
is held only once it has started a delegate. Until then every check that names it answers
`{:refused, {:unknown_agent, name}}`: another main session cannot message it, and it cannot
fix or hand its own service. Why: until `Mains` exists, `Delegates`' rows are the only record
of a main session's name. What I did: built it as the brief says, and a test states it. What
the design should change: the tree's main sessions should come from what holds them. I
recommend that the tree function answer both, `%{mains: [name], delegates: [%{name, project,
parent}]}`, the main sessions coming from the projects' data until `Mains` exists, so that
`Grants` does not change when `Mains` is built.

### new-4. A parent the caller states can disagree with another row

What happened: `Delegates` takes the parent as the caller states it. Two rows can name one
delegate (its name comes from the project and branch) with different parents, and nothing
refuses the second. `Grants` refuses every check while that holds
(`{:refused, {:two_parents, name}}`), rather than pick one. Why: `Mains` does not exist to say
which main session a project has. What I did: the refusal and its test. What the design should
change: `Delegates` should refuse a start whose parent is not the project's main session, once
`Mains` holds it, so the tree cannot hold two parents for one name.

### new-5. Whether an agent may read itself closely

What happened: the design opens `look` and `transcript` to the target's parent, its children
and, for a main session, the other main sessions. That is the edge relation, so an agent's
close read of itself is refused (`:close_read_along_edges`). `Team.tla` leaves reading
abstract, so no model decides it. What I did: built the rule as written. What the design should
change: say whether an agent may `look` at itself. I recommend no: it is in its own turn and has
its own transcript, and the rule stays one relation.
