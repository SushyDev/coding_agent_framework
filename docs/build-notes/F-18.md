# F-18: `Usage`, each account's allowance

## The source

Read from the devenv Claude Code 2.1.322 (`$CAF_CLAUDE`): the strings of its binary, which
hold its `statusLine` documentation, the settings schema and the code that builds the status
line's input. No session was started and no credential or person's config directory was read.

- The JSON Claude Code hands a `statusLine` command on its input has `rate_limits`, with
  `five_hour` and `seven_day`, each `{used_percentage: 0-100, resets_at: Unix seconds}`, and
  `spend_limit` behind a gateway. It is "only present for subscribers ... after first API
  response, while at least one window is present", and each window only "while the API reports
  it and its resets_at has not passed". The code adds `rate_limits` only when one of the three
  windows is there.
- The input also carries `session_id`, `transcript_path`, `cwd`, `model`, `workspace`,
  `version`, `context_window` and the like; none is a credential.
- The command runs on events (each answer, a change of model or mode) and, with
  `refreshInterval`, every N seconds. It is skipped until the workspace is trusted ("Status line
  command skipped: workspace trust not accepted"), and `disableAllHooks` turns it off.
- Hooks' inputs carry no rate limits. The `/usage` screen and `rate_limits_available` come from a
  call Claude Code makes with its own login, which the framework must not make.

So the source is the status line, and the framework reads no credential and calls no API.

## What was built

- **`Accounts.prepare/3`** takes `:programs` (the host's `Programs`, for sh and cat). With it,
  it writes `<config>/framework/statusline.sh` and sets `statusLine` in both role settings
  files to run it by absolute paths. The script copies its input to `Accounts.usage_file/2`,
  `<home>/usage/<account>.json`, only when the text has `"seven_day"`, so a session's text before
  its first answer never replaces a reading. It prints nothing. Every word is quoted for sh.
- **`Usage.Reading`**: pure, total parse of that text into `%{used, resets_at}`, or
  `{:malformed, reason}`; `current?/2` is false once the window has reset.
- **`Usage`**: one process per instance. A read takes each account's file's change time, then its
  bytes, through `:prim_file`, so no call goes through the VM's file server. It writes changed
  rows to `Usage.Table` (`usage_readings`, `usage_reads`), which it alone writes, and cues
  `usage:<host>:<account>` with row ids. `:unread` before the first read; a malformed or
  unreadable file keeps the last good reading and names the problem; a gone file deletes its
  row. Each reading keeps `seen_at`, the file's change time, so its age shows.
- **`Usage.pick/3`** (`pick/2` with the clock): the account among those given whose current
  reading has used the least, ties to the first name, or `{:refused, :none_known}`.
- **`Tracker.UsageSource`**: the table as a `Tracker` source per account, kind `:usage`, scope
  `{host, account}`. The fold needed no change.
- **Tests** (`test/usage_test.exs`): the written command run by sh with a synthetic input, under
  a home whose path has a quote; a text with no weekly window kept out; a half-written file
  keeping the last reading. Properties: `pick/3` over generated readings (current, reset, empty,
  other shapes, absent, accounts given twice or unknown), and the reader over rounds of files
  (good, wrong types, a missing field, not JSON, random bytes, gone).

## Measured

- `gate-test` alone: 90 passed (24 doctests, 8 properties, 58 tests), 5.2 s in ExUnit.
- `devenv test` exit 0.
- About 760 changed lines, over the 500 aimed for: about 485 in `lib/` (much of it docs), 170
  in tests, and this note. `Usage.Table` and the source follow `Registry`'s; the status line
  command in `Accounts` could have been its own unit after `Usage`.

## What I ran into

- The script writes its file in place, without a rename: `Programs` has no `mv`. A read that
  meets a half-written file keeps the last reading with `:not_json`, and the next read heals it.
- Two sessions on one account write the same file; the last one wins, and both carry the same
  account's allowance.

## Findings

### new-1. A reading after its reset says nothing, so an idle account is never picked

What happened: a window's `resets_at` passes, and the share used since is unknown. `pick` leaves
such an account out. Sessions start only on a picked account, so an account whose reading reset
gets no session and so no new reading, while any other account is known.

Why: the only source is a running session on that account, and the allowance is shared with the
person's own use of the account elsewhere.

What I did: nothing past leaving it out; `pick` never guesses.

What the design should change: say what a reset reading counts as. A concrete choice: after its
`resets_at`, a reading counts as 0 % used, marked as assumed, since the window started anew; or
`Delegates` starts on such an account when every known one is above a bound.

### new-2. An old reading understates what is used

What happened: a reading is as new as the last status line drawn on that account. Use outside
the framework's sessions, or an account with no session for a day, makes it low.

What I did: each reading keeps `seen_at`, and views can show its age. `pick` does not weigh it.

What the design should change: a bound on a reading's age for the 90 % move, and whether `pick`
prefers a fresh reading over an old lower one.

### new-3. The status line needs a trusted workspace and hooks on

What happened: 2.1.322 skips the command until the workspace is trusted, and does not run it with
`disableAllHooks`. A delegate in a new worktree may not be trusted yet.

What the design should change: a check, when a session starts, that its account's file was
written after its first answer, flagged when it was not; and the settings never set
`disableAllHooks`.

### new-4. `Usage` reads this machine's home only

What happened: like `Accounts` (F-15 new-3), `Usage` reads local files.

What the design should change: when a remote host runs sessions, its script's file is read
through `Shell`, the way `Registry` reads.
