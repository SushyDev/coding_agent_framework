# F-163: B1 part 1, each box's contract and `Boxes.tla`

A model unit: specs, configurations and the design's text; no Elixir. It is the first of B1's
five parts ("Order of the first units"): each box's contract stated in its spec's header, and one
composed spec, `Boxes.tla`, that checks the boxes together through those contracts.

## What was built

- **`model/tla/Boxes.tla`** (726 lines). The seven boxes over the `Ledger`, each only as what it
  promises at its interface and what it assumes of the boxes it calls:
  - `Sessions`: the agent row, the process outside the BEAM (a count, so a relaunch shows as
    two), its number (`gen`), its turn (ended, a row's, a person's), a stuck turn and the state
    number a claim takes (`ep`); the stop as an idle read and a SIGTERM; `hand` as one write into
    an ended turn of the process the mark names, else refused; the dialog's checked press with
    keys that may still be on their way; the agent process's memory (a press to send, a stop's
    read, the hand's answer) and its restart budget.
  - `Mailbox`: the mark (oldest due first, one in flight, only into a running row's ended turn),
    the call through `Sessions.hand`, refused undoing the mark and anything else keeping it,
    and the settle by the evidence once no call is under way.
  - `Prompts`: a dialog's prompt (`open`, `answering`, `unknown`, `answered`, `withdrawn`) and a
    `restarts` prompt; an answer marked before it is handed, a cut one settled by the owner's
    evidence, unknown kept for a person's clear.
  - `Scheduler`: seats within a capacity, released once the owner says the work ended.
  - `Team`: a parent's fix, its need (a stuck turn) checked on the state the claim takes.
  - `Watch`: a symptom read from the facts, and a remedy through the same `operate/4` and the
    same claim, its precondition read on the state it claims.
  - the `Ledger`: `Claim.tla` instanced whole, on each agent's state number.
  - `Hosts` is left out: no interaction the design names needs more of it than
    `Schedule.tla`'s `NoRunUnleased`.

  The addressee of every row lives the whole life; any other agent only takes a seat, runs, ends
  and gives it back, and has a budget another's crash could spend. That is all the seats and the
  budgets need of it, and it keeps the safety configuration small (see "What I ran into").
- **The interactions**, each a property with a `Break_Boxes_*` that TLC fails:

  | Interaction | Property | Break |
  |---|---|---|
  | a delivery during a move | `NotCutByStop` | `MarkWhileStopping` |
  | | `OnlyToItsProcess` | `NoProcessCheck` |
  | a lease across a dialog | `SeatsHold` (with `LeaseWhileLive`) | `DialogEndsWork` |
  | a prompt across a restart | `OneAnswer` | `ReopenCut` |
  | | `KeptAcrossRestart` | `PromptInMemory` |
  | a remedy racing a fix | `OneActPerState` | `HealerOwnClaim` |
  | | `NeverWorking` | `StaleSymptom` |
  | one agent's restart and the whole one | `OneProcess` | `Relaunch` |
  | | `AtMostOnce` | `UnknownUndoes` |
  | | `OwnBudget` | `SharedBudget` |
  | | `Escalated` (liveness) | `SilentGiveUp` |

  Beside them the `Ledger`'s `OneClaimPerState` and `NoActOnCutOffClaim`, and liveness
  `DialogPasses`, `EndedIsReleased`, `SendingSettles` and `ClaimsEnd`.
- **`Boxes_Safety.cfg`** (two agents on one seat, one row, one dialog, one stuck turn, a crash
  of each agent process, a whole restart) and **`Boxes_Liveness.cfg`** (one agent, the same
  events), and eleven `Break_Boxes_*.cfg`.
- **Each contract spec's header** gains a paragraph: which box it is the contract of, the
  properties it exports as that contract, how they imply what `Boxes.tla` assumes (an argued
  mapping; `Claim.tla`'s is the identity, since `Boxes.tla` instances it), and what they do not
  imply. In `Claim`, `Start`, `Agent`, `Move`, `Dialog`, `Stream`, `Intake`, `Hold`, `Delivery`,
  `Team`, `Delegate`, `Checkout`, `Schedule`, `Copy` and `Shell` (the last a base mechanism, not
  a box). `Prompts` and the `Watch` have no spec yet: `Boxes.tla`'s header states their
  contracts, which `Prompt.tla` and `Heal.tla` will refine.
- **The design**: "The model" gains a paragraph on `Boxes.tla`; B1 says its first part is built.

The seams for B1's later parts: `Restart(a)` here is the step `Start.tla`, `Delegate.tla`,
`Dialog.tla` and `Move.tla` gain; `pr` and `rp` are the state `Prompt.tla` refines; the healer's
steps are `Heal.tla`'s, which adds the allow-list and the cap; `Delivery.tla`'s subscription
adds a way for a row to become due, which this spec leaves out.

Each Break's trace was read for the three hardest: `ReopenCut` (answer, press, whole restart,

did not help, then the healer on the same state) and `UnknownUndoes` (a hand cut by a restart

No existing spec's behavior changed: their headers gained comments only, so their state counts
are as before. The whole fast set ran in `devenv test`'s `gate-model` (below).

## What I ran into

- **The first safety configuration was far too large.** With both agents living the whole life
  (turns, stops, resumes, stuck turns, prompts), TLC had found 72 million distinct states after
  ten minutes and was still going. Only the seats and the budgets need a second agent, so every
  other agent now only takes a seat, runs, ends and gives it back: 250,844 states in 5 s.
- **`KeptAcrossRestart` first failed on the design.** The press task tells `Prompts` "answered"
  as soon as the keys are sent, before they land, so a session can be on its dialog with its
  prompt answered. The property now allows an answered prompt whose keys are on their way, which
  is what `Dialog.tla`'s mark allows too.
- **A stop may cut a person's turn.** `Move.tla` says a prompt through Remote Control may start
  a turn between the idle read and the SIGTERM, and the SIGTERM cuts it; only a row's turn must
  never be cut. So the turn says whose it is, and `NotCutByStop` is about a row's.
- **Fairness on a disjunction was too weak**, so each box's step has its own weak fairness, and
  the mark strong fairness, as `Delivery.tla` has it.
- **The first `devenv test` stopped at the git hooks**: `mix-format` said it modified files,
  though none changed and `mix format --check-formatted` passed. It was the first run in this
  worktree; see the gates below for the later runs.

## Findings

### new-1. An owner may say a lease's work ended while its process lives

What happened: `Boxes.tla`'s `SeatsHold` rests on the owner's promise that work it reports
ended has no live process. `Schedule.tla` takes that as its environment (`work`), and
`Dialog.tla` checks it for a start on a dialog only. `Start.tla` lets an agent row be `refused`
or `orphan` while its process still lives (`NotGivenUpEarly`: a session file that came after
the deadline), until `Recoveries` ends it. `Delegate.tla`'s start is one step and its
`RefusedHoldsNothing` assumes a refused start holds nothing, and `Delegates.Work` answers a
`refused` delegate row `:ended` at once, without asking whether its agent row is free.
Why: the release reads one table's status, while the process is the agent row's.
What I did: stated the gap in the headers of `Schedule.tla`, `Start.tla` and `Delegate.tla`;
`Boxes.tla` checks the promise for its own statuses (`DialogEndsWork` breaks it). I did not
check the code path that writes a refused delegate row against the agent row's end.
What the design should change: the owner's promise becomes a property: "work ended implies no
process of it lives", checked where the owner's statuses are (`Start.tla` with the lease as a
ghost, or B1's `Restart(a)` part). `Delegates.Work` answers `:ended` for a refused row only
once `Sessions.Agents.free?/1` holds of its agent row, as it already does for a finished one.

### new-2. `Delivery.tla` has no cut of a hand by the addressee's own restart

What happened: in `Delivery.tla` a hand is cut only by a restart of the whole framework, since
`Mailbox` is one process. After B4 the transport's write runs in the addressee's agent process,
whose crash alone cuts the call and answers `{:unknown, :restarted}`; `Mailbox` must keep the
mark then, as for any unknown. `Boxes.tla` checks that at the contract level
(`UnknownUndoes` breaks it), but no spec checks it against the transports themselves.
Why: the per-agent restart is new with B4.
What I did: named it in `Delivery.tla`'s header.
What the design should change: B1's `Restart(a)` part adds, in `Delivery.tla`, a cut of the
hand by the addressee's restart, beside the whole one, with `AtMostOnce` and `SendingSettles`
checked under it.

### new-3. A `Mailbox` test asserts a row is still queued after a cue it races

What happened: the second `devenv test` failed one test, `caf_mailbox`'s "a delegate that ended
takes nothing: its queued rows are settled ended" (`apps/caf_mailbox/test/mailbox_test.exs:71`):
its last line asserts that a brief queued to the ended delegate is still `queued` after `cue/1`,
and `Mailbox` had already settled it `ended`. This branch changes no Elixir. Run alone with the
same seed (166889), the file passed four times in a row.
Why: as far as I can tell, `Mailbox` settles a row to an ended agent on any cue it handles, so
whether the brief is still `queued` at the assert depends on which cue the `Mailbox` process
handles first under load. I did not trace it further.
What I did: ran the gates again (below) and left the test as it is.
What the design should change: nothing in the design; the test should wait for an announced
event, or assert what the design says (a row to an ended delegate settles `ended`) rather than
a state a cue may already have passed. A unit of its own.
