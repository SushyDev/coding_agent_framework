# F-127: R7 part 2, the `waiter` transport

The second part of R7 (`docs/design.md`, "Delivery", "Delivery into a main session", "A session
with no waiter", "Ending a session"), against `model/tla/Delivery.tla`, with F-125's new-2 to
new-5 and F-123's new-2 decided by the brief, and the main session's measurement of the waiter
on Claude Code 2.1.322 (an addendum to the brief) folded into the design and the model.

## What was built

- **`Mailbox.Transport.Waiter`**, beside `Stream` and `Call`: the text handed to the waiter
  carries the row's uuid on a last line of its own (`[delivery <uuid>]`, F-125's new-4), and
  `seen/2` reads the session's transcript for that row's lines only: a `queue-operation`
  `enqueue` is `:queued`; a `dequeue` or `remove`, a user line or a `queued_command`
  attachment carrying the mark is `:taken`. `settle/2`: taken is delivered; marked and never
  handed on (`sent_at` nil) is due again; its process gone with no take is due again;
  enqueued waits for the take; no line is due again only once the take bound has passed.
- **`Mailbox`**: a `Sessions` row of any role but `delegate` is a waiter target when `Mailbox`
  has `intake:` (with `transcripts:` and `accounts:`). One row in flight; only while the row
  is `running` and `Intake.waiter?/4` holds; a session with no waiter keeps its rows `queued`
  with `attempt` `:no_waiter`. The mark keeps the process (`at`, the row's pid) and the
  transcript's offset read before it (`from_byte`); `{:ok, :sent}` and an unknown answer keep
  the row `sending` and record `sent_at` (wall-clock ms), a refusal undoes the mark. The take
  bound is `take_bound:`, 10 s by default, and its one timer per row settles the row at the
  bound; a restart sets the timers again from `sent_at`. The table gains `sent_at` and
  `from_byte`. `open_to/3` takes `status: :sending`.
- **`Intake`** cues a session's waiter coming (the first held for a session) and going (its
  hold ended, whether another took its place or none did) on
  `intake:<host>:<account>:waiters` with `ids: [session_id]` (F-123's new-3). A second waiter
  behind the first sends no cue.
- **`Sessions`**: `waiter: %{port, secret}` puts `Intake.waiter_hook/5` (with the host's sh and
  curl) into an interactive session's launch overlay at every start and resume; the row keeps
  only the agent's own options. `open_to: fn name, :open | :sending -> {:ok, ids} end` is read
  in the stop: an interactive session's SIGTERM waits, after its idle read, until no row to it
  is `sending`, until the stop's deadline, then is refused `{:sending, ids}`; a delegate's
  `end_session` is refused `{:open, ids}` while any row to it is open. `stop/4` is `stop/3`:
  the word is gone, and `Delegates` checks the report delivered before it asks (F-125's new-2).
- **`Accounts.overlay/4`**: an overlay's `hooks` add to the account's per event, the account's
  first (F-123's new-2), with a test.
- **`WaiterStandIn`** in `caf_test`: Claude Code's side of the waiter. At a turn's end it runs
  the Stop hooks with `asyncRewake` from the session's settings file, with the Stop input on
  stdin, and on exit 2 writes the transcript lines in the shape the test names: `:idle`
  (enqueue, dequeue, user line), `:busy` (enqueue, remove, `queued_command` attachment),
  `:enqueued`, or `:lost`.
- **Wiring.** `caf_mailbox` uses `caf_intake`, `caf_transcripts` and `caf_accounts`;
  `caf_sessions` uses `caf_intake`. The example app hands `Mailbox` its `Intake`,
  `Transcripts` and `Accounts`, hands `Sessions` `open_to:` and `waiter:`, and routes
  `intake:…:waiters` cues to `Mailbox`. README's "The apps" chart, the status and the
  "Nothing typed" point follow.
- **The model and the design.** `Delivery.tla`: a waiter's row is marked into an ended turn or
  a running one (Claude Code queues it), `Take` takes a waiter's answer into a running turn,
  and `SettleSeen` settles a waiter's row delivered at its take, not at the turn's end; a typed
  write keeps both rules. `OnlyIntoEndedTurn` says so, and `Break_Delivery_IntoRunningTurn`
  still fails, through the typed write. The design's "Delivery" (the exception to "into an
  ended turn", the waiter's row of the table, the take bound's value), "Delivery into a main
  session" (the wiring, the overlay's hooks, the mark, both transcript shapes), "A session with
  no waiter", "Ending a session", "Headless delegates" (the ending's check, and F-125's new-3:
  the fold's record per uuid stays as the claim's evidence and guard) and R7.

## What I ran into

- The brief's settle ("once the turn ended") and the addendum's (the take) differ. I built the
  addendum's: delivered at the `dequeue` or `remove`. In practice the row settles at the next
  waiter's cue, which comes at the end of the turn the text started (idle) or joined (busy), so
  one row is in flight per turn either way.
- `Sessions` needs both "open" and "sending": a delegate's stop refuses any open row, while an
  interactive session's idle read waits only for a `sending` one (a `queued` row is never
  marked once the row is `stopping`, so waiting for it would wait to the deadline). So
  `open_to:` is `fn name, which -> … end` and `Mailbox.open_to/3` takes `status: :sending`,
  where the brief wrote `fn name -> [ids] end`.
- The transcript's path needs the account's config directory, which `Mailbox` did not have:
  it takes `accounts:` and reads `Accounts.config_dir/2`, as `Delegates` does.
- A waiter row's settle reads the session's transcript through `Transcripts.read/3` and
  `text/5` from the offset kept at the mark, at every settle while the row is `sending`.

## Findings

### new-1. The waiter's settle reads the transcript on every cue while a row is sending

What happened: each settle of a `waiter` row runs `Transcripts.read/3` for its session and then
`Transcripts.text/5` from the row's offset, two shell runs. `Mailbox` settles on every cue it
gets (`stream`, `sessions`, `delegates`, the waiters'), so a busy host reads a main session's
transcript many times while one row waits for its take.
Why: `Mailbox` has no transcript cue of its own and no cache of what it read.
What I did: nothing more; the read is from the offset, so it is short.
What the design should change: route `transcripts:` cues to `Mailbox` and read a waiter row's
lines only on those, the waiters' cue and the bound; or keep the last offset read per row.

### new-2. A waiter's turn check is the waiter alone

What happened: the design says the turn state is `Sessions`' function for the target's kind.
For the waiter, `Mailbox` reads only whether `Intake` holds a waiter, since Claude Code queues
the text into a running turn anyway (the addendum), and `Sessions` has no turn function for
an interactive session yet (R9).
What I did: the mark needs the row `running` and a waiter held; no turn read.
What the design should change: nothing for the waiter. R8's typed write needs the turn read,
and R9's function should give it.

### new-3. `Sessions` now uses `caf_intake` for the waiter's fragment

What happened: putting the hook into the overlay at the start needs `Intake.waiter_hook/5`, so
`caf_sessions` uses `caf_intake` (a reader below it, which uses no other app).
What I did: declared it; README's chart shows it.
What the design should change: nothing, unless `Mains` is to own the main session's launch;
then the fragment moves there.
