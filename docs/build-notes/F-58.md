# F-58: `Sessions` checks, adds and sets up a start's worktree, and removes it after a restart

## What was built

The second half of F-55's code, split as F-55 new-11 proposes. F-55's builder wrote it; the
reviewer split it off unchanged. It builds on F-57's `Sessions.Worktree`.

- A launch with `worktree: %{project: project, branch: branch}` runs at
  `<home>/worktrees/<project>/<name>`. A start whose path another row that has not ended holds is
  refused before its row is written (`Table.holding/4`). The table gains `repo`, `branch` and
  `worktree`.
- After the row, a task linked to `Sessions` reads `git worktree list` and `git status`, adds
  the tree when the path is free, reads the list again (the list, not the add's exit status,
  says what the add did), and runs the project's setup. Each command runs through `Shell` with
  the host's reaper (`reaper:`), so `Sessions`' death ends them. The row's deadline and the
  call's timeout cover the setup's (F-55 new-8, new-9).
- A resume takes its name's tree as it is and runs the setup (F-55 new-5).
- After a restart, a starting row refused as interrupted has its tree removed when it is on the
  branch, clean and held by no other row. The row's `worktree` says what was done.

Tests on real git repositories under the test VM's own directory
(`apps/caf_sessions/test/sessions_worktree_test.exs`).
