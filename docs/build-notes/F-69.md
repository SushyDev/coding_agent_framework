# F-69: `Team.tla` follows the tree

A model unit: `model/tla/Team.tla`, its configurations and its part of `model/tla/READING.md`.
No code.

## What was built

`Team.tla` was written for one project in which any agent acted on any other, with a second
project's agents only calling in to be refused. It now models the tree of "Agents working
together" (F-68).

- **Two projects.** `Projects` is a set of sets, each a project's agents (`{{p, d1}, {q, e1}}`),
  and `Mains` names the main session of each; every other agent is a delegate. `Main(a)` is the
  main session of `a`'s project. The second project's agents have their own states, turns and
  faults, where `Foreign` had none. A delegate has no children here: its children are
  subagents, which the framework does not reach.
- **Edges.** `Edge(c, t)`: a main session to its delegates and to the other main session, a
  delegate to its main session. `Send` stores a row only along an edge. A message to an ended
  delegate goes to that delegate's main session.
- **Fixes.** `MayFix(c, t)` is one relation: the caller is the target's main session. No agent
  fixes itself and none fixes a main session, because a main session has no parent and no agent
  is its own. The fix kinds are interrupt (stuck), resume (dead, renamed from "respawn" to match
  the tool) and stop (idle); answer stays in `Intake.tla`.
- **Two calls at once.** Only a main session fixes a given delegate, so the old way to show
  `TwoClaims` (two agents claim one state) no longer exists. One caller can still make the same
  call twice at once, from its main turn and a subagent. A claim row now carries `n`, 2 for the
  caller's second call on the same state, and only `Break = "TwoClaims"` lets that row in.
- **Services.** `ServiceFixed(c, s)` is a restart or a stop, by the owner or the owner's parent.
  `ServiceHanded(c, s, b)` is the owner `c` handing to its parent or one of its children. A kept
  service goes to its owner's parent when the owner ends. A service's own claim stays abstract,
  as before; the model checks who fixes it, not how it is claimed.
- **Properties.** New invariants `AlongEdges` (every delivered message's sender and addressee
  are an edge, and it reached the addressee or, once that delegate ended, its main session),
  `OnlyParentFixes`, `MainNeverFixed` (no claim on a main session, and none ever ends),
  `ServiceFixedByOwnerOrParent` and `HandedAlongEdge`. `NoSelfFix` now reads the claims table.
  `ParentNeverStopped` became `MainNeverFixed`; `SameProjectOnly` is gone. The liveness
  properties are as before, with the recipient of a redirected message being the delegate's
  main session.
- **Header.** It names `Grants` (the edges, the claims), `Mailbox`, `Services` (owner, keep,
  fixes, hand-ons) and `MCP` with today's tool names, and says why `SelfFix`, `SiblingFix` and
  `FixMain` widen one guard rather than remove three.

### The Breaks

Kept, each still failing on its own property: `IntoRunningTurn`, `RedeliverAfterRestart`,
`RedirectUnsettled`, `NoRedirect`, `NoOrder`, `ClaimInMemory`, `StaleFix`, `OwnerClearedFirst`,
`NoOwnerWatch`.

Rewritten: `SelfFix` (it widens `MayFix` by `c = t`) and `TwoClaims` (one main session's two
calls on one dead delegate, by `n`).

Removed, since their rules are gone:
- `CrossProject`: main sessions now message each other across projects, and a fix across
  projects is already outside "a parent's own child". `OffEdge` takes its place for messages.
- `StopParent`: the old rule refused only a stop of the parent. The tree refuses every fix of a
  main session. `FixMain` takes its place.

New:

| Break | What it does wrong | Fails |
| --- | --- | --- |
| `OffEdge` | a message is stored without the edge check (a delegate to its sibling, or to another project) | `AlongEdges` |
| `SiblingFix` | a delegate may fix another delegate of its main session | `OnlyParentFixes` |
| `FixMain` | fixes are granted along any edge, so a delegate or the other main session stops a main session | `MainNeverFixed` |
| `ServiceFixAnyone` | any agent may restart or stop a service | `ServiceFixedByOwnerOrParent` |
| `HandToSibling` | a delegate hands its service to its sibling | `HandedAlongEdge` |
| `HandByOther` | an agent other than the owner hands a service on | `HandedAlongEdge` |

## What I ran into

- `TwoClaims` could not fail under the tree. With only a parent fixing, one caller is the only
  claimant, and a claim row that is a set member cannot be taken twice by the same caller. The
  row's `n` makes the second call a distinct row, as two concurrent calls are in a table.
- The `Team` fast configurations went from about 15 s together to about 70 s in the gate run
  (about 150 s on the more loaded machine). Each is under the 30 s that `bin/check-model`'s
  header gives a fast configuration in the gate run, and under what `Start_TwoSessions` takes;
  `Team_Messages` reached 42 s at a load average of 67.

## Findings

### new-1. A message to an ended delegate goes back to its own sender

What happened: only a delegate's main session may message it, so the redirect in "Messages"
("a message to a delegate that has ended goes to its main session instead, once, and says so")
always hands the message back to the main session that sent it, as a new turn.

Why: the redirect was written when any agent of a project could message a delegate.

What I did: modeled it as the design says; `AlongEdges` allows it, since the row's sender and
addressee are an edge.

What the design should change: say that the redirect returns the message to its sender, or
replace it with an answer to the sender (`delivered` never comes; the row says the delegate
ended before the message went in), which saves the main session a turn spent on its own text.

### new-2. "No agent may stop, move or interrupt a main session" says less than the rule above it

What happened: "Who may act" lists stop, move and interrupt. The fix rule ("a parent's act on
its own child") already refuses all four fixes, answer and resume included, since a main session
has no parent.

What I did: modeled the one relation; `MainNeverFixed` checks that no claim on a main session
is taken.

What the design should change: "No agent fixes or moves a main session; only a person does."

### new-3. Whether `keep` goes with a service when it is handed

What happened: "Services" says a service started with `keep: true` goes to the owner's parent
when the owner ends. It does not say whether the flag stays when the service is handed, for
example a main session's kept service handed to a delegate that then ends.

What I did: kept the earlier model's reading, a flag on the service that a hand does not change.
No property depends on it: either reading hands only to the owner's parent or ends the service.

What the design should change: say that `keep` belongs to the service and stays with it across
hands, or that a hand clears it.

### new-4. What a service's claim names

What happened: `service_restart` and `service_stop` act "under a claim", and a claim is "in one
state", but the design gives a service no state number the way `Recoveries` numbers an agent's.

What I did: left the service's claim abstract, as the earlier model did, and checked only who
may fix.

What the design should change: name the state a service's claim holds, for example its held
process (pid and start time) and its restart count, when `Copy.tla` and `Services` are written.
