# F-160: `Programs.find/3` finds a program whose name is also a shell builtin

## What was built

- **`Programs.find/3` searches the `PATH` for a builtin's file.** `command -v` prints the bare
  name for a builtin (`kill`, and in some shells `sleep`), so `find` refused
  `{:not_found, [:kill]}`. When the answer is not an absolute path, the same shell run now loops
  over `$PATH` (`IFS=:`) for an executable regular file of that name. It costs no second round
  trip to a remote host. A name with no such file is still refused.
- **Tests** (`apps/caf_test/test/programs_builtin_test.exs`, run through the real `/bin/sh`):
  `kill` and `sleep` are found as files; with a `PATH` holding an empty directory, `kill` is
  refused. The module is not async because it sets the VM's `PATH`.

## What was measured

On macOS `/bin/sh -c 'command -v kill'` prints `kill`; the new loop finds `/bin/kill`.

## What I ran into

`Programs.names/0` holds only the programs the framework runs, so `echo`, `test` and `printf`
cannot go through `find/3` (`{:unknown_names, _}`). The tests use `kill` and `sleep`.
