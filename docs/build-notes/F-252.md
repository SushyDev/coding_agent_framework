# F-252: one form of a process's start time, so a Linux main's stop signals it

## What was built

On Linux (Claude Code 2.1.322, NixOS, 2026-11-24) every real main's end answered `{:unknown,
{:no_exit, {:ok, :gone}}}`, and four mains ran on after their tests, their leases held. A main
row took its `proc_start` from its session file, which on Linux is a start in clock ticks since
boot, while `Holder.Process.signal/4`'s shell compares a start with `ps -o lstart=`. That shell
found the start "gone" and sent nothing (F-246's new-6).

Now a start has one form inside the framework: the `ps -o lstart=` text in UTC and the C locale,
its runs of spaces made one (`Holder.Process.normal/1`).

1. `Holder.Process.from_ticks/3` turns each `{pid, ticks}` into that form in one shell on the
   host. For each pid it reads `<proc>/<pid>/stat`, then `ps -o lstart=`, then the stat file
   again. Both stat reads must hold the file's ticks for the answer to be `{:live, start}`.
   A stat read with other ticks is `:replaced`, a missing stat file or a `ps` that lists
   nothing is `:gone`, and a failed read is `:unknown`. `judge_ticks/2` is its pure judge, and
   `ticks?/1` names the form.
2. The `Registry` calls it for every session file whose `procStart` is all digits, as it reads
   the files (`judged/2`, for its reads and for `running/3`). A converted file's row holds the
   `ps` text and `alive: :live`. Any other file's row holds no start (`nil`) and its `alive`
   says why. A file in the `ps` form is checked by `liveness/3` as before, and its row's start
   is stored with its runs of spaces made one.
3. `Holder.Process.liveness/3` reads the `ps` form only again: F-246's `/proc` read in it,
   `by_stat/3` and `judge_stat/2`, is removed, and `Sessions` no longer takes `cat` for it. No
   part but the `Registry`'s read sees ticks.
4. The `Registry` takes `proc:`, the directory read for a start in ticks (default `"/proc"`), so
   a test on a host with no `/proc` names one of its own. It is per instance: no global state.
5. The screen stand-in takes `proc_start: {:stat, dir}`: it writes the ticks that
   `<dir>/<pid>/stat` holds as it writes its session file.

### Why convert at the read, not teach every check two forms

The checks of a start run in shells on the host: the holder's reading (`@read`), its push
(`@push`) and its signal (`@signal`), each a check and an act in one process, as `Start.tla`'s
`Signal` models it. Teaching each one a second form changes four shell protocols and the model's
`Signal`, and every later check must learn both forms again. Converting once, where a file is
read, changes no shell and no model: each check keeps comparing one string with `ps`. The cost is
one more shell per `Registry` read with ticks files, and on Linux it replaces the `ps` that
`liveness/3` would run, so the count of shells per read stays the same there. The two stat reads
around the `ps` keep a pid reused between the reads from lending its start to the file.

### Every place that stores or compares a start

Each one is now in the one form:

| Place | Where its start comes from | How it compares |
| --- | --- | --- |
| The holder's record (`Holder.Process`' `@wrapper`) | `ps -o lstart=` of the wrapper's own pid, written by `echo $$ $t`, so its runs of spaces are one | `@read`, `@push`, `@signal` compare `$(echo $t)` with it |
| A main row (`Sessions`' `running/3`, `confirm/3`, `orphan/3`) | the `Registry` row, now always the `ps` form or `nil` | by `liveness/3` and the holder's shells |
| A delegate row (`file_of/2`, `orphan_held/3`) | the holder's record | as above |
| `end_reading/2` (a main's stop and end) | the row's `proc_start` | `signal/4`'s shell: now finds the process and sends TERM |
| `limited_reading/4` (a move's stop of a limited turn) | the row's `proc_start` | the same shell |
| `liveness/3` | any caller's start | one `ps`, each side made `normal/1` |
| `Sessions.Turn.file/2` | a row's and a file's start | `normal/1` on both |
| The stuck-background groups (`StuckBackgrounds.Groups`) | a delegate's holder record, and each group leader's `ps -A -o pid=,lstart=`, made `normal/1` | its `/proc` read is CPU ticks only, never a start; the group's TERM goes through `signal/4` |
| `Runs` | its wrapper's own `ps -o lstart=`, sent as it prints it | only through `liveness/3`, which makes it `normal/1`; nothing signals by it (new-2) |
| `Mover`'s claim, `AbsentMains`' evidence, the tracker's fold | a row's `proc_start` | stored or shown, never compared in a shell |
| `Registry.running/3` (`bin/caf-import`) | the files, converted as a read converts them | `liveness/3` or `from_ticks/3` |

## Findings

### new-1. A session file's start in the `ps` form may hold a padded day

What happened: `ps -o lstart=` pads a day of one digit ("Nov  7"). The holder's record and the
shells' `$(echo $t)` make that one space, but a main row took the file's text as written. If
Claude Code writes the padded text, a main's stop on days 1 to 9 of a month would have read
`gone` on macOS too. Why: only `liveness/3` and `Turn.file/2` made a start `normal/1`. What I
did: the `Registry` stores a `ps`-form start made `normal/1`, as item 2 asks. Whether 2.1.322
pads it was not measured. What the design should change: add a macOS session file written on a
day of one digit to the fixtures.

### new-2. `Runs` keeps its wrapper's start as `ps` prints it

What happened: `Runs`' wrapper sends `ps -o lstart=` unchanged, padding kept. Why: it is only
compared through `liveness/3`, which makes both sides `normal/1`. What I did: nothing; no shell
compares it. What the design should change: if `Runs` ever signals by it, the wrapper should
send `$(echo $start)`, as the holder's record does.

### new-3. Two parsers of a stat line

What happened: `StuckBackgrounds.Groups` and `Holder.Process` each split a `/proc/<pid>/stat`
line after its last `)`. Why: they were written apart (F-184, F-246). What I did: nothing.
What the design should change: one pure parser in `Holder.Process`, used by both.
