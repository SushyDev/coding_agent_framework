# F-39: why `sessions_test.exs` "new-2" failed now and then

## The failure

In about one full `gate-test` in three on a busy laptop, the test "new-2: past the deadline,
Adopt makes a live socket an orphan, a dead one refused" found the row for `orphan` as
`status: "refused"`, `reason: "interrupted"`, `pid: nil`, and
`viewer: "{:unknown, {:resize, \"%0\", {:refused, :no_server}}}"`. It passed alone.

## The cause

The test rewrote the stand-in script while the `orphan` start could be running it.

`launch(ctx, :never)` writes `<test dir>/claude-never` and the test starts `orphan` with it in a
task. The next line, `own_dir(ctx, "dead", :never)`, calls `launch(ctx, :never)` again, so it
writes the same path again while the `orphan` start runs. `File.write!/2` truncates the file and
then writes it, so for a moment the script is empty. A start that executes the path in that
moment runs an empty file. `sh`'s `exec` of an empty executable runs it as a script and exits 0
at once. Then:

1. `dtach -n` exits 0 once it has started `sh`, which is before `sh` reads the stand-in. So
   `Holder.hold/4` answered `{:ok, socket}` (the logs show `dtach -n` answering before the
   stand-in's first line in 11 of 12 runs).
2. The held program exits at once, and dtach removes the socket.
3. The viewer's `dtach -a` finds no socket and exits. Its tmux session ends, and with it the
   test's tmux server, since it held no other session. The resize that follows the open answers
   `{:refused, :no_server}`.
4. After the restart, `Adopt` reads the socket as absent and writes `refused{interrupted}`.

Every field of the failing row follows. Nothing else in the suite shared a file, a socket or a
tmux server with this test.

## The evidence

Temporary logging, since removed, wrote to a file outside the repository: each
`ClaudeStandIn.write!/2` (path, start and end), the size of the stand-in script before and after
`Holder.hold/4`, what `hold` answered, `Holder.state/2` right after it, what the viewer answered,
and a line from the stand-in's first command.

**Twelve full `gate-test` runs with the logging** all passed; the logging itself changed the
timing. Each run's log still shows the race, measured from the start of `orphan`'s hold:

**With the empty moment widened on purpose** (the test aid truncated the file, waited 400 ms,
then wrote it), the test failed alone, with the reported row field for field: `refused`,
`interrupted`, `pid: nil`, and the viewer's `{:resize, "%0", {:refused, :no_server}}`. The log
of that run: `hold orphan answered {:ok, ".../orphan.sock"} size=0 state={:ok, :absent}`, and no
line from the `orphan` stand-in.

**An empty stand-in** run as `Sessions` runs it (`sh -c 'cd -- "$0" && exec "$@"' dir
claude-never`) exits 0 at once.

The two earlier failures with tmux's "fork failed: Device not configured" (a pty refused) did
not come back in 22 full runs. See new-2.

## The fix

- **`ClaudeStandIn.write!/2`** writes the script whole under a name of its own, makes it
  executable, and renames it into place, as the stand-in already does for its session file. A
  start that runs the path sees the old file or the new one, never an empty one. With the same
  400 ms wait put between the write and the rename, the test passed three times of three, and
  the `orphan` stand-in started each time.
- **The test** writes the `dead` stand-in, and with it `claude-never`, before it starts
  `orphan`, so nothing is written while a start runs.

No code outside the tests changed. No retry, timeout or wait was added.

The ten runs after the fix took 8 to 17 s each, against 26 to 36 s for the twelve before it: the
laptop was less busy then. They show the suite passes with the fix. They do not show the old
failure rate under the same load; the widened-window test above shows the fix itself.

## Findings

### new-1. A test aid rewrote a file a running process could read

What happened: `ClaudeStandIn.write!/2` wrote its script in place, and one test wrote it again
while a start that runs it was under way. Under load, that start ran an empty script.

Why: writing a file in place truncates it first. The aid wrote the session file whole and
renamed it, but not its own script.

What I did: the aid writes the script whole and renames it; the test writes every stand-in
before its first start. `HeadlessStandIn` writes its script once per test, before any start, so
it is left as it is.

What the design should change: add to "Tests": a file that a started process may read (a
script, a config, a fixture) is written whole and renamed, never rewritten in place.

### new-2. The row does not say what the hold answered

What happened: the failing row could not tell a held program that exited at once from a hold
that failed. A `dtach -n` that cannot get a pty exits 1 with `init_pty: Device not configured`.
`Holder.hold/4` then answers `{:unknown, {:dtach, 1, out, path}}`, `Sessions` opens the viewer
as for any unknown hold, and the row ends the same way: the viewer's `no_server`, then
`refused{interrupted}`. Only the temporary logging told the two apart.

Why: `Sessions` keeps a hold's unknown answer only in the call's flow, not in the row.

What the design should change: keep an unknown hold's reason in the row (for example in
`reason` while the row is `starting`), so a row says why its process may not have started.

### new-3. `erl_child_setup: failed with error 32` printed again

What happened: F-25's new-5 saw it once in three runs. Here it was printed in 7 of the 12 runs
before the fix, in 4 of the 10 after it, and once in `devenv test`. Every one of those runs
passed and exited 0. It is not tied to this test or to the fix.

What the design should change: nothing yet. It is common enough now to find which test prints
it, as its own unit.
