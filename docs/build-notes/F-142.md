# F-142: follow-ups from F-133, F-137 and F-138

The brief names eight follow-ups. A first pass built items 1 and 2 and the move's half of item
3, and stopped on two findings the design did not settle. The main session decided both: a long
row is typed as a pointer to a file, and the drain denies new background commands. This unit
builds those decisions and all eight items. In all it adds about 1,200 lines and removes about
270, tests and docs included.

## What was built

1. **The drain waits for background commands** (F-133's new-1). Measured by the main session
   on 2.1.322: the session file says `shell` while a background command runs after the turn
   ended, and `idle` once it ends. `Sessions.stop/3` already sends the SIGTERM only on `idle`,
   so `shell` refuses the stop (`{:not_idle, "shell"}`), and the `Mover` asks again on the next
   `registry:` cue. `Sessions.Turn.file_state/1` reads `shell` as `:running`, where it read
   `:unread` before. In `Move.tla`, `IdleRead` needs `bg = {}`, and `Cleared` no longer reads
   `bg`. The new `Break_Move_ShellIsIdle` fails `NothingLost`. Since `Cleared` no longer
   guaranteed `bg = {}`, TLC found a crash during `stopping` ending a background command; a
   crash is not the move's loss, so `lost` now counts only the SIGTERM's.
2. **The copy takes `session-env/<session id>`** (F-133's new-4), beside the transcript and its
   directory, as a directory or a file. A session with none has nothing to copy.
3. **A resume carries the first due row by `launch`** (F-137's new-1). `Mover`'s resume of an
   interactive session first calls `Mailbox.launch/4`, passes the text as `prompt:`, and tells
   `Mailbox.launched/3` the answer. While a row is still `sending` it waits for the next cue.
   - **The pointer** (new-1 below, decided). A row too long to type is written to
     `<home>/due/<agent>/<id>.md`, and the `Inlet` types one line that names the file, with the
     uuid at its end. A row is too long when it has more than one line, a control character, or
     more than 76 characters with its mark. `Sessions` passes that directory by `--add-dir` at
     every interactive start, so reading the file never asks permission. The file goes once
     its row is delivered. `Mailbox` takes `home:`.
   - **`Delivery.tla`**: the typed write drops its `Long` guard, `Held` is gone, and `Arrives`
     has no escape. The Break `TypeLong` (and `NoLongTyped`) became `NoPointer`: a long row is
     not typed, and `Break_Delivery_NoPointer` fails `Arrives`. `Delivery_Interactive` now has
     one long row.
   - **The instancing specs** take `turned` and `Long` from their own state:
     - `Move.tla`: a `turned` variable (false at the resume, true at a turn's end), `Long` every
       row, and `stopping` only while the old process runs. `LaunchMarked` and
       `ResumedWith(i)` are the launch, and `ResumedBare` resumes with no prompt only when no
       row is due or in flight.
     - `Team.tla`: a `turned` per agent (false at a resume, true at a turn's end or an
       interrupt) and `Long` every row. `Break_Team_NoPointer` fails `MessageDelivered`.
     - `Delegate.tla`: `parentTurned` (false when the parent's process runs again) and `Long`
       every report. `Break_Delegate_NoPointer` fails `ReportArrives`.

     The first pass's `Break_Move_NoResumeLaunch` and `Waits` are gone, and so is
     `Break_Delivery_NoLaunch` (see "Gates"): with the pointer, a row
     a bare resume leaves arrives anyway, so the launch is the quicker path, not the only one.
4. **An interactive delegate's fixes** (F-137's new-3).
   - `Inlet.interrupt/3` checks that the screen shows a turn running, sends Escape as its own
     command, and reads the screen until the turn has ended.
   - A permission answer goes to the `PermissionRequest` `Intake` holds for the delegate's
     session (`Intake.answer/4`).
   - The state a fix claims comes from `Intake`'s rows of that session: the newest event's id,
     the held requests' ids, and whether its process runs.
   - `Delegates` takes `inlet:`, `intake:` and `intake_db:`, and now depends on `caf_inlet` and
     `caf_intake` at run time.
5. **`Delegates` keeps the marked line's offset** (F-137's new-4), in memory, per session and
   uuid, and reads from it (`Transcripts.Fold.marked_at/2`). A mark no longer at its offset is
   looked for again from byte 0.
6. **Rows to the operator are `kept`** (F-138's new-1) from their store, out of `open_rows`.
   Rows an earlier build stored `queued` are kept at `Mailbox`'s start. `Mailbox.reply/2`
   answers the reply to a message by the message's id.
7. **A text of several lines** (F-138's new-2). The decision on new-1 changed this item:
   "Delivery" now says such a text goes by the waiter or as the typed pointer, so it does not
   wait for a waiter.
8. **An answer's labels are kept as JSON** (F-138's new-3): a new `answer` column, shown by
   `asked/3` as `answers`.
- **The drain denies background commands** (new-2 below, decided). `Mover.pre_tool_use/2` is
  the framework's `PreToolUse` callback. While the agent row has a move phase, it denies a `Bash`
  call with `run_in_background` and the `Monitor` tool, with a reason. It hands every other call
  to the app's callback. The example app always gives it, so every account's settings name the
  `PreToolUse` hook.
- `design.md`: "Moving it", "Interactive delegates", "A session with no waiter", the session
  file's statuses and the per-release check, "Delivery", "The operator" and "An ask".
  `READING.md`: `Delivery.tla`'s `typed` and `turned`, and `Move.tla`'s steps.

## Findings

### new-1. A row stored after a resume that carried none, or after a restart cut the waiter, waited for a person's prompt

What happened: a launch at the resume reaches only a row due at that moment. A row stored after a
resume that carried none, or after a restart or the waiter's deadline cut the waiter, waited for
a person's prompt.
What I did: stopped and reported, with the pointer as the recommendation.
Decided by the main session: the pointer through the typed write, built here (item 3).

### new-2. Nothing stopped a background command from starting during the drain

What happened: "Moving it" step 1 says the drain starts no new background commands, but nothing
in the code stopped Claude Code from starting one.
Decided by the main session: the drain stops what the framework starts, and the framework's
`PreToolUse` callback denies a background `Bash` and `Monitor` while a move runs, built here.

### new-3. The pointer's file is read by the agent, so the row is delivered when the line is taken

What happened: the transcript's user line settles a typed pointer, as any typed row. That line
shows the agent was given the path, not that it read the file.
Why: nothing in the transcript ties a read of the file to the row.
What I did: nothing more. The main session then kept the file after delivery: removing it at the taken line could beat the agent's read of it in that turn, and the framework keeps its data.
What the design should change: if a read must be confirmed, read the transcript for the agent's
`Read` of that path in the turn the line began, and keep the file until then.

### new-4. The framework's PreToolUse hook now runs on every tool call of every account

What happened: the drain's deny is a `PreToolUse` callback, so the example app writes the hook
into every account's settings. Every tool call now posts to `Intake` and waits for the callback
(at most 5 s; the decision is a table read).
What I did: the callback reads one agent row and answers at once; any other call passes to the
app's callback, or `:pass`.
What the design should change: if the cost shows, a `matcher` of `Bash|Monitor` on the hook,
when the app gives no callback of its own.
