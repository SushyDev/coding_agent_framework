# F-271: bin/caf-import --replace takes over a stopped main started before the import

Built by the main session. Not landed: the host move it was for was fixed by hand instead.

## What happened

On a new host the app started before the import, so its config's main sessions started fresh
under their names. `caf-import` then copied the old conversations, and at the next start
`Sessions.import_main/4` refused both names `{:exists, "stopped"}`: a name is taken only with no
row, or by a main declared and never started. The app's start-or-resume then resumed the blank
conversations.

## What was built

- `--replace <name>`, for a name the run gives with `--name`, stamps the manifest with
  `replace_at`. A rerun for a conversation imported already stamps it again.
- `Sessions.import_main/4` replaces a `main` row that holds no process and was started before
  `replace_at`, with the manifest's session, account and project, and clears the last run's
  process, dialog, prompt, stop and move fields. A row started after it stays refused, so a
  later start under the name is never undone.
- A test in `mains_test.exs`.

## Findings

### new-1. An import cannot take a name a started main holds, and nothing says so until the next start

What happened: the refusal is an act written at the app's next start, and shows only in its log.
Why: the import checks only that no row of the account runs, not that each name is free.
What the design should change: `caf-import` should refuse at once, naming each name a main row
holds and its session, and say how to take it over (`--replace`, or forget the row).
