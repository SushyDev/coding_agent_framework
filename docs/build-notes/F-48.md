# F-48: the screen capture script a person runs

## What was built

`bin/capture-screen`, the script that captures `Screen`'s fixtures from a real interactive
Claude Code session, and a test of its dry run. `Screen` itself is not built, and the real
Claude Code was not run.

- **Programs.** It checks the `CAF_*` variables it needs, re-runs itself under `$CAF_BASH` when
  another bash started it, and sets `PATH` to `$CAF_TOOLS_PATH` (coreutils, grep, sed) as
  `bin/check-model` does. tmux, git, env, sleep and claude are called by their `CAF_*` paths.
- **Its own tmux server.** It makes a temporary directory (`$TMPDIR/cs.XXXXXX`, short for the
  socket's 104 bytes, and refused when longer than 100), starts tmux there with `-f /dev/null`
  and `-S <dir>/tmux`, and on any exit, Ctrl-C included, runs `kill-server` on that socket and
  removes the directory. `TMUX` is unset. It names no other server.
- **One pane, 120x40.** The status line is off and `window-size` is `manual`, so a person's
  terminal attached at another size does not resize the pane. `remain-on-exit` keeps the last
  screen after `/exit`, and `remain-on-exit-format ''` keeps tmux's "Pane is dead" line out of
  it. Each capture checks the pane is still 120x40.
- **The launch.** `env -i` with what `ClaudeCLI` keeps (`HOME`, `PATH`, `TERM=xterm-256color`,
  `LANG=C.UTF-8`, `CLAUDE_CONFIG_DIR`) and `DISABLE_AUTOUPDATER=1` (new-2), in a new git
  repository inside the temporary directory, so the trust dialog shows. The config directory is
  the one argument: an existing absolute directory, and never `~/.claude`.
- **The states**, one at a time: `trust-dialog`, `idle-empty`, `text-typed`, `turn-running`,
  `turn-ended`, `permission-dialog`, `turn-ended-after-tool`, `exited`. The script prints the
  command that attaches a second terminal (`$CAF_TMUX -S <socket> attach -t capture`). It types
  into the box itself, with `send-keys -l`, and a line's text and its Enter go in one tmux
  command. The person answers the two dialogs in the attached pane, since each is a decision.
  The person presses Enter in the script's terminal once the pane shows each state, or types
  `q` to stop. Each state is captured with `capture-pane -p` (`<state>.txt`) and `-p -e`
  (`<state>.ansi`). `exited` waits until the pane is dead, and every other state stops the run
  if Claude Code already exited.
- **The scrub.** The scratch repository's path (as given and as macOS resolves it,
  `/private/var/…`), the home directory (both forms), each `--name`, the user name (`id -un`)
  and the host name (`uname -n` and its first label) become `/work/repo`, `/home/user`,
  `Person`, `user` and `host`, in that order, by exact match. Every changed line is printed
  before and after, with escapes shown as `\e`. Then two checks, on each line with those names
  marked out:
  - a name still there in any case is refused. An account's display name in another case is the
    likely one, and the message says to pass it as `--name`;
  - a name found more often in the file's lines joined than in its lines one by one is cut
    where the screen wraps, so the scrub could not reach it. It is refused.

  On a refusal nothing is written. Otherwise the files and `manifest.json` go to
  `apps/caf_screen/test/fixtures/<version>/`, or `--out <dir>/<version>/`. The version is the
  first word of `claude --version`. An existing version directory is refused, never replaced.
- **The manifest** names the Claude Code version, the tmux version, whether it was a dry run, the
  pane size, and for each file its state, whether it has escapes, a description of the state,
  the pane size and the capture time in UTC.
- **`--dry-run`** writes a stand-in into the temporary directory: a bash script that draws a
  fixed box and moves from state to state on each key, as Claude Code would. Its screen shows
  the working directory, `$HOME`, `$CLAUDE_CONFIG_DIR`, the user name and the host name, so
  the scrub has something to scrub. Its last line names its state, and the dry run waits for
  that line on the pane, for up to 10 s, instead of waiting for the person. The two dialog
  answers, which a person gives in a real run, are keys the dry run sends itself. Its version
  is `dry-run`.
- **`CaptureScreenTest`** in `caf_test` runs the dry run on a real tmux server, with its own
  `HOME`, `TMPDIR` and output directory under the test's directory. Four cases:
  - a run writes the 16 files and the manifest, with the right states, sizes and times. The
    `.txt` files have no escapes and the `.ansi` files do. Every path, the user name, the host
    name and a `--name` are replaced. The output prints the changed lines. The temporary
    directory is gone afterwards;
  - a `--name` the screen shows in capitals is refused, and nothing is written;
  - a home path long enough to wrap is refused as cut across two lines;
  - `~/.claude` as the config directory is refused before anything starts.
- `README.md` ("Development") says how to run it, in a few lines.

## The command the person runs

From the umbrella root, with the account logged in once in its own directory:

```sh
devenv shell -- bin/capture-screen <home>/accounts/<account>/claude
```

Add `--name '<display name>'` and `--name <email>` for what the welcome screen shows of the
account; a refused run names what it found. Then, in a second terminal at least 120x40, run the
attach command the script prints. Read every file in
`apps/caf_screen/test/fixtures/<version>/` before committing it.

## What was measured

- One dry run takes about 4 s (3 runs: 4.15, 3.93, 4.05 s): about 2 s to step through the
  states and 2 s to scrub 16 files.
- The first scrub ran each line through a subshell and took 6 s. It now assigns variables in
  place.
- `CaptureScreenTest`'s four cases take 12.3 s together, run async.
- A dry run's 16 files and manifest come to 13.6 kB.

## What I ran into

- The first manual dry run used the scratchpad directory as `TMPDIR`, and tmux failed with "File
  name too long". The script now refuses such a path itself, before it starts tmux.
- A home path long enough to wrap was neither scrubbed nor refused at first. The scrub works
  line by line, and the user name inside the cut path was replaced, which hid it from a check
  of the joined text. Counting each name in the joined lines against the lines one by one
  catches it.
- `shopt -s nocasematch` also makes bash's `${var//pattern/…}` match in any case. So it is on
  only around the refusal check, and the scrub stays exact.
- Design "Rules learned" says to unset `window-size` after `resize-window`, for viewers. Here the
  size must stay fixed while a person's terminal is attached, so the capture sets it to
  `manual` on purpose.

## Findings

### new-1. The capture does not launch Claude Code as a parent is launched

What happened: a parent runs with `--model`, `--name`, `--settings`, `--mcp-config`,
`--strict-mcp-config` and `--remote-control` (`ClaudeCLI`), held by dtach and viewed in a tmux
pane. The capture runs plain `claude` in the pane, with the same environment and none of those
flags.

Why: the account's settings and MCP files come from `Accounts.prepare/3`, which is Elixir, and a
person's capture script should not start Remote Control on their account. Remote Control's
notice, the status line and the session name can each change what the screen shows.

What I did: built the plain launch, and noted the gap in the script's launch comment.

What the design should change: say whether `Screen`'s fixtures must come from a parent's own
launch. If so, the capture should take `ClaudeCLI`'s argv, with Remote Control the one
exception, once a command exists that prints it for an account.

### new-2. A parent's environment leaves Claude Code's auto-updater on

What happened: `ClaudeCLI` keeps `HOME`, `PATH`, `TERM`, `LANG` and `CLAUDE_CONFIG_DIR`, and so
the auto-updater runs. `check-versions` already sets `DISABLE_AUTOUPDATER=1`. The capture sets
it too, so the run writes nothing outside the account's directory and no update notice lands in
a fixture.

Why: devenv pins Claude Code. An update that a session installs for itself is a version the
lock does not name, and each pinned release is checked against the design.

What the design should change: add `DISABLE_AUTOUPDATER=1` to what a launch keeps
("Rules learned", **Claude Code**), and then to `ClaudeCLI`'s environment.

### new-3. A capture leaves its session in the account's directory

What happened: trusting the scratch folder records it in the account's `.claude.json`, and the
session's transcript stays under the account's `projects/`. The scratch folder itself is gone.

Why: the design forbids editing a file Claude Code rewrites, and the script deletes nothing in a
config directory.

What I did: said so in the script's header.

What the design should change: say whether a capture runs on a working account or on one kept
for captures, so that its leftover session never shows in the account's lists.
