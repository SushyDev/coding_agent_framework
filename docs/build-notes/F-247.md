# F-247: a test's helper module is defined before the test

## What was built

Five test files defined a helper process (an `Intake` stand-in) after the test module that
starts it: `delegates_interactive_test.exs`, `mailbox_launch_test.exs`,
`mailbox_reload_test.exs`, `mailbox_waiter_test.exs` and `mains_test.exs`. Each helper now
comes first in its file, as `inlet_test.exs`'s `Probe` already did. Nothing else changed.

## What was measured

In a `gate-test` run at a load of about 90 on 15 cores (2026-11-24), `MailboxLaunchTest`
failed once with `ArgumentError: The module …MailboxLaunchTest.NoWaiter was given as a child
to a supervisor but it does not implement child_spec/1`. The same file passed three times
alone. ExUnit starts a test module as soon as that module is compiled, while the rest of its file
is still being compiled. Under load, a test can start before a helper defined below it exists.

## Findings

None.
