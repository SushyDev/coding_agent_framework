# F-66: a test VM leaves no process behind

## What was built

- **A bound on each stand-in.** `ClaudeStandIn` and `HeadlessStandIn` read with `read -t`, so
  each ends by itself after `TestHost.stand_in_idle/0` seconds (90) with no input. `write!` takes
  the bound as its last argument, so a test can check it with 1 s. The four held stand-ins that
  ended in `exec cat` (`HolderTest` twice, `RecoveriesSetup`, `TmuxSamplerTest`) and the one in
  `ClaudeCLIHeldTest` now end in `TestHost.echo_tail!/1`. It records the pid in `<dir>/pids/`
  and echoes lines under the same bound. Its command line names the test's directory, which
  `cat`'s did not. `StreamTest`'s deaf process sleeps the same bound, not 600 s.
- **Ending what a test recorded.** `TestHost.end_recorded/2` finds every `pids` directory under a
  directory, at any depth, and renames it. It ends each recorded pid whose command line still
  names that directory: CONT, then TERM, then KILL for any still alive after a 5 s wait. Each
  stand-in records its pid with `: > pids/$$ || exit 0`. So a stand-in that starts after the
  rename cannot record, and exits at once. A pid whose command line does not name the directory
  is never signaled: another program may have reused it.
- **Where it runs.** `SessionsSetup`, `StreamTest`'s setup and `SessionsHeadlessTest`'s `own_dir`
  call it in `on_exit`, where `kill_all/1` was. The held-stand-in helpers register it before the
  hold, so a test that fails mid-start is covered too. `kill_all/1` stays for a test that ends a
  stand-in while it runs. Each `test_helper.exs` calls `TestHost.end_vm/0` when the suite ends.
  It calls `end_recorded/2` on the VM's directory, prints any pid it had to end, then removes the
  directory.
- **The check.** `gate-test` (`devenv.nix`) runs `mix` in a subshell that records its own pid and
  then execs `mix`. That pid is the VM's `System.pid()` (checked: a background `mix run` printed
  the same pid the shell's `$!` gave). After the run, the gate lists processes with `ps` and
  fails if any command line names `/caf-<that pid>/`. It names each one and ends none. It reads
  the list again for up to 5 s first, because a dtach master exits a moment after its child. A
  `ps` that fails fails the gate.
- Tests in `StandInTest`: an idle stand-in of each kind ends by itself, with its input held open;
  `end_recorded/2` ends a stopped stand-in, and a start that runs after it exits at once; a
  recorded pid whose command line does not name the directory is left alone. A doctest covers
  `end_recorded/2` on an empty directory.

## What was measured

- **Before.** On `main`, every full `mix test --exclude model` left 6 processes naming its VM's
  directory: the `:never` stand-ins of `SessionsTest`'s "taken", "blind" and "gamma", each with
  its dtach master. A second VM on the machine (32752, another checkout's run) had left the same
  six.
- **Why.** In a probe I did not commit, `SessionsSetup`'s `on_exit` found `pids/` empty for
  "gamma": the start answered `unknown` (the test moves its clock past the deadline) before the
  stand-in had recorded its pid (new-1). A TERM by pid ends such a stand-in, and its master exits
  within a second.
- **The bound.** ExUnit's default timeout is 60 s, and no test raises it, so no test can use a
  stand-in longer than that. With `--slowest 25` per app, the longest test that uses a stand-in
  took 1.2 s ("a start is confirmed by its first event and the pid its wrapper records"), and the
  longest test of all took 2.1 s. I chose 90 s: above the timeout with room to spare, and short
  enough that a stand-in from a killed VM is gone within a minute and a half.
- **`devenv shell -- gate-test`, three passes,** each exiting 0 with 246 passing (242 before,
  plus the three new tests and one doctest) and no failure. After each, processes whose command

## What I ran into

- The first version of the late-start test wrote its script after `end_recorded/2`, and
  `write!` makes `pids/` again, so the late stand-in recorded and waited. In a real test the
  script is written before the end, so the test now writes it first.
- A failing run's log once held `erl_child_setup: failed with error 32 on line 284` (a broken
  pipe in the VM's port helper) next to the scratch failures. It did not recur and changed no
  outcome.
- Six processes from VM 32752 were already running when I began, and other checkouts' runs left
  more while I worked. They are not this test VM's, so I did not touch them.

## Findings

### new-1. A start can answer before its stand-in records its pid, so ending by the recorded pids missed it

What happened: the design's rule is that a stand-in writes its pid and "a test ends what is left
by those pids alone". `SessionsTest`'s unknown starts answer as soon as the test moves its clock,
which can be before dtach's child has run far enough to record. The test then ended with an
empty `pids/`, and its stand-in recorded a moment later and read forever.

What I did: the end renames each `pids` directory, so a stand-in that starts later cannot record
and exits at once. The check of recording and the end cannot both miss a stand-in: either it
recorded before the rename and is ended, or it finds no directory and exits.

What the design should change: add to the test rules: "A test's end seals what its stand-ins
record, so a stand-in that starts later exits at once; the VM ends every recorded pid before it
removes its directory, and `gate-test` fails on any process still naming that directory."

### new-2. A recorded pid may name another program by the time a sweep reads it

What happened: pids on this machine went from about 32,000 to 98,000 and wrapped within a
quarter of an hour, with several checkouts testing at once. A VM's sweep reads pids recorded
minutes before, so a stand-in that exited by itself may have left its pid to another program.

What I did: `end_recorded/2` signals a recorded pid only while `ps` shows a command line that
names the directory the pid was recorded under. It chooses by the recorded pid and confirms by
the command line; it never chooses by the command line. A `ps` that fails counts as "not ours",
so a leftover is then left to the gate's check rather than signaled blind.

What the design should change: say whether this confirmation is the rule for every test cleanup
by pid. `kill_all/1`, still used mid-test, signals without it. Mid-test the pid is seconds old,
so I left it.

### new-3. Some held processes cannot record, so only the gate sees them

What happened: a held process that is not a script, such as `StreamTest`'s deaf `sleep` or a
bare `cat` under dtach, has a command line that does not name the test's directory. Its dtach
master's does. Such a process cannot be confirmed by its command line (new-2), so `end_vm/0`
cannot end it. Each has a per-test cleanup, and a passing run leaves none, but a test that fails
before that cleanup leaves one: the deaf `sleep` for up to 90 s, a bare `cat` until its master
ends.

What I did: replaced every `exec cat` held stand-in with `echo_tail!/1`, and bounded the deaf
`sleep`. The holder tests' bare `cat` holds (`HolderTest`, lines 25, 51, 72 and 76) are refused
before anything runs, or are refused because a live socket holds the name, so they start
nothing.

What the design should change: say that every process a test holds is a stand-in script that
records its pid and is bounded, and that a test never holds a bare program. Recording the dtach
master too would be the other way. A master exits with its child, so I did not.

### new-4. `CaptureScreenTest` failed once: an escaped capture had no escapes

What happened: on the first attempt at gate run 1, "writes each state with and without escapes,
scrubbed, with a manifest" failed at `assert escaped =~ "\e["`. The `.ansi` capture held only the
stand-in's last line and blank lines. The test runs `bin/capture-screen`, with its own tmux
server and stand-in, which this unit does not touch. The three runs after it passed.

What I did: nothing more; I reran.

What the design should change: nothing; it is not on the list of known flakes. I recommend a unit
that has `bin/capture-screen` wait for the stand-in's state to be drawn before it captures.
