# F-35: every `Shell` command is a process group of its own, ended with its port

`Shell` now ends a command and everything it started in its group when the port closes: on
a timeout, when the caller dies, or when the VM dies. A process held by `dtach -n` outlives all
three. The change takes MuonTrap's ideas and does them in a POSIX `sh` wrapper, with no C.
It runs on macOS and Linux, under bash or dash.

## What was taken from MuonTrap

The source is MuonTrap 2.0.1 from Hex (`mix hex.package fetch muontrap 2.0.1`), by file and line.

- **The owner's death is the port's stdin closing.** "Erlang signals that it's done by closing
  stdin" (`c_src/muontrap.c:866`). The port closes on a timeout, when its owner dies, or when
  the VM dies, so one signal covers all three.
- **Kill order and grace.** `kill_child_nicely` sends SIGTERM, waits up to
  `brutal_kill_wait_ms` for the child to exit, then sends SIGKILL (`muontrap.c:628`–`644`). The
  wait is 500 ms by default (`muontrap.c:84`) and is set by `:delay_to_sigkill`
  (`lib/muontrap/options.ex:201`).
- **The exit status passes through.** A child that a signal ended exits with `128 + WTERMSIG`,
  and any other child with its own `WEXITSTATUS` (`muontrap.c:903`–`909`). A plain port gives
  the same numbers, so `Shell`'s answers do not change.
- **Not taken:** MuonTrap signals only its one child, and without a cgroup it never reaches that
  child's own children (F-32). Here the target is a process group, which macOS has too.

## What was built

- **The wrapper** (`Shell`'s `@wrapper`), run by the host's `sh`:
  - OTP starts every port program with `setsid` (`erl_child_setup` imports `_setsid`; `ps`
    shows the port's `sh` with pgid equal to its pid). So the `sh` already leads a new group,
    and the wrapper needs no job control.
  - The wrapper starts a watcher subshell in that group. The watcher blocks in `read` on the
    port's stdin. At end of file it ignores TERM itself and sends `kill -s TERM -- -$$`. Then
    it runs the host's `sleep 0.5` and sends `kill -s KILL -- -$$`, which ends the watcher too.
  - The command runs as an async list in the same group, and the `sh` waits for it. When the
    command exits, the `sh` kills the watcher by pid (its own child, not yet reaped) and exits
    with the command's status.
  - On a normal exit the only extra work is one fork, one `kill` and the reaping. There is no
    polling.
- **What the wrapper relies on, and why:**
  - OTP's `setsid` for each port. If a later OTP dropped it, `kill -- -$$` would find no group
    with that id and do nothing. It could never reach the VM's group. `shell_group_test.exs`
    would fail.
  - POSIX `read`, `kill -s SIG -- -pgid`, `trap`, `wait` and `$!` only.
  - An async list without job control starts on `/dev/null` before its own redirections (dash
    does so), so both the watcher and the command get the port's stdin back from fd 4.
  - dash prints a foreground command's signal on stdout, so the command is waited for, not run
    in the foreground. The `sh`'s own stderr goes to `/dev/null`, and the command's stderr goes
    to the port through fd 3.
- **A missing program** still answers `{:refused, {:cannot_start, path, :enoent | :eacces}}`.
  Before it starts anything, the wrapper tests the path and prints a NUL-led line. That costs a
  `stat` in the shell, not a file call on the VM's file server.
- **A timeout** closes the port and answers `{:unknown, {:timeout, ms}}` at once. The watcher
  ends the group. `Shell` no longer runs `kill`, so `Host` names this machine's `sh` and
  `sleep` in place of `kill` (`Host.local/3`, `Host.ssh/5`), and `Programs` knows `sleep`.
  `Shell.run/4` keeps its signature and answers.
- **Over ssh**, the group is the local `ssh`. The remote command still needs the remote host's
  own kill (F-32).
- `model/tla/Shell.tla`, `Shell_Design.cfg` (132 states), and three `Break_Shell_*`
  configurations that TLC fails:
  - `ProgramOnly`, a kill by the command's pid alone, leaves its child running.
  - `HeldStays`, a hold that keeps the group, gets killed with it.
  - `WatchOutside`, a watcher outside the group, kills another program's group once the id is
    reused.
- `test/shell_group_test.exs`: a stand-in `sh -c` with `sleep 60 &` in its group, `wait`, and a
  `dtach -n` hold. After a timeout, after the owner is killed, and after a `:peer` VM is
  killed with `-KILL`, its `sh` and child are gone and the hold lives. Status 137 and output
  pass unchanged. With the kills aimed at `$$` in place of `-$$`, three of the four fail.
- The "dtach" and "Tests" rules in `docs/design.md`.

## Measured

The wrapper's overhead per command against a plain port is the median of 200 runs of devenv's
`echo`, after 10 warm-up runs. The rounds were interleaved, and the load average was 41–65 on
15 cores.

| Run | Median ms (two rounds) | Over a plain port |
|---|---|---|
| Plain port, `echo` (as `Shell` was) | 8.7, 7.7 | — |
| Wrapper under devenv's bash 5.3 | 21.8, 22.6 | +14 |
| Wrapper under macOS `/bin/sh` (bash 3.2) | 18.6, 20.6 | +11 |
| Wrapper under macOS `/bin/dash` | 13.7, 15.7 | +6.5 |
| Bare `bash -c '"$@"'`, no wrapper | 18.0, 17.7 | +9.6 |

The overhead is more than a few milliseconds, and most of it is starting a shell at all: bash
alone costs 9.6 ms of its 14. The wrapper's own fork, wait and kill cost about 4 ms more. dash
starts in a fraction of bash's time. See new-2.

The suites `shell_group_test.exs`, `shell_test.exs` and `holder_test.exs` pass under all three
shells: devenv's bash, `/bin/sh` and `/bin/dash`.

## What I ran into

- `zsh` refuses `set -m` without a terminal, and dash turns job control off without one. The
  job-control wrapper the brief suggested works under bash only. OTP's `setsid` makes job
  control unnecessary.
- dash printed `Killed: 9` into the output of a command a signal ended, on stdout, so
  redirecting the shell's stderr did not hide it. Waiting for the command as an async list
  does.
- Bash 3.2 in POSIX mode has no process substitution, and macOS refuses to open `/dev/fd/N`
  read-write. So there is no pure-shell timer for the grace, and the host's `sleep` times it.
  It runs only after the port closed.
- `registry_test.exs` (from F-7) read a port's pid with `Port.info/2` after `true` had
  started, and failed in two of three `gate-test` runs: under load, `true` had already exited.
  It now takes the pid of an `sh` that `Shell.run` has run to its end.
- The VM-death test's peer took over `:peer`'s 15 s to boot once under load. Its boot wait is
  now 45 s.

## Findings

### new-1. `Stream`'s claim command now ends with the VM if it runs through `Shell.run`

What happened: "Headless delegates" and `Stream.tla` (`CatWrites`, "a restart does not stop
it") say a claimed line goes in "by a process that does not end with the framework". Every
command `Shell.run` starts now ends with the VM.

Why: the claim's `sh -c 'exec 3<"$1" && rm "$1" && exec cat <&3 >"$2"'` runs in the command's
group, and the VM's death closes its port.

What I did: nothing; another builder is writing `Stream`.

What the design should change: say how the claim command outlives the framework. It could be
held with `dtach -n` like an agent, or a short `setsid`-like step could start it. `Shell` could
also offer a detached start that answers once the claimed command has started and leaves the
group. That start would be modeled in `Stream.tla`.

### new-2. A host's shell for `Shell` should be dash where there is one

What happened: the wrapper adds about 14 ms per command under bash and 6.5 ms under dash. Most
of that is the shell's start.

Why: bash is a much larger program to load and start than dash.

What I did: kept devenv's bash as the test host's `sh`, and ran the suites once under
`/bin/dash` and `/bin/sh` by hand.

What the design should change: `Hosts` should give `Shell` `/bin/dash` on macOS and the
system's `/bin/sh` on Debian-like Linux. devenv could export dash, so the tests run the wrapper
under both shells.

### new-3. Children a command leaves when it exits on its own still run

What happened: the group is ended only when the port closes while the command runs. A command
that exits on its own and leaves a child in its group behaves as before: the child runs on. If
the child holds the port's output, `Shell` times out and the child stays.

Why: the owner asked for no work on a normal exit beyond reaping, so the `sh` ends only its
watcher.

What I did: modeled it and stated it in `Shell.tla`'s header and `Shell`'s moduledoc.

What the design should change: decide whether such leftovers end too. One way: the `sh` sends
TERM to its group on a normal exit while the watcher lives, which is one more `kill`. A
leftover that ignores TERM would still need the watcher's grace.

### new-4. The watcher's grace does not end early

What happened: MuonTrap waits for SIGCHLD and sends SIGKILL only when the child is still
there. The wrapper's watcher always waits the full half second before its KILL.

Why: a shell cannot wait on processes that are not its children, and the watcher has none in
the group.

What I did: nothing. It costs a process for 0.5 s after a timeout or an owner's death, and
nothing on a normal exit.

What the design should change: nothing unless timeouts become frequent.
