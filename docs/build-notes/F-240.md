# F-240: a message to an interactive delegate after the tree restarts

## What was built

- **The reproduction** (`apps/caf_mailbox/test/mailbox_restart_test.exs`), on the stand-in: an
  interactive delegate `d1` (`ScreenStandIn`, its pane 200 columns wide as the live one was),
  idle; the `Mailbox` and the `Inlet` stopped and started again while the session runs on; no
  waiter, as after a restart cut it; a framework home 100 characters longer than the test's
  directory, as a live home under an application-support directory is. Then an 860-character
  message from `main`, then a short one. On `main` at 6d4f4b9 both stay `queued` for ever: the
  first with `attempt` `["too_long",196]`, exactly the live row 39, and the second behind it
  with no attempt, exactly row 48. Nothing is typed.
- **The model** (`Delivery.tla`): a constant `Wide`, the `Long` rows whose pointer line is still
  wider than the box; the typed write never reaches them. `Stuck(i)`: such a row, first to its
  interactive addressee, whose process runs idle with no waiter. `Wake(i)`: the wake line, typed
  once (`woke`, a mark in the table, and `wakes`, a ghost count); the alone spec's `Woken`
  says whether the session took it, a turn that ends and brings a waiter. `WaitBound(i)`: past
  the bound the row is `undelivered`, and a notice to its sender is stored under its key.
  `Arrives` allows `undelivered` for a `Wide` row; `UnknownWhy` says `unknown` comes only from a
  forced end and `undelivered` only from the bound; `UndeliveredTold` and `WakeOnce` are new;
  `UnknownStays` covers `undelivered`. `Delivery_Wide.cfg` (one sender, row 1 wide, row 2
  behind it, row 3 room for the notice, a restart, a prompt that may come, a wake line that may
  be ignored) checks every property. `Break_Delivery_WaitForever` (no bound) fails `Arrives`;
  `Break_Delivery_WakeInMemory` (the mark is memory, so a restart forgets it) fails `WakeOnce`.
  The four specs that instance `Delivery` bind `Wide <- {}`; every `Delivery` configuration
  sets `Wide = {}`.
- **The fix** (`Mailbox`):
  - A row whose text the `Inlet` refused (`Transport.Typed.text_refused?/1`) still goes to a
    waiter that comes. With the session idle and no waiter held, the wake line, `[framework] a
    message is waiting for you.`, is typed once in its place through the `Inlet`, checked as any
    typed line. Its mark, the new column `woke_at`, is written before the keys go, so a restart
    never types it again; the line's answer writes nothing. The refusal tries it at once.
  - `wait_bound:` (600 000 ms by default) runs from `woke_at`, or from the refusal with no
    wake line yet. Past it, with the turn still idle and no waiter, the row is `undelivered`,
    `attempt` `["wait_bound", refusal]`, and the next row to the session is tried at once.
  - The sender gets a notice row of its own, under the row's uuid, through the normal path:
    ``undelivered: message <id> to <agent>, after <n> s``.
  - `open_to/3` no longer counts the row, so a parent's stop is not refused by it.
- **`look`** (`MCP`): an interactive agent's `events` reads `not followed (interactive)`, not a
  refusal.
- The design's "A session with no waiter" (which names the wake line), `Mailbox`'s,
  `Mailbox.Table`'s and `Transport.Typed`'s docs, and the README status line say so.

## What was measured

- On the stand-in, on `main`: the long row's pointer line, ``From main (message): a message for
  you is in `<home>/due/d1/1.md`; read it. [delivery <uuid>]``, is wider than the 196 columns
  the `Inlet` allows a 200-column pane (`width - 4`), and is refused `{:too_long, 196}` before a
  key goes.
- With the fix: the wake line is typed within a moment of the refusal. When the turn it starts
  ends, `WaiterStandIn`'s hook takes the 860-character row whole, the transcript's lines settle
  it `delivered` by `waiter`, and the short row behind it is typed. With the line ignored and a
  1.5 s bound, the row is `undelivered` about 1.5 s after the wake line, `main` has the notice,
  and the short row goes in. A restart between the wake line and the waiter keeps `woke_at` and
  types nothing more.
- TLC: `Delivery_Wide` 2 045 distinct states, 31 s; `Break_Delivery_WaitForever` fails
  `Arrives` in 1 171; `Break_Delivery_WakeInMemory` fails `WakeOnce` in 116;
  `Delivery_Interactive` unchanged in outcome, 234 716.

## What I ran into

- **Which of the two causes held.** Only the second. The `too_long` at 196 *was* the pointer:
  an 860-character text goes as the pointer line, and that line, which names the whole path of
  the due file, is what the `Inlet` refused. With a long home it is wider than the box, so the
  row is never typed and "waits for a waiter" (`Transport.Typed.text_refused?/1`, and the
  design's "A pointer line the box still cannot hold is refused, and its row waits for a
  waiter"). An idle session has no waiter after a restart cut it, and starts none until a turn
  of it ends, so the row waited for ever, and row 48 behind it, from the same sender, with it.
  Other long messages to the same parent went in because the parent is a main session with a
  waiter, which takes a text of any length.
- **`not_followed` is not a cause.** `Stream` follows headless delegates only: `Sessions` calls
  `Stream.follow/5` for a headless start alone, and nothing follows an interactive delegate,
  before a restart or after it. `look`'s `events` is `Stream.log/4`, so for an interactive
  delegate it always answered `{:refused, :not_followed}` (the test shows it before and after
  the restart). No interactive delivery reads `Stream`: the typed and waiter transports read the
  agent row, the session file (`Registry`), `Intake`'s waiter and the transcript. `Stream`'s own
  table keeps the headless delegates it follows across a restart. So item 3's first fix,
  following every interactive delegate again at boot, has nothing to follow, and was not built.
- **What the design wants for the rows behind** (item 4): in order per sender and addressee
  (`Delivery.tla`'s `InOrder`), one row in flight per addressee. `Mailbox` keeps one queue per
  addressee (`Table.open_rows/1`), stricter than the model's `First`, which lets another
  sender's row pass. Rows 39 and 48 share a sender, so 48 could not pass 39 either way. The wake
  line or the bound frees it: a row behind a refused one waits at most the bound.
- **The short row in the reproduction.** "short one" is 78 characters with its frame and mark,
  over `Transport.Typed.short/0` (76), so it too went as a pointer and was refused. The tests
  send "hi". Under a long home the typed transport alone carries a framed text of about 28
  characters at most; the wake line is what lets every longer row reach such a session.
- A bound that wrote the row and stopped left the row behind it for the next cue, which an
  idle session with no waiter never sends; the next row is tried at once. The same holds for
  the wake line after a refusal.
- The test that a row with no home waits now sees the wake line: that row is refused as too
  long, and is stuck as any refused row.
- `erl_child_setup: failed with error 32` printed in mailbox runs that passed; it comes from a
  port closed early and failed nothing.
- The branch is past 500 changed lines: about 640 in code, specs, tests and docs, and some 105
  more in the model configurations, most of them one-line `Wide` bindings. It was not split.

## Findings

### new-1. The pointer line itself does not fit a box under a long home

What happened: the pointer line names the due file's whole path, and under a home like the
live one it is wider than the 196 columns a 200-column box holds. The wake line works around
it by bringing a waiter, at the cost of a turn the session spends on a line that says nothing.

Why: the `Inlet` refuses a box of more than one line, since no fixture shows how a release
draws a wrapped box (F-113's new-1).

What I did: the wake line and the bound, as decided. I did not build a two-row box reading.

What the design should change: capture 2.1.322's screen of a box wrapped over two lines (a
fixture at 200 columns), teach `Screen` to read it, and let the `Inlet` type a pointer line up
to two rows; at 200 columns that covers every home under about 270 characters, and the pointer
then goes in with no wake line.

### new-2. A row answered `unknown` that was never typed (decided)

What happened: the first build answered a row at the wait bound `unknown`, which elsewhere
means the text may have gone in.

What I did: as decided, the status is `undelivered`, modeled in `Delivery.tla` (`UnknownWhy`
covers both, `UndeliveredTold` the notice), and the sender gets a notice row.

What the design should change: nothing more; the views and `Metrics` may count `undelivered`
on its own when they next change.

### new-3. `look`'s `events` for an interactive agent (decided)

What happened: `look` showed `events: {refused: :not_followed}` for every interactive agent,
which the live report read as a fault.

What I did: as decided, `look` names it `not followed (interactive)`. No MCP test covers it:
the MCP suite starts headless delegates only, and an interactive one there is a setup of its
own.

What the design should change: nothing.

### new-4. The wake line's answer is not recorded

What happened: the wake line's mark is written before its keys, and its answer writes
nothing, so a row whose wake line the `Inlet` refused (the screen not idle, say) waits for the
bound with no second line and no record of why.

Why: the line is typed once per row, never repeated; the row's `attempt` keeps the refusal
that `text_refused?/1` reads, so the wake line's answer has no field of its own.

What I did: nothing beyond the mark.

What the design should change: decide whether the wake line's answer is kept (a column, or an
act in `Acts`) so a view can show a row whose wake line never went in.
