# F-90: `MCP`'s `run`: an unknown answer names its job; the cap and the job id per instance

## What was built

- An unknown `run` answer (any reason) is `{:unknown, %{job: id, reason: reason}}`; in the
  JSON the tool returns, `{"unknown": {"job": "mcp-<instance>-<n>", "reason": …}}`. Known
  answers are `Jobs`' own, unchanged.
- `:cap` is an option of `MCP` (ms, default a day) in place of the module constant.
- `:instance` is a required option of `MCP`; the job id is `mcp-<instance>-<call id>`.

Tests (`apps/caf_mcp/test/mcp_test.exs`): an unknown answer names its job, as a term, as JSON
and in the call log; the cap option and its default; two instances over one `Jobs` stand-in
make different ids. The `run` test checks the new id form.

## What was measured

`devenv test` exited 0 and ended with `every gate ran`; `gate-test` passed three times, with no `Failed:` lines and no `Result: a/b` with a not b.

## What I ran into

An unknown answer needed a `Jobs` that answers unknown. A real one does so only on a drop, a
missing exit or a timeout, which are slow or racy to make, so the tests use a stand-in module
with `Jobs`' `run/6`.
