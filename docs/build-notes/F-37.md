# F-37: the framework as a Mix umbrella, one app per part

## What was built

A mechanical move, with no change of behavior. Every module and test moved with `git mv`, and
module names stay `CodingAgentFramework.*`. Each app has its own `mix.exs`, and each app with
tests has its own `test_helper.exs`, a copy of the old one. The build, deps and lock stay at the
root (`build_path`, `deps_path`, `lockfile`). `mix.lock` did not change. The root `mix.exs` is
the umbrella (`apps_path: "apps"`), and the root `.formatter.exs` formats every app.

`caf_test` compiles its code only in the test env, as `test/support` did. Every other app uses
it `only: :test`. Its `stream_data` is also in dev, so `mix format` can import its rules.

`:crypto` is now declared (`extra_applications`) by `caf_intake` and `caf_stream`, the two apps
that call it. Before, the one app got it through `plug`. No module uses `Logger`, so no app
declares `:logger`.

No code is shared between parts beyond the apps above. Each of the eight `Table` modules has
its own `open/1` (WAL, a 5 s busy timeout) and its own private `query/3`. Pulling that out would
change code, so the move leaves it (new-3).

The tests moved to the lowest app that may use everything they touch, not always to their part's
app. See new-1.

Hex packages: `exqlite` for each app with a `Table`, and `plug` for `caf_intake`. Tests also use
`stream_data` (`caf_registry`, `caf_transcripts`, `caf_stream`, `caf_tracker`, `caf_test`), and

The test-only apps (`only: :test`): every app with tests uses `caf_test`. `caf_cli` also uses
`caf_holder`. `caf_stream` uses `caf_cli`. `caf_tracker` uses `caf_accounts`, `caf_control`,
`caf_holder` and `caf_tmux`.

Checked: Mix sorts the apps and refuses a cycle, and `tsort` on the edges above finds none. It
goes one way: host (`caf_shell`, `caf_tmux`, `caf_holder`), then readers and writers, then
`caf_sessions`, then `caf_recoveries` and `caf_tracker`. Inside the readers-and-writers layer
three apps use another of that layer: `caf_accounts` uses `caf_intake` (for its http hooks), and
`caf_usage` and `caf_cli` use `caf_accounts`. `caf_tracker` uses `caf_recoveries` (for
`RecoveriesSource`), so `caf_recoveries` sits below it.

## What I ran into

- Mix refuses a cycle even when one edge is `only: :test`: `Could not sort dependencies. The
  following dependencies form a cycle`. I tried this first in a scratch umbrella of two apps.
- `mix test --only model` still works from the root. When it recurses through an umbrella, an
  app with no test left after the filter prints a line, and the run does not fail.
- Seven apps have no tests of their own. `mix test` prints `There are no tests to run` for each
  and goes on.

## Findings

### new-1. Six test files cannot live in their part's app

What happened: "The parts" says each app has its own tests. Six test files use a module from an
app above their own. `intake_test`, `usage_test` and `sessions_test` read their rows through a
Tracker source. `tmux_sampler_test` and `recoveries_test` start a `Tracker`. `intake_test` also
prepares `Accounts`, and `accounts_test` holds a stand-in with `ClaudeCLI`'s environment. The
tests of `caf_shell` use `TestHost`, which uses `caf_shell`.

Why: an app's tests may use only the apps it declares. Declaring an app above it, even
`only: :test`, is a cycle, and Mix refuses it.

What I did: moved each file whole to the lowest app that may use everything it touches. The
intake, usage, sessions, sampler and recoveries tests went to `caf_tracker`, the accounts test
to `caf_cli`, and the shell tests to `caf_test`. No test changed. The `mix.exs` of `caf_tracker`
and `caf_cli` say why. So `caf_shell`, `caf_intake`, `caf_accounts`, `caf_usage`, `caf_sampler`,
`caf_sessions` and `caf_recoveries` have no tests in their own apps.

What the design should change: say that a test of a source, or of two parts together, belongs to
the higher app. Then split each of these files in a unit of its own. The cases that read a
Tracker source become tests in `caf_tracker` (for example `intake_source_test`). The `Accounts`
hooks case moves to `caf_accounts`, which then uses `caf_intake` in its tests as it does in its
code. The held stand-in case becomes a `caf_cli` test. Each part's own cases go back to its app.
For `caf_shell`, `TestHost` uses `Host`, `Programs` and `Shell`, so either its tests stay in
`caf_test` or `TestHost` is split into a part with no host and a host part. Keeping them in
`caf_test` is simpler.

### new-2. A use reached through a declared app compiles without its own declaration

What happened: in a second scratch change I removed `caf_shell` from `caf_stream`. `Stream`
calls `Shell.run`, yet it still compiled with `--warnings-as-errors`. `caf_stream` reaches
`caf_shell` through `caf_holder`.

Why: Elixir's check accepts a module from any app in the dependency tree, not only one declared
directly.

What I did: put the line back. Each app here declares every app its code names, as read from
`mix xref graph`.

What the design should change: "a use that is not declared does not compile" holds only for an
app the declared ones do not bring along. If it matters, a gate could compare each app's
`mix xref graph` with its declared deps. I did not build that.

### new-3. Each `Table` repeats its own way of opening SQLite

What happened: the eight `Table` modules, in eight apps, each open the database with WAL and a
5 s busy timeout, and each has a private `query/3`.

Why: each was written in its own unit, before the apps were split.

What I did: nothing. The move changes no code.

What the design should change: if one way of opening the tables is wanted, put it in a
host-layer app (a `caf_sqlite`, used by each app with a `Table`), as its own unit.
