# F-68: agents on the workstation, work on hosts, a tree that talks along its edges

A design unit: `docs/design.md`, `README.md` and one word in `CLAUDE.md`. No code changes.

## What was decided

The person set the framework's core shape, and the words for it:

- **Words.** *Main session* (a project's top agent, on its trunk), *delegate* (a real Claude
  Code session a main session starts, on any account) and *subagent* (Claude Code's own, run
  inside an agent on its account). *Parent* and *child* name only the link between two levels;
  *agent* means a main session or a delegate. *Workstation* is the person's computer, where every
  agent runs; a *host* is any machine that runs work for agents, the workstation included; a
  *job* is a one-off command and a *service* a kept program; a *copy* is a host's copy of a
  worktree. The Elixir application that runs the parts is the *embedding app*, so *host* names
  only machines. The design's "The words" became "Concepts", which defines each once.
- **Agents run only on the workstation.** Hosts run jobs and services, on a copy of the agent's
  worktree that rsync brings in step before each run, edits not yet committed included. A service
  on another host can have a port forwarded to the workstation. Both jobs and services are in
  scope now.
- **One main session per project**, on trunk in the project's own checkout. It changes nothing
  there; after each landing the framework pulls trunk. A main session can start one for a
  project that has none (`start_main`).
- **The tree talks along its edges.** An agent messages its parent and its children, and main
  sessions message each other, across projects. Only a parent fixes its child. Any agent can read
  the whole tree (`agents()`, from the `Tracker`).
- **Reports.** A delegate's report still arrives as a message when its work ends; `run_delegate`
  adds a form that holds the call for the report of short work, up to a timeout.

## What changed in the design

- "What it is", "Concepts", the parts table (`Parents` became `Mains`; `Copies` and `Jobs` are
  new; `Mailbox`, `Services` and `Grants` follow the tree), "Hosts" (was "Multiple hosts"),
  "Main sessions" (was "Parent sessions"), "Agents working together" and its tools table with a
  column for who may call each, `Team.tla`'s invariants, and the order of the units, which now
  names `Copy.tla` before `Copies`, `Jobs` and remote `Services`.
- The remote agents of the first plan (a session held on another host, its hooks forwarded back
  over ssh, its session files and status line read there) are dropped. What is built stays keyed
  by host.

## Findings

### new-1. The code's docs still say "host app"

What happened: 13 `@moduledoc` and `@doc` texts in ten apps say "host app" for the embedding app.

What the design should change: nothing; a small unit renames them to "embedding app", with any
`parent` that names a kind of agent in the built code's docs.
