# F-279: a message of any length is delivered by bracketed paste, and settled by its transcript line

## Why

The operator's messages to a main session or a delegate went as typed lines only while the line
fit the pane: about 123 characters of text at 200 columns (F-277). A longer one went as a due
file's pointer. The operator wants a message to arrive as a message, not as a file. F-277's
new-5 named the way: paste the text from a named tmux buffer, then Enter, and settle by the
transcript's user line.

## What was built

- **The model first.**
  - `Agent.tla`'s write is three steps (F-279): `WriteAsked` is the load (`load-buffer -b
    <name> -`), which sets the buffer named for that write alone; `Paste` checks the pane's tag,
    pastes what the buffer holds then, and drops it, in one step; `Enter` is a write of its own
    under the same check. A server's death drops its buffers. A refused paste drops its buffer
    too. A new invariant, `PastesItsOwnText`: what reaches a pane is its own write's text.
  - `Break_Agent_OneBuffer.cfg`: every write shares one buffer name. TLC finds two loads, then
    the first write's paste, which puts the second write's text into the first pane (837
    distinct states).
  - `CheckThenSend` still fails, now through the Enter: a paste's check, a server's restart,
    and the Enter by pane id alone into another agent's pane. The paste alone could no longer
    show it, since a restart drops the buffer.
  - The two-write config grew from 1.18 M to 14.7 M distinct states (78 s). It moved to
    `slow/Agent_WritesTwo.cfg`. The fast `Agent_Writes.cfg` has one write (910 k states, 14 s);
    a new fast `Agent_Pastes.cfg` has two writes and a server death, no viewer death (1.46 M
    states, 18 s). `PastesItsOwnText` is in all four write configs.
  - `Inlet.tla`'s header says a write's run is the three commands, in one call. Its queue is
    unchanged. `Delivery.tla`'s `Long` is now "past the paste's bound" and `Wide` "no pointer
    line to paste" (no home); its actions are unchanged.
- **`Shell.run/4`** takes `input:`, bytes written to the program's stdin as it starts, at most
  `Shell.input_max/0` (16 384, the smallest pipe buffer of the hosts), so the write is whole
  before the program reads and never fails once it exits.
- **`Tmux`**: `write/4` takes `{:paste, buffer, text}`. The CLI runs `sh -c 'head -c <n> |
  tmux … load-buffer -b <name> -'` with the text on stdin: the stdin of a port never closes, so
  `head` reads exactly the text's bytes and ends the pipe. Then one guarded command: `paste-buffer
  -p -r -d -b <name> -t <pane>`; the refusal branch runs `delete-buffer` first.
  `Tmux.paste_text/1` is the one check of a paste's text: valid UTF-8, not empty, at most
  `paste_max/0` bytes, no control character but newline and tab. The CLI needs `sh` and `head`.
- **`Inlet.type/4`** pastes: the turn, the empty box, the paste into `buffer:` (required), then
  the screen until the box no longer reads empty (its text, or a screen `Screen` cannot read:
  the fold, or many lines), then Enter. The function form of the text (F-277) and the width
  limit are gone from the write.
- **`Mailbox`** pastes a row's framed text and mark when it is at most `Transport.Typed.bound/0`
  (8 000 bytes), any number of lines; past it, the due file and its pointer line. The buffer is
  `caf-<uuid>`; the wake line's is `caf-wake-<uuid>`. `Transport.Typed.fits?/3` is gone.
- **`ScreenStandIn`** asks for bracketed paste, takes a paste whole with its newlines, draws it
  as its text when it is one line that fits or else as `[Pasted text #n +k lines]` (modeled,
  not captured), and writes each submit's newlines as `\n` in `submitted`.
- `docs/design.md` ("A session with no waiter", the `Inlet` row, "Delivery") and the README's
  status line.

## Measured

Not measured on a real Claude Code: no logged-in setup of my own, and the gates start none.
The bound is set low, at 8 000 bytes. How to measure it, by a person at a logged-in terminal:

1. Start Claude Code 2.1.322 in a tmux pane on a socket of your own.
2. For sizes 8 000, 16 000, 32 000 and 64 000 bytes, of many lines and of one: `head -c <n>
   file | tmux -S <socket> load-buffer -b m -`, `tmux -S <socket> paste-buffer -p -r -d -b m
   -t <pane>`, wait for the fold, then `send-keys Enter`.
3. Read the session's transcript: the user line's `content` must hold the whole text. Note the
   largest size that does, and capture the fold with `bin/capture-screen` as a fixture.

## Findings

### new-1. The check after a paste reads "the box is not empty", not the fold

What happened: no fixture of 2.1.322's fold was captured, and `Screen` reads a box of more than
one line as unrecognized. The `Inlet` sends Enter once the box reads anything but empty: its
text, or a screen `Screen` cannot read.

Why: the box was empty before the paste, so what it holds then is the paste. The settle is the
transcript's user line, never the screen.

What I did: that check, and a stand-in that draws a fold modeled on F-277's new-5.

What the design should change: capture the fold (`bin/capture-screen`) and add a `Screen`
reading for it, so the check reads "a paste fold, or the text itself". An unrecognized screen
then stops counting as drawn.

### new-2. The bound is not measured

What happened: see "Measured". `Transport.Typed.bound/0` is 8 000 bytes; the tmux part takes
up to 16 384 per paste.

What the design should change: measure as above, then set the bound by the result, at most
`Tmux.paste_max/0`. A larger paste needs the load to take its stdin in more than one pipe's
worth, which `Shell` does not do.

### new-3. The wake line, `wait_bound` and `Wide` now serve only a row with no home

What happened: a pointer line has no width limit once it is pasted. A row the typed write
cannot carry is now only a row past the bound with no `home:`, or one with a control character.

What the design should change: the main agent may decide whether a framework with no home
should refuse a message past the bound at its store, and the wake path go. I did not remove
it.

### new-4. `Inlet.reload_plugins/3` still types its command

What happened: `/reload-plugins` goes as typed keys with the width check, since a pasted slash
command may not run as a command in Claude Code. Not measured.

What the design should change: nothing unless a pasted command is shown to run.
