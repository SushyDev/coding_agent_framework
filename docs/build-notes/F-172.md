# F-172: an ask withdrawn; the pointer line; a forced end's rows settled; names that fit the home

Five follow-ups to F-166, F-169 and F-170, in `Mailbox`, `Mains`, `MCP`, `Acts`, `Delegates`,
`Services` and the app's config.

## What was built

- **An ask withdrawn.** `Prompt.tla` first: `WithdrawNow` is one more way a prompt settles, by
  its rightful answerer in one step with its claim, as `AnswerNow` is, so an answer and a
  withdrawal race to one settle. The alone spec has a fifth prompt, `ask` (kind `question`,
  its owner `Mailbox`), checked in `Prompt_Asks`; `AnsweredOnce` holds there, and
  `Break_Prompt_WithdrawSettled` (a withdrawal of an answered ask) fails it. In the code,
  `Mailbox.withdraw/4` stores a row from the operator to the asker under the ask's uuid, kind
  `withdrawn`, text `Ask <id> was withdrawn: <reason>`, delivered as an answer is. The answer
  and the withdrawal share the table's unique key, so the second is refused `:settled`;
  `answer/4`'s second answer is now refused `:settled` too, in place of `:answered`. `asked/3`
  shows the settle with its `kind`. The operator's call is the `withdraw` tool, the operator's
  alone, and `Operator.withdraw/3`.
- **The pointer line.** `Transport.pointer_line/2` names the file in backticks; `Mailbox`
  frames it with the row's sender as it frames the text, so the typed and the launch pointer
  read ``From d1 (message): a message for you is in `<path>`; read it.``, and an unframed brief's
  ``A message for you is in `<path>`; read it.``. The settle still matches each row by its uuid
  mark, which the transcript line carries after the text. The typed short limit stays. The
  launch test that goes as a pointer now runs under a home with a space (`the home`), through
  a real start with the stand-in, and settles by its user line.
- **A forced end's rows settled by `Mailbox`.** A forced act's claim in `Acts` carries `detail`
  `{"force":true}` (`Acts.claim/6`'s new `detail:` option; `MCP` writes it on a forced `stop`
  and a forced `end_main`). `Mailbox` given `acts:` settles, at the start of each of its
  settles, every row `sending` to an agent whose row ended, with no process left, after such a
  claim: `unknown`, `ended_while_sending`, each settle a row of `Acts`. The tree hands it the
  instance's `Acts`. In `Delivery.tla`, an evidence settle (`SettleSeen`) no longer reads a row
  to a session whose end was forced once it ended: that row is `ForceSettled`'s alone, as the
  design says. `fcall` (memory) holds the forced ends whose operator's call runs;
  `Break_Delivery_SettleInCall` settles only there, and a restart between the end and the
  settle leaves the row `sending` (`ForcedSettles` fails, on `Delivery_ForcedSettles`).
- **Names that fit the home.** `Config.name_room/1` answers `%{agent: n, service: n}`: 103 less
  the home and `/d/.sock`, or `/ws/services/.sock`. The tree hands each as `name_room:` to
  `Delegates`, `Mains` and `Services`, which refuse a longer name `{:bad, :name, {:longer_than,
  n}}` before any row. Sockets stay in the home.
- **`Mains`' start passes its caller's deadline.** Its call of `Sessions.start/5` and
  `resume/6` carries `caller_deadline: row.deadline - @slack`, as `Delegates`' does. A test
  holds the start's task at its `mcp:` function, suspends `Sessions` so the request waits in its
  queue, moves the clock past the caller's deadline, and sees `{:refused, :caller_gone}`, the
  row refused and no session made.

## What I ran into

- The first `Break_Delivery_SettleInCall` passed: in the model, once a forced session's process
  is gone, the transports' evidence settles a row left `sending` (due again, then `ended`), so
  nothing stays `sending`. The code did the same (see new-1). The guard on `SettleSeen` makes
  the model say what the design says, and the Break then fails.
- `Mains.start_main/5` calls `Sessions.declare` before its start, so a test that suspends
  `Sessions` first holds the declare, not the start. The test holds the start's task at its
  `mcp:` function instead, which runs right before the call of `Sessions`.
- `Worktree.name?/1` caps a name at 64 bytes. A home shorter than 39 bytes leaves more room than
  that, so `Mains` checks the room before the shape, or a long name is refused `{:bad, :name}`.

## Findings

### new-1. F-170's new-5 rows did not stay `sending`; they were settled `ended`

What happened: F-170's new-5 says a restart between the forced end and `ended_while_sending/3`
leaves rows `sending`. In the code before this unit, after such a restart a waiter row with no
hand-on answer (`sent_at` nil) or a launch or typed row whose process is gone is made due again
by its transport, and `deliver/3` to the ended agent then settles it `ended`.
Why: each transport's settle reads the process's end as "nothing more will come" and makes the
row due again; the ended target ends it. `ended` says the row never went in, while a forced
end's row may have.
What I did: `Mailbox`'s forced settle runs before any transport reads its evidence, and the
model's `SettleSeen` leaves such a row to `ForceSettled`.
What the design should change: nothing more; "Delivery" now says the forced settle comes
first.

### new-2. No spec models `Mains`' start

What happened: F-166's new-1 asked to give `Mains`' start the queued request in its spec. No
spec models `Mains`' start: `Team.tla` starts with its main sessions running, and
`Checkout.tla` models only the checkout.
Why: `Mains`' start came after the specs that would hold it.
What I did: followed `Delegate.tla`'s `Called`, `CallerLate` and `TakeStale`, whose rule is the
same (a refusal at the row's deadline on an absent agent row needs `Sessions` to refuse a late
request), and named them in the code's comment and the test.
What the design should change: say whether `Mains`' start needs a spec of its own, or that
`Delegate.tla`'s start protocol is its contract too.

### new-3. `Team.tla`'s ask has no withdrawal

What happened: `Team.tla` instances `Prompt.tla` for an ask (`Q`), and `AnswerOnce` there counts
one answer row per ask. A withdrawal row shares the answer's key, but `Team.tla` has no step for
it.
Why: the brief named `Prompt.tla`; `Team.tla`'s state is already large.
What I did: `Prompt_Asks` checks the race alone.
What the design should change: when `Team.tla`'s ask is next changed, add `Withdraws` as
`Q!WithdrawNow` with its row, so `AnswerOnce` covers both.

### new-4. The name room covers the home only

What happened: a service on another host holds its socket in that host's directory, not the
home, so `name_room:` (the workstation's) does not bound it; `Holder` still refuses a socket path
too long there at its start.
Why: the brief asks for the room the home leaves.
What I did: `Services` checks the home's room for every service, whatever its host.
What the design should change: if services on other hosts matter, the room per host (103 less
its directory and `/services/.sock`), from the `hosts` config.

### new-5. `withdraw` is listed to every agent

What happened: the operator's `withdraw` tool is in `MCP`'s one tool list, as `end_main` and
`answer_startup` are, so every agent sees a tool that refuses it `:operator_only`.
Why: the operator's calls go through the same tools as an agent's (`MCP.operate/3`).
What I did: followed `end_main`'s shape.
What the design should change: a list of the operator's own tools that agents do not see, if
the agent's surface should stay small.

### new-6. This unit is over 500 changed lines

What happened: about 620 changed lines and four new configurations.
Why: five follow-ups in one brief, each with its tests and docs.
What I did: kept each in its own part of the diff.
What the design should change: nothing; a brief of five follow-ups could be two branches.
