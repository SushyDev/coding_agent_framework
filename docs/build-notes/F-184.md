# F-184: a background command that outlives its delegate's report; a turn its end wakes

F-183 stopped on `stuck_background` and `hooks_silent`, whose readings were not recorded. The
main session then measured a headless turn with a 120 s background `Bash` command on Claude
Code 2.1.322: the turn's `result` comes while the command runs; at its end come
`task_updated`, `task_notification`, `background_tasks_changed` with no task, a new
`system`/`init` and a second turn of Claude Code's own, with its own `result`. This unit builds
the four items the brief decided from that. No test or step of it started the real Claude Code.

## What was built

- **The second turn is not a second report** (item 1). `Stream.Fold` reads an init that comes
  while the turn reads ended (a session id already read, `idle`, not gone) as a turn of Claude
  Code's own: `idle` is cleared until its `result`. So `Sessions.Turn` reads it `:running`,
  `Stream` refuses a message into it `turn_running`, and a parent's message waits for its end
  instead of having that turn's result taken as its reply. Its result names no message, so it
  is kept in `own` and told to the parent once, as F-155 built, never as the report: the fold
  keeps the first result on the brief's message. The fold also keeps Claude Code's own list,
  the last `background_tasks_changed` (`background`: its task ids and how many came), cleared at
  an exit and a resume. The headless stand-in's `bg` plays the measured order, the command's
  end and its turn's result each released by a line the test writes to a FIFO. `DelegatesTest`
  checks it end to end: the report taken while the command runs, a parent's message held
  through the turn of its own, one notice, one reply.
- **`Remedies.tla`** changed for both. The `partial` report is gone (`hands`, `made`, `took`,
  `PartialOnce`, `Break_Remedies_PartialStands`, `Break_Remedies_PartialTwice`). A delegate has
  its turn (`brief`, `idle`, `own`, `ended`), a background command and the reports taken: the
  brief's result is the report whether a command runs or not; the command's end starts a turn
  of its own; the delegate ends only with no turn or command running. New: `OneReport`
  (`Break_Remedies_LastResult`: the report read from the latest result), `StuckAfterReport`
  (the symptom only after the report, no partial), `EndedQuiet`, and `ReportTaken` as liveness
  (the report is never held up). The remedy's effect that ends the symptom ends the command, so
  a turn of its own follows.
- **`stuck_background`** (item 2; `CodingAgentFramework.StuckBackgrounds`, in `caf_recoveries`,
  one per host, after `AbsentMains` in the tree, reading `stream` and `watch`). The state: a
  running headless delegate whose fold's turn ended with a result while `background` names a
  task, and a process group of its process whose CPU time has not moved for `quiet:` (ten
  minutes by default), timed from this process's first read. `StuckBackgrounds.Groups` reads
  every `/proc/<pid>/stat` and `ps -A -o pid=,lstart=` in one shell on the host: a group is one
  led by a descendant of the delegate's process outside its own group, its CPU time the sum of
  its members' `utime`, `stime`, `cutime` and `cstime`; a host with no `/proc` answers
  `{:unknown, :no_proc}`, so nothing on macOS is stuck (new-1). On F-182's shape: recorded
  first, decided by a row in `Acts`, asked off the list or past its cap; else claimed (act
  `end`) and TERM sent to the group by its leader's pid and start time
  (`Holder.Process.signal/4`, `group: true`). The row is then `acted` with the tasks and the
  count of lists read; the next `background_tasks_changed` decides it: a task gone is
  recovered, all still listed fails the verify (off the list, asked), the delegate gone is
  unknown. A group already gone is refused and asked; an unknown signal is asked. The default
  list has `stuck_background` by `end`, 10 per bound.
- **`hooks_silent`** (item 3; `CodingAgentFramework.HooksSilent`, in `caf_recoveries`, one per
  host, reading `transcripts` and `intake`, and at the tree's interval, since a silence sends
  no cue). For each running agent with a session, the newest tool call in the last 64 KiB of
  its transcript (`Transcripts.Fold.tool_calls/1`) is silent when older than `bound:` (two
  minutes) and its session's newest `Intake` row (`Intake.Table.newest/4`) was written before
  it, less `slack:` (5 s) for the two clocks. The app's tree always hooks `PreToolUse`, so each
  call posts a row before it runs. One state per call; recorded in the `Watch` and shown; the
  kind is on the default list with a nil remedy, so it is never asked.
- **Tests wait on the announced event** (item 4). `SessionsSetup` starts `Stream` with
  `interval: 100` and a `notify:` that sends the test `{:cue, cue}`, and gives
  `stream_until/4` (the fold checked first, then at each `stream:` cue) and `turn_ended/3`
  (`Sessions.Turn.stream/1` ended, no line waiting for its replay). Every headless test that
  stops a session soon after a start now waits on it: `agents_test.exs`'s "a delegate ends only
  once no process of it may live" (the F-183 and F-176 failure), `sessions_options_test.exs`,
  and `sessions_headless_test.exs` (its `stream_row`, which the stops of `d3` and `d4` follow).
  The other `Sessions.stop` calls in the tests stop interactive stand-ins, whose stop reads the
  session file, not `Stream` (`sessions_worktree_test`, `agents_source_test`, `mains_test`,
  `sessions_dialog_test`, `sessions_test`).
- **Docs**: `docs/design.md` ("Metrics and healing": the measured order, what F-184 built, the
  table; "The delegate protocol": no `partial` report; B8), the README.

## Findings

### new-1. No event names a background task's process, so a task maps to a group only by the tree

What happened: `stuck_background` ends "that task's process group". `task_started` and
`background_tasks_changed` carry a task id, a run id, a tool use id and a description, but no
pid. The pinned release's bundle spawns each shell command `detached` (its own session and
group), so a background command is a group led by a descendant of the delegate's process.
Why: Claude Code does not expose the pid. What I did: a group is any such group outside the
delegate's own, keyed by its leader's pid and start time, read only while the list names a
task and the report was taken (so no foreground command runs); its verify reads whether a task
the list named left it, not which one. Not checked: whether a stdio MCP server a project
configures is spawned detached too; if it is, a quiet one reads as a stuck group while any task
is listed, and would be ended. Not checked on Linux against
the real release: this machine is macOS, where the reader answers `unknown`. What the design
should change: the release check records, on Linux, the process tree of a headless session with
one background command, to confirm the group's shape; and, if a later release names the task's
pid or offers a stop of a task in its control protocol, the remedy ends the task by that.

### new-2. An init while the turn reads ended is a turn of Claude Code's own

What happened: after a background command's end, the fold read the turn ended (no task, the
last result read) while Claude Code ran a turn of its own, so a parent's message could be
written into it and that turn's result, naming the message, taken as its reply. Why: only the
framework's own write cleared `idle`. What I did: an init that comes while the turn reads ended
clears `idle` until the next result. Between the `task_notification` and that init the fold
still reads ended; a message written then goes into the turn Claude Code starts, which answers
it. What the design should change: confirm the release writes one `system`/`init` per turn it
starts, as measured; the release check records it with the background command.

### new-3. `hooks_silent` compares two clocks

What happened: a tool call's time is Claude Code's timestamp on its host; an `Intake` row's is
the framework's. Why: the transcript is the only record of the call. What I did: a slack of
5 s, and only the newest call of each session is read. What the design should change: nothing,
unless hosts reached over ssh drift more; then the slack is the host's measured offset.

## Landed with one change (the main session)

new-1's open case (a quiet stdio MCP server spawned detached reads as a stuck group, and would be
ended) is real on Linux, where the framework is about to run. So `stuck_background` lands shown
only: `Watch.default_remedies/0` gives it no remedy, and the design's table says so. An operator
turns the remedy on with `remedies:`. It goes on by default once the Linux release check records
a headless session's process tree with one background command and one stdio MCP server.
