# F-13: a Claude config directory of the framework's own per account (design)

## What was built

Design only, no code. The owner decided that the framework never uses `~/.claude`. Each
framework instance has a home, given by the host app, and each account's Claude config
directory lives in it, at `<home>/accounts/<account>/claude`. Every launch sets
`CLAUDE_CONFIG_DIR` to it, and a launch without one is refused. The framework writes each
account's settings, hooks and MCP servers there from data. `docs/design.md` gains the words
"framework home", and its account word, `Accounts` row and "Claude Code" rule change.

`Registry` already reads whatever `config_dir` its caller gives, so it needs no change. `Accounts`
and `ClaudeCLI` are built later against this text. For development, devenv can export a home
under its state directory when the example app needs one.
