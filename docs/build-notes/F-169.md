# F-169: the embedding tree as a library function; a PreToolUse callback that corrects; a home with a space

An app now embeds the framework and runs a main session on it. It had to copy the example's
private wiring, could not correct a tool call from its callback, and could not use the default
app home on macOS. This unit is B3's start ("The app's surface") and decision 1's correction
(every tool call checked, corrected rather than refused where it can be).

## What was built

**The tree as a library (B3's start).**

- A new app, `caf_surface`, with the module the app's surface names: `CodingAgentFramework`.
  `child_spec/1` takes one `CodingAgentFramework.Config` and answers one supervisor child, id
  `{CodingAgentFramework, instance}`, so two instances are two children; `start_link/1` starts
  it. A start it refuses or cannot settle fails the app's start with `{:refused, reason}` or
  `{:unknown, reason}` as the error. `parts/1`, `reads/0`, `server/1`, `resources/1` and
  `job_units/3` are as they were.
- The tree is the example's, moved whole with `git mv` (`example.ex` to
  `coding_agent_framework.ex`, `example/config.ex` to `config.ex`, `example/ends.ex` to
  `ends.ex`, `example_test.exs` to `surface_test.exs`), so its order, its cues and its
  callbacks do not change. The bare `CodingAgentFramework` module that only held a doc in
  `caf_shell` is gone; its doc is now the surface's.
- `Config.new/1` checks the config whole, each refusal naming its key: a key it does not know
  (`struct!` raised before), `tool_hooks` (only `pre_tool_use` and `post_tool_use`, each a
  function of one argument), `extensions` (new, `[]` by default, checked by
  `MCP.extensions/3`, the same check `MCP` runs at its start, answering `{:bad, :extensions,
  reason}`), and a home too long for its tmux socket (below). `MCP` takes the config's
  `extensions:`; the example never passed them before.
- `caf_example` keeps `ConfigFile`, `Console` and `Run`, and declares `caf_surface` and only
  the apps its console names (18 fewer).

**A PreToolUse callback that corrects.** `Intake`'s `pre_tool_use:` callback may also answer
`{:allow, updated_input: map, additional_context: text}` and `{:deny, reason,
additional_context: text}`, each key optional. `Intake` writes them as the hook's
`updatedInput` and `additionalContext`, the shape Claude Code 2.1.322 reads for PreToolUse. A
context over 10,000 characters, an input that is not a map, `updated_input` beside a deny, or
a key it does not know is no decision: the call passes, and the row's `problem` names why
(`["context_too_long", 10001]`, `["bad_answer", "updated_input"]`). The doc says to write the
context as facts. A correction is a decision as any other: its row has the actor `app`, the
response it sent (the new input in it) and the tool's own input in `data`.

**A home with a space.** A read-only audit followed every path from the home to a shell, a
socket and a program's argument. Every `sh -c` script already quotes its positional
parameters, and every other path goes as its own argument or a single-quoted word. Three
places broke:

- `ToolHome.ssh_options/1`: ssh splits `UserKnownHostsFile` on whitespace into several files.
  The value is now `UserKnownHostsFile="<path>"`, which ssh takes as one word; that one change
  fixes all four of its uses (ssh over `Shell.command/3`, rsync's `-e`, a service's forward,
  `GIT_SSH_COMMAND`). `prepare/2` no longer refuses whitespace; it refuses a home holding a
  control character, `"`, `\` or `%` (what would break ssh's quoting or be read as its token),
  as `{:bad_home, home}`.
- `Copies`: rsync splits `-e` on whitespace, and the local shim's path was not quoted.
- The console's attach line, printed for a person to paste, quotes the tmux path and socket.

**Sockets.** Each socket under the home must fit macOS's 103 bytes: `<home>/tmux.sock`,
`<home>/d/<agent>.sock`, `<home>/ws/jobs/<job>.sock`, `<home>/ws/services/<service>.sock`.
Names up to 64 bytes are allowed, and `Holder` already refuses a name that does not fit by
name, `{:socket_path_too_long, path}`, at its start. The tmux socket was the one that would
fail later, at tmux's first command; `Config.new/1` now refuses a home over 93 bytes, `{:bad,
:home, {:longer_than, 93}}`. A home of 42 bytes (`/Users/x/Library/Application
Support/myapp`) leaves an agent's name 53 bytes, a job's id 47 and a service's name 43.

**The model.** No spec changes. `Intake.tla` and `Hold.tla` leave which decision abstract
(allow, deny and ask are one "decision"); a correction is one more decision's body, so the
hold's states, its one response and its deadline are as modeled.

**Tests.** `IntakeToolsTest`: a correction's response and its row; each answer out of shape a
pass with its problem, and 10,000 characters taken. `SurfaceTest` (the example's tree test,
moved): the whole tree now runs under a home named `the home`, with real tmux, dtach, git and
the headless stand-in; a correction through the account's real hook; a config's extension
listed and called on the agents' endpoint. `ToolHomeTest`: a signed commit and a project's
override under a home with a space; `ssh -G` reads the known hosts as one file; the refused
homes. Doctests for `child_spec/1`, `Config.new/1` and `MCP.extensions/3`.

- The test homes on macOS are about 70 bytes (`$TMPDIR/caf-<pid>/t<n>/…`). A first cap that
  left every socket a 32-byte name (a home of at most 53 bytes) refused every test's home. The

## Findings

### new-1. B3 says the example keeps its ends; the ends are wiring every app needs

What happened: B3 says "`caf_example` keeps its config file, its console and its ends, and
loses its supervisor's wiring". `Ends` runs `Services.owner_ended/3` on the cue of an agent
row's end, which the design lists among what the app "still wires that the parts do not
offer".
Why: an app that took the library's tree and not `Ends` would keep an ended delegate's
services running; "The app's surface" says the app wires nothing else.
What I did: moved `Ends` into the tree as `CodingAgentFramework.Ends`, and wrote it into "The
app's surface".
What the design should change: B3's line reads "keeps its config file and its console". Or,
if the example is meant to keep it, the surface needs a way for the app to add a part that
reads cues (`subscribe/2`, B3's rest), and the design says so.

### new-2. A name's room under a long home is found only at its start

What happened: a socket's name may be 64 bytes, and under a 42-byte home an agent's name past
53 bytes, or a service's past 43, is refused only when it starts.
Why: the room depends on the home, and a fixed minimum that left every name 64 bytes would cap
the home at 21 bytes, which no macOS app home fits.
What I did: refused only a home whose tmux socket does not fit, and documented the room a home
leaves.
What the design should change: either the names' cap follows the home (the config answers the
room it leaves, and `delegate` refuses a longer name before any row), or sockets move to a
short directory of their own outside the home (the design keeps all state in the home today).

### new-3. A message's pointer names its file without quotes

What happened: `Mailbox.Transport.pointer/2` types "A message for you is in <path>; read it."
With a space in the home, the agent may read the path wrong.
Why: the text is also the evidence a delivery settles by, so changing it changes what
`Transcripts` matches.
What I did: nothing.
What the design should change: put the path in backticks in the pointer and in the evidence it
is matched by, in one unit with a test of a delivery under a home with a space.
