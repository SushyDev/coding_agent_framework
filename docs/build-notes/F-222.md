# F-222: a restart with an interactive delegate's report taken no longer brings the tree down

## What was built

`Delegates.tell_turns/4` took the state as its first argument and again inside the read's result:
`tell_turns(s, row, agent, {turns, s})`. That clause matched only when the read left the state
unchanged. For an interactive delegate whose report was taken, `ended_own/3` reads `turn_of/3`.
After a restart, that read caches a mark and returns a new state, so no clause matched. Now the
clause takes the read's state and ignores the one before: `tell_turns(_before, row, agent,
{turns, s})`.

A test in `delegates_interactive_test.exs` (the turn after the report) now kills `Delegates`
after the notice, starts it again, cues it, and checks that it lives and told the turn once. The
test failed with the `FunctionClauseError` before the fix, and passed three runs of three after.

## What was measured

Found by the end-to-end rerun on macOS (2026-11-23): the first framework start after an
interactive delegate (demo-unit-notes) reported crashed `Delegates` on every tick. It hit its
restart limit, and the app went down (`:shutdown`). Since F-155. With the fix, the run restarted
twice more with interactive delegates in that state, with no crash.

## Findings

None.
