# F-130: R9 part 2, the turn state, the ledger's rows, one rule for stored terms

R9's second part (`docs/design.md`, "The parts", "A session's life", R9), as F-129's new-1
names it, with F-129's new-2, new-4 and new-5 decided in the brief, and F-113's new-2, F-117's
new-2, F-120's new-2, F-126's new-1, new-2 and new-4, and F-127's new-2 read for it.

## What was built

- **The turn state** (`Sessions.Turn`, a pure module in `caf_sessions`), one function per kind
  of session over the evidence its caller read: `headless/2` from `Stream`'s fold (one read
  decides: the log is ordered and a `result` closes a turn), and `interactive/3` from the
  session file's `status` (`Registry`'s row of the row's process, by pid and start time) and
  whether `Intake` holds the session's waiter. Only the two together are `:ended`; the file
  alone that reads idle is `:idle`, which a write must check again by a reading of its own
  (R8's box check), so one read is never the only sign a turn ended when it decides a write
  (F-113's new-2). The states: `ended`, `idle`, `running`, `waiting`, `ending`, `gone`,
  `not_running`, `unread`. `of/2` picks the function by the row's kind.
  - `Mailbox`'s stream transport marks a row only when `Turn.headless/2` is `:ended` (it read
    the same fields before, by hand). Its waiter transport is unchanged (F-127's new-2: the
    waiter alone, since Claude Code queues into a running turn).
  - `Sessions`' stop finds the session file by `Turn.file/2`. It still sends SIGTERM on the
    file's `idle` alone (new-1).
  - The `Tracker`'s tree reads a delegate's state by `Turn.stream/1` and now gives a main
    session a state too, from its session file in the view (`Turn.file_state/1`), and its
    subagents. The view holds no waiter, so that state is one read, for a person.
- **`Acts` rows** (F-126's new-1 and new-4). `Acts.answered/4` settles a row by a call's
  answer, one rule for every part: ok `verified`, refused `failed` (no act time), unknown
  `unknown`.
  - A session's start and resume: `Sessions` (option `acts:`) writes a row with no state
    (actor `sessions:<host>`, act `start` or `resume`) before the agent row, and settles it when
    the call answers. A row that cannot be written refuses the start `{:acts, answer}`. A
    restart of `Sessions` closes the rows its last life left claimed (`Acts.interrupt/3`).
  - `Delegates`' own resume after a first kill: claimed on the state `%{delegate: id, resumes:
    n}` (actor `delegates:<host>`) before the row counts the resume, settled by `Sessions`'
    answer; a claim not taken resumes nothing, and the next cue tries again.
  - A service's `stop/4` (of a `running` row) and `restart/4`: claimed by the caller on
    `service:<name>` with the running process (pid, start time, restarts), settled by the
    answer. A stop sent again to an `ending` row goes on under the first call's act. A second
    fix of one process is refused `{:claimed, by}` or `{:already_claimed, by}`.
  - A raised error, which this unit takes to be **a part's crash the app sees**: the example
    app watches each part's process (one unlinked watcher per process, which ends with it) and
    records an abnormal exit as act `error`, actor `app`, target `part:<key>`, settled `failed`
    with `Exception.format_exit/1`'s text. A part's `{:unknown, reason}` is not recorded: its
    caller holds it, and the act it belongs to settles `unknown`. A crash of `Acts` itself is
    not recorded in it. `Acts` now starts second in the app's tree, after the reaper, before
    every part that writes to it.
- **`Store.update/4`'s one rule** (F-117's new-2, F-126's new-2): every value goes through
  `Store.text/1` (an atom as its name, any other term as canonical JSON, never `inspect`
  text). `Store.from_inspect/1` (moved from `Acts.Table`) reads an earlier build's `inspect`
  text, and `Store.convert/3` rewrites a table's columns by it in one transaction; it leaves
  JSON and plain text as they are, so a second run changes nothing. `Sessions.Table` converts
  `reason` and `viewer`, `Delegates.Table` `reason`, `Mailbox.Table` `attempt`, on open.
  `Sessions.Table`'s own atom-to-name dump is gone. `Mailbox` compares `attempt` with
  `"no_delivery"` and `"no_waiter"`, the names.
- **The last writer sources** (F-120's new-2): `Stream.Table.meta/0` (its `stream_reads` as
  the reads table) and `Intake.Table.meta/0` (unread until the host's `Intake` started, then
  read now, as every writer's table is) make their sources from `Tracker.TableSource`;
  `StreamSource` and `IntakeSource` are gone. `Reader.open/2` takes the table's `open:`
  options (a column a later build added). `caf_tracker` no longer uses `caf_stream` or
  `caf_intake` outside its tests.
- **`agents()`** (F-129's new-5, decided): the tree leaves out delegates that ended unless
  asked: `Tracker.agents/2` and `Tree.agents/2` take `all: true`, and so does the MCP tool's
  `all` argument. `MCP`'s close reads (`look`, `transcript`) use the whole tree, so an ended
  delegate's transcript can still be read. "Messages" in the design says a message to an
  ended delegate is stored and settled `ended`, and that ended rows are kept.
- **The design and README**: "The parts" (`Store`'s rule, a session's turn, an act's rows and
  which raised errors are recorded), the `agents(all)` row, "Messages", R9 and R10. README's
  Status and "The apps" chart (`caf_tracker` no longer uses `caf_intake`, `caf_stream` or
  `caf_recoveries` outside tests; `caf_sessions`, `caf_delegates` and `caf_services` use
  `caf_acts`).

## What I ran into

- A stale held `can_use_tool` request in a fold that already read its turn's `result` would
  have kept `Mailbox` from ever delivering, had `Turn.stream/1` read `waiting` before `ended`.
  It reads the result first: a turn that ended waits on nothing.
- The tree's entries (`Sessions.Agents.tree/1`) leave out the pid and start time, which a main
  session's file is found by, so `Tree` looks each entry's full row up by host and name.
- `Services` runs each call in the caller's process, so its act is claimed there, after
  `Grants`' check: a claim before the check would let a caller with no right take a state its
  owner then could not fix.

## Findings

### new-1. A stop's SIGTERM still rests on one read of the session file

What happened: `Sessions.stop/3` sends SIGTERM to an interactive session once its session file
reads `idle` (and no `Mailbox` row to it is `sending`). That is the file alone, which
`Sessions.Turn` calls `:idle`, not `:ended`.
Why: a session with no waiter (no `waiter:` in the app, or idle past `Intake`'s waiter
deadline, two hours) would never stop if the stop asked for `:ended`. And the SIGTERM is no
write into a turn: Claude Code ends a running turn at it and keeps its transcript (F-114).
What I did: nothing beyond reading the file through `Turn.file/2`.
What the design should change: say whether a stop's idle read must be `:ended` when the
session has a waiter, or whether one read is enough for a SIGTERM; R8's typed write is where
`:idle` must be checked again either way.

### new-2. Readers still store a problem as `inspect` text

What happened: `Store.update/4` and the writers now store every term by `Store.text/1`. The
readers do not write through it: `Registry`, `Usage`, `TmuxSampler`, `Transcripts` and
`Intake.Table.insert/5` put a problem into their rows as `inspect` text (`":not_json"`).
Why: they write through `Reader.write/3` and their own inserts, which the brief's rule
(`Store.update/4`) does not reach.
What I did: nothing, to keep this unit to its tables.
What the design should change: whether "no `inspect` text in any table" covers the readers'
`problem` columns, and if so, a unit that stores them by `Store.text/1` and converts them on
open (`Store.convert/3` does it in one call per table).

### new-3. An owner's end stops its services with no row in `Acts`

What happened: a service's `stop/4` and `restart/4` are acts now; `owner_ended/3`, which the
app calls when an agent ends, ends that agent's services with no row.
Why: it is the app's consequence of an end already cued, not an agent's fix, and the brief
names a service's restart and stop.
What I did: nothing.
What the design should change: say whether an end that follows an owner's end is an act of
its own (actor `app`, the owner's end as its state).
