# F-266: leases and jobs through the facade

## What was built

This unit builds item 1 of the brief only: the reads. The whole brief was estimated at well over
500 changed lines apart from the model and the tests. The reads were about 120; the job under a
`:landing` lease was about 250, because it needs a run in the worktree, a copy that carries
`deps` and `_build`, and a runner that answers the id at once; the stop was about 150; and the
docs about 80. So, as the brief says, the job, its stop and their model go in a unit of their
own (new-2, new-3).

- `CodingAgentFramework.holds(instance, opts)` in `caf_surface`. It answers what holds the
  machine in one call: the unreleased leases, oldest first, then the last `ended:` released ones,
  newest first (0 to 200, default 20); for a job's lease, the job's command, worktree, copy path,
  log path, state, exit code and refusal reason; the first 200 copies with their paths and turns;
  each resource's capacity and held units; and the pressure. It is one call because a panel
  shows these together and the pressure lives only in the `Scheduler`'s process. The leases
  (`caf.db`), the jobs (`parts/jobs/jobs.db`) and the copies (`parts/copies/copies.db`) are each
  read once, read-only, by `Store.read_only/4`, leases first. The pressure comes from
  `Scheduler.pressure/2` on the running tree's part. A copy's path and a job's log path are
  computed from the host's directory as `Copies.place/1` and `Copies.Held.context/3` compute them;
  the test checks that the log path is the file the job writes.
- `jobs.argv`: a job's row keeps its command, as JSON, written with the `asked` row. The brief
  asks for each job's command, and no table kept it. A file made before this unit gains the
  column, as earlier columns were added.
- `Scheduler.Table.released/2` (the last `n` released leases, newest first) and
  `Copies.Table.first/2` (the first `n` copies without `sent`), so each read is bounded in SQL.

No model changed: the reads are one read of each table, with no protocol over time.

## Tests

`surface_test.exs`, "holds reads two leases with their jobs, the copies and the pressure": an
agentless tree runs two heavy jobs in two copies, each held until the test writes a gate file.
While both run, `holds/1` shows two unreleased leases, each with its job `running`, its command,
its copy and a log path whose file says the job started. It also shows `slot` with 2 of 2 held,
both copies with their paths on disk, and the pressure. After the gate, `holds(ended: 1)` shows
only the newest released lease, released by the monitor, with its job `exited 0`, and no slot
held. An `ended:` out of range and an unknown instance are refused.

## Measured

The test runs in about 6 s alone, at a load average of 55 on 15 cores.

## Findings

### new-1. A heavy command's lease keeps no command and no log

What happened: the brief asks that a `caf-run` lease show its command, its log path and when it
ended. The lease row keeps the class, the agent (`module`), the tool call's id (`request_id`
`run:<id>`), the holder `{"run", "<pid> <start>"}` and `released_at`. The wrapper sends the
intake's plug only the class, the id, the agent, the pid and the start. The command's output
goes to Claude Code's own background output file, which the framework does not know. Why: F-171
made the lease the run's only row ("no table: the lease is the row"). What I did: `holds/2`
shows a run's lease with its agent, tool call id, process and release time, and nothing else.
What the design should change: either the wrapper sends its command with the ask and the lease
keeps it (a column the plug writes, bounded in length), or the panel names the tool call, whose
command and output the agent's transcript already holds (`conversation/3`'s `tool_call` entry
has the input and the result). The second keeps no second copy.

### new-2. A job runs only in a copy that carries no ignored files

What happened: item 2 asks for a landing job that runs either in the worktree itself or in a
copy that carries `deps` and `_build`. `Jobs.run/6` always runs in a copy that `Copies.sync/5`
fills with the files git does not ignore, so `deps` and `_build` are never sent, and there is no
run in the worktree. Why: "Hosts" decides that every job runs in a copy, so build outputs stay
apart from an agent's edits. What I did: nothing; it is the next unit. What the design should
change: say whether a run in the worktree is allowed (it breaks "build outputs stay apart" on
the workstation), and, for a copy, name the ignored paths a sync carries (`carry: ["deps",
"_build"]`) and whether a later sync deletes what the worktree removed from them.

### new-3. A job answered at once needs a process that owns its run

What happened: item 2 asks that the facade answer the job's id at once, and the end later.
`Jobs.run/6` works in its caller's process: it waits for a queued lease, holds the job and waits
for its end there, and `Jobs` watches that caller. Why: the caller owns the run, so a caller's
end settles the row. What I did: nothing. What the design should change: name who owns the run
when the app does not wait, such as a task supervisor in the tree, or `Jobs` itself, and what a
restart does to it. The stop (item 3) needs a state recorded before it acts, `stopping`, in
`Jobs.Table` and in `Copy.tla`'s and `Schedule.tla`'s `work`, so the lease stays live until the
end is written.
