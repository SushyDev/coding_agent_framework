# F-108: what an app built on the framework needs

A design unit: `docs/design.md` only. No code changes.

## What was decided

An app to be built on the framework listed its gaps, assessed at F-104. The person decided four
that reverse earlier decisions:

- **Several main sessions per project**, each named by the app (one per epic, say), sharing the
  project's checkout. `start_main` takes a name; a name in use is refused. (Was: one per project.)
- **Interactive delegates**: a start option, `interactive: true`, runs a delegate like a main
  session, attachable, with `Screen`-checked writes. Headless stays the default. (Was: delegates
  are headless.)
- **One package**: developed as the umbrella, used as one `coding_agent_framework` package, by
  git tag first and Hex later.
- **Programs looked up or given**: `Programs` takes paths given (devenv, for the framework's own
  development) or looked up on `PATH`, each checked against its supported versions at start.
  (Was: every tool from devenv.)

The rest of the list is taken as asked, as items 10 to 16 of the order of units: an operator
principal; launch options per agent; PreToolUse and PostToolUse hooks and a permission policy;
`Screen`, delivery, interactive delegates, `Mains` and `Mover`; packaging, the toolchain floor, a
library supervisor and accounts; what the app reads and drives; `Stacks`, LiveView and Ghostty.
"Concepts" gains **operator**.
