# F-54: the design takes F-51's and F-52's findings

## What was built

`docs/design.md` only:

- "Rules learned", viewers: a lost viewer is reopened with the command of the part that holds
  its program, never a plain `dtach -a`. `Recoveries` asks `Sessions`, and a socket with no row
  ends `failed{no_session}`. When `Services` is built, the sampler's held row names a socket's
  owner, and `Recoveries` asks that part (F-52 new-1).
- "State that never lags or lies", total folds: a load fills a field a newer build added with
  its default and answers an unknown field as a problem, so a row an earlier build wrote is never
  taken for a new one (F-51 new-9).
- "Rules learned", tests: a test of what a viewer runs reads the pane's start command from its
  own tmux server (F-52 new-5).

F-51 new-7 (the caller's word on the report until `Delegates`) is already in "Ending", from
F-51 itself.

## Left as they are

- F-52 new-2: `Recoveries`' `holder:` now only checks the host. It stays until a part answers
  its host another way; nothing else needs it changed.
- F-52 new-4: a viewer's command waits behind a start in `Sessions`' mailbox. Decided only if a
  start's steps prove slow on a real host.
- F-52 new-3: `HeadlessStandIn.kill_all/1` fails when nothing started. A code fix, its own small
  unit.
- `Stream.Table`'s load, which takes a stored fold with other keys as new, changes to the rule
  above in its own unit.
