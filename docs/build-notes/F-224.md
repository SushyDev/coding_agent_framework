# F-224: the store's busy bound has a slack that holds on a loaded host

## What was built

The store's bound tests allow 500 ms past `Store.busy_bound/0`, up from 100 ms. `Store`'s doc
and the design's `Store` row now say the same. The code is unchanged: it already clips its last
sleep to the time left (`min(sleep, left)`).

## What was measured

On 2026-11-23, with three gate runs and a live end-to-end run on one machine, the F-216 tests
failed three times: answers at 2,168 ms against a 2,100 ms limit, in `store_test.exs`'s
"write and open against a held lock…" and "a transaction against a held lock raises Busy…". The
overshoot is the last try's own run plus the scheduler. The deadline itself holds. The calls over
a store write have a 5 s timeout, and two writes at 2.5 s each still fit under it.

## Findings

None.
