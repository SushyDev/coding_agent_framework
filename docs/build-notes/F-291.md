# F-291: a host's programs are found on the PATH they run with

## What was built

F-280's lookup of a remote host's programs ran with the `PATH` ssh gives a non-interactive shell.
On a Mac that `PATH` lacks `/opt/homebrew/bin`, where `flock`, `dtach` and a new rsync are put, so
a placement there was refused `{:no_program, host, [...]}` though the programs were installed and
the entry's `env` named their `PATH` (F-280's finding new-4).

- `Programs.find/3` takes `path:`. The lookup then sets that `PATH` before it looks. The `PATH`
  goes to the shell as an argument, never inside the script's text.
- `Hosts` passes the entry's `env` `PATH` when the entry names one. Without one, nothing changes.

## Tests

- `programs_builtin_test.exs`: a program in a directory whose name has a space is not found on the
  shell's own `PATH`, and is found with `path:` naming that directory.
- `hosts_test.exs`: with `dtach` and `flock` only in another directory, a host whose entry names no
  `PATH` is refused naming both, and the same host with `env: [{"PATH", ...}]` is placed, and its
  `dtach` is the one in that directory.

## Findings

### new-1. The operator's `~/.zshenv` workaround is no longer needed

With the entry's `env` `PATH` set, the Mac's shell startup files need not name Homebrew's
directory.
