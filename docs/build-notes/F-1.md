# F-1: the skeleton and `Agent.tla`

## What was built

- **The Mix project** `coding_agent_framework`: an OTP library with no application callback and
  no processes, `lib/coding_agent_framework.ex` with its moduledoc, `.formatter.exs` and
  `.gitignore` (which ignores `_build/` and `.claude/worktrees/`).
- **devenv**: Erlang/OTP 29 and Elixir 1.20.5 from nixpkgs-unstable, tmux 3.8, dtach 0.9,
  Claude Code 2.1.322 (the one unfree package permitted), git, gh, and TLA+ 1.8 (`tlaplus18`,
  TLC 2.18) on `jdk21_headless`.
- **`bin/check-model [all | slow | <configuration>]`**: runs TLC on `model/tla/*.cfg` (the fast
  ones) or `model/tla/slow/*.cfg` (by hand), prints each configuration's states, depth and
  seconds, and passes a `Break_*` configuration only when TLC exits 12 or 13 and reports a
  violation. Any other result fails it.
- **`model/tla/Agent.tla`**: one host's tmux server, panes with tags, dtach sockets, held
  Claude Code processes, viewers, the sampler and the writes. One action per event:
  `ServerDies`, `ServerRestarts`, `AgentStarted`, `AgentExits`, `SocketGoesStale`,
  `ViewerDies`, `SamplerReads`, `ViewerReopened`, `ViewerReopenRefused`, `PaneLookedUp`,
  `WriteAsked`, and `WriteSent` (only under `CheckThenSend`). Its header names `Tmux`,
  `Holder`, `Control` and `TmuxSampler`, and what it leaves abstract.
- **`model/tla/READING.md`**: TLA+ for an Elixir reader.
- **`test/model/check_model_test.exs`**: runs `bin/check-model all`, tagged `:model`, in the
  default `mix test`.

## The model

Invariants: `WriteReachesItsSession`, `OldPaneIdNeverReachesAnother`, `OneProcessPerSocket`,
`TypeOK`. Action property: `AgentOutlivesServer`. Liveness: `LostViewerReopened`,
`UnviewedAgentSeen`.

Each `Break` value removes one guard, and its configuration fails as it must:

| Configuration | Removes | TLC reports |
|---|---|---|
| `Break_Agent_NoPaneCheck` | the tag check on a write | `OldPaneIdNeverReachesAnother` |
| `Break_Agent_CheckThenSend` | the check and send as one tmux command | `OldPaneIdNeverReachesAnother` |
| `Break_Agent_CleanLiveSocket` | refusing to remove a live socket file | `OneProcessPerSocket` |
| `Break_Agent_TmuxHoldsAgent` | dtach: the agent runs in its pane | `AgentOutlivesServer` |
| `Break_Agent_NoReopen` | reopening a lost viewer | `LostViewerReopened` |
| `Break_Agent_SamplerReadsPanesOnly` | the sampler reading held sockets | `UnviewedAgentSeen` |

## Measured

`bin/check-model all` on this laptop (15 cores, TLC `-workers auto`), wall seconds per
configuration including the JVM's start:

| Configuration | Bounds (starts, server deaths, viewer deaths, writes) | Distinct states | Depth | Seconds |
|---|---|---|---|---|
| `Agent_Writes` | 3, 1, 1, 2; safety only | 918,317 | 26 | 12 |
| `Agent_Viewers` | 2, 1, 1, 1; safety and liveness | 71,946 | 20 | 17 |
| `Break_Agent_CheckThenSend` | 2, 1, 0, 1 | 6,376 | 13 | 3 |
| `Break_Agent_CleanLiveSocket` | 2, 0, 0, 0 | 104 | 8 | 2 |
| `Break_Agent_NoPaneCheck` | 2, 1, 0, 1 | 5,714 | 13 | 3 |
| `Break_Agent_NoReopen` | 1, 0, 0, 0 | 12 | 4 | 3 |
| `Break_Agent_SamplerReadsPanesOnly` | 1, 0, 1, 0 | 6 | 3 | 2 |
| `Break_Agent_TmuxHoldsAgent` | 1, 1, 0, 0 | 46 | 6 | 3 |
| `slow/Agent_Restarts` (by hand) | 3, 2, 1, 2; safety and liveness | 6,690,622 | 31 | 1,115 |

A second run of `bin/check-model all`, after the slow run had ended, took 10 s for
`Agent_Viewers`, 6 s for `Agent_Writes` and 1 to 2 s for each break; `mix test` ran it in 26 s.
A break's state count changes from run to run: TLC's parallel workers stop at whichever
counterexample one finds first.

The first design configuration, with liveness at bounds 3, 1, 1, 2, took 122 s: liveness
checking, not the state count, set its time (the same 918,317 states take 12 s for safety
alone). So the gate splits it into `Agent_Writes` (safety at the larger bounds) and
`Agent_Viewers` (liveness at smaller ones), and the larger liveness run is `slow/`.

## What I ran into

- TLC's parse error (exit 150) on `-1` with only `Naturals` extended; the spec extends
  `Integers`. `bin/check-model` reported it as a failure, as it should.
- No invariant of the design failed while writing the spec. The two write breaks find the same
  scenario in 11 steps: an agent's viewer is `%0`, a caller keeps `%0`, the server dies and
  restarts, the other agent's viewer opens first and takes `%0`, and the write lands there.

## Findings

### new-1. The pane check and the send must be one tmux command

What happened: `Break_Agent_CheckThenSend` checks the pane's tag in one step and sends in the
next, as a writer does when it reads `list-panes` and then runs `send-keys`. TLC finds the
server dying and restarting between the two, another agent's viewer taking the checked id, and
the send reaching it.

Why: pane ids restart at `%0` with the server, and the agents outlive it, so the window between
a check and a send is exactly the window the check is meant to close.

What I did: the design in the spec checks and sends in one tmux command, so tmux checks the very
pane it sends to; a server that dies in between fails the command and sends nothing. A tmux
command list such as `if-shell -F -t <pane> '#{==:#{@<tag option>},<session>}' 'send-keys …'`
does this without a shell; unit 2 should confirm it on tmux 3.8 with a contract test.

What the design should change: "Writes to panes" should say the check runs in the same tmux
command as the send. The check "or the session's process in the pane" cannot run inside tmux,
so the design should also say every pane the framework writes to is tagged as it opens, and an
untagged pane is refused rather than checked by process.

### new-2. The empty-target refusal cannot fail on its own

What happened: with the check and send in one command, a break that lets an empty target
through (tmux reads it as its current pane) finds no violation: the tag check refuses any pane
but the session's own. Run by hand on a scratch copy of the spec at `Agent_Writes`'s bounds:
1,011,102 distinct states, 12 s, no error. So it has no `Break_*` configuration.

Why: the check reads the tag of the pane tmux resolved, so a wrong target, empty or not, is
refused there.

What I did: the spec keeps the refusal as a guard, since it costs nothing and gives the write a
named reason, and its comment says what it adds.

What the design should change: nothing in the rule, but the model rule "every guard has a
`Break_*` configuration" meets guards that are defense in depth. Either a guard that cannot fail
alone is named as such in the spec's header, or its `Break_*` removes it together with the guard
it backs up.

### new-3. The sampler must read the held sockets, not only the panes

What happened: `Break_Agent_SamplerReadsPanesOnly` breaks `UnviewedAgentSeen` in 3 steps: a
held agent that never had a viewer, or whose viewer died, has no pane, so a sampler of panes
never sees it.

Why: the design's table gives `TmuxSampler` the job "samples each server's panes", and
`Holder` the list of a socket's children; neither part's job sees a held agent with no pane.

What I did: the spec's sampler reads the held sockets and the panes together.

What the design should change: say which part joins `Holder`'s sockets with the panes to report
"held, no viewer": `TmuxSampler` reading both, or the `Tracker` folding both readers.

### new-4. A lost viewer is reopened only if something restarts the server

What happened: `LostViewerReopened` holds only with fairness on `ServerRestarts`: the framework
starts its tmux server again after it dies. Without that fairness, a behavior in which the
server stays down is allowed, and in it a viewer lost with the server is never reopened (by
construction; not run as its own configuration).

Why: viewers live on the server; after a server death every held agent is unviewed until a
server runs again.

What the design should change: name the part that restarts a host's tmux server after it dies
(the host supervisor or `Tmux`), so `Agent.tla`'s fairness has an owner in the code.
