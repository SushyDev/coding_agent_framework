# F-53: headless delegates, from F-49's findings (design)

## What was built

Design only, no code. "Headless delegates" and the **dtach** rules take F-49's findings:

- A delegate's pid is the one its wrapper writes to `pid` before `exec`, read after the init
  names the session id (new-1).
- Two things are checked against each pinned release: whether `-p` writes a session file, and
  whether the init comes before the first line is read; if not, the brief goes in right after
  the hold (new-1, new-2).
- A stop is done when the pid is gone and the socket has ended; a resume before that is refused
  (new-4).
- The viewer runs the command `Sessions` answers for the row, and waits for a log not yet there
  (new-5, new-7).
- The stream directory is named by the session id (new-8).

new-3 and new-6 (a resume and the end in `Stream.tla`) are F-51; new-5's code is F-52.
