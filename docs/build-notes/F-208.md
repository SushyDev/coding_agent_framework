# F-208: a warning in test code fails the gates

## What was built

`gate-compile` compiles the test build too (`MIX_ENV=test mix compile --warnings-as-errors`),
which covers each app's `test/support` and the stand-ins, and `gate-test` runs
`mix test --warnings-as-errors`, which covers the test files themselves. `CLAUDE.md`'s gates say
so.

## Why

An app that embeds the framework now runs the framework's tests with warnings as errors in its
own gate. A warning in the framework's test code would pass the framework's gates and fail the
app's. The gates should be the stricter of the two, never the looser.

## What was measured

Before the change, on `main` at 31e58c4: `MIX_ENV=test mix compile --warnings-as-errors` exits 0,
and the four logs of F-202's full gate (one `devenv test`, three `gate-test`) hold no compiler
warning. So the change fails nothing today; it keeps it that way.
