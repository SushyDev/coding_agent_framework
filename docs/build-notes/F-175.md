# F-175: the whole tree under a home whose path has a space

An embedding app had reported the tree refusing a home under `~/Library/Application
Support/<app>/framework`. That note predates F-169, so the test came first.

## What was built

A test in `apps/caf_surface/test/surface_test.exs`, "the whole tree runs under a home whose path
has a space (F-175)": it starts the tree with `CodingAgentFramework.child_spec/1`, reads the
project's checkout, starts a delegate through MCP with the headless stand-in, and reads its
delegate row, its session row and the tree. The surface suite's home is now
`<dir>/Application Support/app/framework`, so every test there runs under a path with a space in
the middle.

## What was measured

The test passed with no change to any library code, and so did the whole surface suite on that
home. Nothing refused: the checks, the shell lines, the tmux and dtach arguments, the hook
commands and the MCP config paths already hold a space (F-169). No code was changed.

## What I ran into

A main session started through the whole tree (`Operator.start_main`) answers `{:unknown,
:no_session_file}` with the headless stand-in, with or without a space (checked with a home
without one, and with the stand-in writing its session file at the start). A main session is a
dialog on a screen, which the screen stand-in plays; but that one writes no session file for
delegates, and a tree has one `claude`. So the test starts a delegate and reads the declared main
as its parent; a started main under a space home is not covered at the tree level.

## Findings

### new-1. No stand-in plays both a main session's dialog and a delegate's session file
What happened: `start_main` in the whole tree is unconfirmed with the headless stand-in; a screen
stand-in as the tree's `claude` leaves a delegate's start to time out. Why: the headless one has
no dialog, the screen one writes no session file, and `Config` takes one `claude`. What I did:
tested the delegate and the declared main only. The design should change: one stand-in that plays
the dialog and writes the session file on a message, so a surface test starts a main too.
