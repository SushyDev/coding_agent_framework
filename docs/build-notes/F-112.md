# F-112: what F-109 and F-110 found, folded into the design

A design-only unit: no code changes.

## What changed in `docs/design.md`

- **Agents working together.** A paragraph on the operator (F-109's new-1, new-2, new-3). No
  agent messages the operator; an agent reaches a person through `ask`. A reply to the
  operator's message, or the notice in its place, is kept for the app, which reads it by the
  message's id. The operator's `run_delegate` hands the report to the operator. The main
  session sees both in the log.
- **Who may act.** A delegate's launch is at most its parent's (F-110's new-4, decided by the
  person running the project: "narrow only"). Through the agent tools a start may add deny
  rules and disallowed tools; anything wider is refused with `{:wider_than_parent, what}`. The
  app's own code starts an agent with any launch.
- **Rules learned.**
  - An agent's settings are one merged file (new-1).
  - The per-release check covers which settings a launch reads, the file form of
    `--append-system-prompt`, and how tool patterns split (new-1, new-2, new-3).
  - The appended prompt is fixed at the first start (new-5).
  - An app may set `CLAUDE_CODE_*` names on purpose; only the framework's own are refused
    (new-6).
  - A `Stop` hook cannot deliver to an idle main session, so delivery stays with `Screen`
    (F-107's new-1).
- **Order of units.**
  - Item 10 gains the operator's replies and its `run_delegate` report.
  - Item 11 gains the narrow-only check.
  - Item 13's `Mains` notes a main session's kept services (F-109's new-4).

F-110's new-7 needed no change.
