## What was built

- **`Mailbox`'s hand-on in a task** (F-132's new-2). The stream's `Stream.write`, the waiter's
  `Intake.deliver` and the typed write's `Inlet.type` run in a linked `Task`; the answer comes
  back as a message and is written as before (refused undoes the mark, sent or unknown starts
  the take bound). The row is `sending` meanwhile, and the settle skips a row whose hand-on is
  in flight, as `Delivery.tla`'s `hand` already does (`i \notin hand`), so the model did not
  change. One row in flight per addressee and the order hold, since the row is marked before
  the task starts. An answer that kept the mark is settled at once; a refusal waits for the
  next cue, as before, so a refused row is not marked again in a loop. A raise, throw or exit
  in the hand-on is an unknown answer. The reads before a mark (the transcript's offset, the
  turn) stay in the process, each bounded at 5 s.
- **Readers store a problem by `Store.text/1`** (F-130's new-2): `Registry` (`not_json` for
  `:not_json`), `Usage`, `TmuxSampler` (a failed sample's problem and a malformed entry's
  row) and `Intake.Table.insert/5`. `Transcripts` already stored plain words (`no_file`,
  `rewritten`), which are `Store.text/1`'s. A reader's table metadata may name `convert:`
  columns, which `Reader.open/2` converts at each open; `Intake.Table.open/1` converts its own.
  `Store.convert/3` finds rows by `rowid`, so a reads table keyed by its scope converts too.
- **An owner's end that ends its services is an `Acts` row** (F-130's new-3): actor `app`, act
  `service_stop`, target `service:<name>`, and as its state the service's process (pid, start
  time, restarts) with `owner_ended: owner`, so it never takes the claim of the owner's own
  stop of the same process. A kept service handed to the parent is no end, and writes no row.
  An end sent again (the row `ending`) goes on under the first claim, as `stop/4`'s does.
- **The model on the agent row** (F-133's new-3): a `model` column on `agents`, added to an
  older file. A start writes its launch's model; a resume whose launch names none takes the
  row's, as it takes `options`. `Mover`'s `launch:` no longer needs a model, so a moved main
  session keeps the model it started with.
- **Indexed reads** (F-126's new-5, F-129's new-5). `Acts.rows/3` takes `since: at` (claimed,
  acted, ended or cleared at `at` or later) and `nil` as `IS NULL`; `acts` gains `acts_open`
  `(actor, status)`, `acts_reason` `(actor, reason)` and `acts_target` `(actor, target,
  claimed_at)`. A `Recoveries` check reads its `acted` rows, its uncleared `repeating` rows, the
  rows of the sockets the sample reads lost since the window's start or the time their sample
  row took its status (whichever is earlier), and per end owed that socket's ends. An open or a
  clear before both changes no state's key (`lost_viewers/2` takes the later of the row's time
  and the open) and no count (`losses/3` counts within the window). `agents` gains indexes by
  status, cwd, parent and move; `Sessions.Agents.children/3` and `Mover`'s moves under way
  read by query, not by filtering every row.
- **The design** records F-133's new-5 (a move's state: the process's pid, start time and
  account, and the count of its moves ended) and new-8 ("no new deliveries" is no row that
  would start a turn; a waiting call still takes its answer) as decided; "Delivery" says the
  hand-on never blocks `Mailbox`; the agent row keeps the model; the order of the units names

## Findings

### new-1. A `Recoveries` check still reads every row of a socket lost for long

What happened: the rows of a lost socket are read from the earlier of the window's start and
the time the sampler's row took its status. A socket that stays lost (a viewer that fails to
open, never cleared) keeps an old `written_at`, so its every row since then is read at each
check.
Why: an open or a clear after that time changes the state's key, so it must be read; the
reader cannot tell which rows are opens without reading them.
What I did: nothing more; the read is by the `acts_target` index and by that socket only.
What the design should change: nothing unless such a socket is common; then `Recoveries` keeps
its last open per socket as a row of its own (or `Acts` answers the newest open of a target).
