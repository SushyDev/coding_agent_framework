# F-4: agents working together (design)

## What was built

Design only, no code. `docs/design.md` gains:

- "Agents working together": any agent of a project can message the others, look at them, fix
  one that is stuck, and start, use and fix services, through one set of tools. The tools are
  strict in how they act (named targets, the owning part acts, explicit outcomes, the caller's
  identity fixed at launch, every call logged) and loose in what (any agent, any service, any
  program within the project).
- Three parts: `Mailbox`, `Services` and `Grants`. `MCP` lists the tools.
- Two words: service and claim.
- A fifth spec, `Team.tla`, before `Stack.tla`, and its place in the order of units.

## Decisions taken here, open to review

- Scope is the project: any agent may act on any agent or service of its own project, and on
  nothing outside it.
- A fix takes a claim on the target's current state; a second fixer of the same state is
  refused. This reuses the "act once per state" rule of `Recoveries`.
- No agent stops or moves a parent, and no agent fixes itself.
- A message goes in only when the target's turn has ended, like any write, and a message to an
  ended delegate goes to its parent.
- A service ends with its owner unless it was kept or handed on.
