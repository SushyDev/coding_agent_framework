# F-275: Remote Control only for main sessions, never a delegate, and a main's title

## What was built

- **Remote Control follows the kind, not the role.** `ClaudeCLI.session/3` takes `kind:`
  (`:main` or `:delegate`). By default it is `:main` for role `:parent` and `:delegate` for role
  `:delegate`. A role `:delegate` with kind `:main` is refused `{:bad, :kind}`. Only kind
  `:main` gets `--remote-control`. The settings file is the kind's: the account's
  `parent.settings.json` (`remoteControlAtStartup: true`) for a main, and
  `delegate.settings.json` (`false`) for every delegate.
- `Sessions` gives the launch's kind to `ClaudeCLI`, and writes a delegate's overlay
  (`Accounts.overlay/5`) over the delegate's file, so an interactive delegate's overlay says
  `remoteControlAtStartup: false` too. `Accounts.overlay/5`'s second argument now names the
  base file (`:parent` or `:delegate`), not a role.
- **A main's title.** `Mains.start_main/5` and `Mains.resume_main/3` take `title:`. It is checked
  by `ClaudeCLI.title/1` in `Mains` before any start row, refused `{:bad, :title}`. It travels
  to `Sessions` in the launch, is kept on the agent row (new column `agents.title`), and
  `ClaudeCLI` gives it to `--name` and `--remote-control` in the agent name's place. With no
  title the agent name is used, as before. A start or resume that names no title keeps the
  row's, as `meta:` does, so an app changes a stopped main's title by naming it at the next
  resume, and a recovery's resume keeps it. A title on a delegate is refused `{:bad, :title}`.
- A title is a launch word as the others are (`word?`: not empty, no leading hyphen, no control
  character, so no newline), valid UTF-8, at most 120 bytes. Spaces and inner hyphens are fine.
  It is one argv element, so no shell splits it. Locally the hold execs the list. Over ssh
  `Shell.shell_quote/1` puts every word in single quotes, a `'` written as `'\''`.
- `Mains` now declares `caf_cli` for `ClaudeCLI.title/1`.
- The design (Remote Control rule, the Delegate definition), `ClaudeCLI`'s, `Accounts`'s,
  `Sessions`', `Sessions.Table`'s and `Delegates`' docs, and the README status say this.

## What finds a session by its `--name`

One thing: `Sessions`' confirm of an interactive start reads the account's session files
(`Registry`) and takes the live one whose `name` equals the row's. Claude Code writes the
`--name` value there, so with a title the file carries the title. The confirm now compares
with the name the launch gave: `row.title || row.name`. Nothing else looks a session up by it.
`Turn.file/2` (the end reading, `Mailbox`, `Delegates`) matches by pid and start time. Mailbox,
`look`, resume and the MCP tools go by the agent row's name. Remote Control's own list is
Claude Code's and only shows the title. The screen's rule draws the `--name` value, and
`Screen` reads nothing from it.

## What role still decides

Role `:parent` against `:delegate` still decides how the session runs: Claude Code's terminal
interface or headless `-p` with stream-json. With that come the launch transport (the prompt
file read into the last argument), the viewer pane and screen reads, the startup dialogs, the
waiter hook, `--add-dir` for the due directory, the release read, and `Turn`'s readings. Kind
now decides Remote Control, the settings base file, the permission mode's slot (`main` or
`interactive`), the delegate's overlay defaults, and the tree. Role and kind are not one thing:
an interactive delegate is role `:parent`, kind `:delegate`. Naming role by what it is
(`:interactive` and `:headless`) would read better; see new-2.

  `:delegate`) has no `--remote-control` and the delegate's settings file, or its own overlay; a

  gives the agent name; an empty, multi-line, leading-hyphen, too long or non-string title is
  refused, and a title on a delegate too. The headless test is as before.
- `apps/caf_delegates/test/delegates_interactive_test.exs`: an interactive delegate's real launch
  has no `--remote-control`, and its overlay says `remoteControlAtStartup: false`.
- `apps/caf_mains/test/mains_test.exs`, "a main's title goes to both flags…": a bad title is
  refused before any start row or agent row; a titled start launches with it in both flags, is
  confirmed by the session file that carries it, and keeps it on its row; a resume with none
  keeps it; a resume with a new one changes it; a main without a title launches under its name.

## Findings

### new-1. The start's confirm still matches a session file by its `--name`

What happened: an interactive start is confirmed by the live session file whose `name` is the
row's. With a title, Claude Code writes the title there, so two mains on one account with the
same title would confirm by each other's file.

Why: dtach does not report the pid, so the confirm found the process by name. But
`Holder.Process` now writes the held program's record (pid and start time) before it execs,
which `Turn.file/2` already matches by.

What I did: the confirm compares with the launched name (`title || name`). I did not change the
mechanism.

What the design should change: confirm an interactive start by the hold's record (pid and start
time), as the other readers do, so `--name` is display only. Until then, an app gives its mains
distinct titles on one account.

### new-2. Role names how a session runs, but is spelled as a place in the tree

What happened: role `:parent` means "Claude Code's terminal interface" and is given to
interactive delegates, which are not parents. Remote Control was decided by role and so went to
every interactive delegate.

What I did: Remote Control now follows kind. The role's values are left as they are.

What the design should change: rename role to `:interactive` and `:headless` (the row's `role`
column and `ClaudeCLI.session/3`), and the account's `parent.settings.json` to
`main.settings.json`, so neither reads as a place in the tree. They should not become one field:
kind and role vary on their own (an interactive delegate).
