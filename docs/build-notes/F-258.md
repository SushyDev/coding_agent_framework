# F-258: the operator interrupts a main session's turn

## Why

`Operator.interrupt(mcp, main)` answered `{:refused, {:not_built, :main_fix}}`. A delegate's fix
goes through its parent, and a main session has none. Only `resume` and `answer` had a main
session's path through `Mains`, so an app's "stop this turn" button on a main session could not
work.

## What was built

- **The model.** `Team.tla` already modeled the operator's interrupt of a main session: `Kinds`
  holds `interrupt` for any target, `MayFix` grants the operator any agent, and an interrupt
  needs a stuck turn (`Needs`). `Team_OperatorClaims` checks it. What was missing was a
  property that names the interrupt, so a wrong grant fails on an interrupt and not on some other
  fix. Added:
  - `MainInterruptedByOperatorOnly`: every claim of an interrupt on a main session is the
    operator's. `MainFixedByOperatorOnly` implies it.
  - `Break_Team_MainInterruptsMain.cfg` (Break `FixMain`, two projects with main sessions only):
    TLC's trace ends with `p` interrupted by `q`.
  - `Break_Team_MainInterruptsSelf.cfg` (Break `SelfFix`, same projects): the trace ends with
    `p` interrupting itself.
  - `Team_OperatorClaims.cfg` checks the new invariant too, and passes. The header names `Mains`'
    fixes.
- **`Mains.interrupt/3`**, beside `resume_main/3` and `answer/5`. Options `state:` (the claimed
  state) and `timeout:` (the press's bound, 30 000 ms by default).
  - Inside `Mains`, one call checks: `inlet:` given (`:no_inlet`), the name is a main session,
    the claimed state is still the session's (`{:moved, now}`), and its agent row is `running`
    (`:gone`). It answers the `Inlet` and the session's `release`.
  - The press is `Inlet.interrupt/3`, run in the caller's process, so a press of up to its bound
    does not hold `Mains`' other calls. An interactive delegate's press runs inside `Delegates`;
    this one does not need to, since `Mains` keeps nothing about the press.
  - It answers the Inlet's answer unchanged: `{:ok, :sent}` once the screen no longer shows the
    turn running, `{:unknown, {:still_running, reading}}` or `{:unknown, {:escape, reason}}`.
    With no turn running it is `{:refused, {:screen, reading}}`, the same as an interactive
    delegate's interrupt, since both go through the same Inlet call.
- **`Mains.fix_state/3` takes `fix: :interrupt`**, which adds `offset`, the newest hook event
  `Intake` stored for the session (nil without `intake:`), as an interactive delegate's state
  has. Without it, a main session's state (status, session id, pid, start time, held) stays the
  same from turn to turn. The first interrupt's settled claim would then refuse every later
  interrupt of that process as already claimed (`Acts.claim/6`). Only the interrupt's state has
  it: `MCP` reads it with `fix: :interrupt`, and `Mains.interrupt/3` checks the claim against
  it. The state `answer` and `resume` claim and check is unchanged from `main`, so a hook event
  between their read and their act does not refuse them as moved. A main session writes many.
- **`Mains.fix_check(:interrupt, state)`** refuses `:gone` unless the status is `running`, as
  `Delegates.fix_check/2` refuses an interrupt of a gone process. It is checked before the
  claim, so a declared or stopped main session takes no claim.
- **`MCP`'s `fixer/4`** sends the operator's `interrupt` of a main session to `Mains`, as it
  does `resume` and `answer`. The claim in `Acts` is written before the act, by the same
  `act/5` every fix goes through. A stop of a main session is still `{:not_built, :main_fix}`: a
  main session ends by `end_main`.
- **Wiring**: `caf_mains` depends on `caf_inlet`; the surface gives `Mains` the host's `inlet:`.
- `Operator.interrupt/2`'s doc, `MCP`'s moduledoc, the design's "Main sessions" and the README
  status line say so.

## Tests

- `mains_test.exs`, "the operator's interrupt of a main session ends its running turn": the
  screen stand-in started with `--screen running` (through a wrapper, with no trust dialog,
  since past one the stand-in goes idle). A declared main session is refused `:gone`. A state
  that is not the session's is refused `{:moved, state}` and presses nothing. The claimed state
  gives `{:ok, :sent}`, and the stand-in wrote `interrupted`. A second interrupt finds no turn:
  `{:refused, {:screen, %{state: :idle}}}`.
- `mains_test.exs`, "a main session's answer is taken though a hook event came after its
  read": with a real `Intake`, a held `PermissionRequest`, then a `Notification` for the same
  session. The interrupt's state moved (its `offset` grew), the answer's did not, and
  `Mains.answer/5` on the state read before the event answers `{:ok, :sent}`.
- `surface_test.exs`: the operator's interrupt of a declared `app-main` goes to `Mains` and is
  refused `:gone` with no row in `Acts`. `app-main` calling `interrupt` on itself is refused
  `:no_self_fix` by `Grants`.
- A main session interrupting another main session: `mcp_delegates_test.exs` already asserts
  `lmain` → `main` is refused `main_fixed_by_operator_only`. `Grants` refuses it before `fixer/4`,
  so `Mains` does not change it.
- A delegate's interrupt: the existing headless (`mcp_delegates_test.exs`) and interactive
  (`delegates_interactive_test.exs`) tests are unchanged and pass.

## Measured

- `Break_Team_MainInterruptsMain` and `Break_Team_MainInterruptsSelf`: 36 distinct states,
  depth 8, 2 s each. `Team_OperatorClaims`: 10 135 distinct states, 4 s.

## Findings

### new-1. No test runs the operator's interrupt of a running main session through `MCP`

What happened: the surface test's tree runs the headless stand-in for every session, so a main
session there never draws a screen the `Inlet` reads. The mid-turn interrupt is tested on
`Mains` directly. The route from `Operator.interrupt/2` through `MCP` is tested only on a
declared main session, which is refused before the claim.

Why: the surface test's config has one `claude:` for every agent row.

What I did: tested each half on its own: the claim and route in the surface test, the press in
the `Mains` test. The claim code is the one `act/5` every fix shares, already tested for
delegates.

What the design should change: let a test tree name the screen stand-in for its main sessions,
so one test can take an operator's interrupt from `MCP` to the screen.

### new-2. An interactive delegate's answer can be refused for a hook event

What happened: the first version of this unit put `offset` in every fix's state of a main
session, as `Delegates` does for an interactive delegate. The review found that an answer to a
main session's permission request would then be refused `{:moved, now}` when any hook event (a
`Notification`, say) came between its read and its act, and a main session writes many.

Why: `offset` is what makes each turn a new state for an interrupt. An answer is already tied
to its request by `held`, and a resume to its process by `pid` and `proc_start`.

What I did: `offset` is only in the state an interrupt claims (`fix: :interrupt`). The answer's
and resume's state is as on `main`. A test checks that an answer is still taken after a hook
event moved the interrupt's state.

What the design should change: an interactive delegate's state (`Delegates.fix_state/3`) still
has `offset` for every fix, so its answer can be refused the same way. Give it the same split.

### new-3. Tests time out at 60 s under a load of 60 to 80 on 15 cores

What happened: before the rebase, `gate-test` runs 1, 2 and 5 of five passed. Runs 3 and 4
failed only in `apps/caf_example/test/console_test.exs`. In both, "bin/caf-example names a
refused config and ends with status 2" timed out at 60 s in `read_until/3`. In run 4, "the
console's acts go through the operator's tools" was also refused `{:instance_running, "t"}`.

After the rebase onto `c8c5e88`, every full run failed one to three tests, each in its own file,
all by a 60 s timeout:

- `devenv test`, first run: the `mix-format` hook said files were modified, but the tree had no
  change and `mix format --check-formatted` passed. Second run:
  `apps/caf_surface/test/surface_test.exs`, "the config's usable keeps a start off an account
  the app flags, in every part that picks".
- `gate-test` 1: `apps/caf_example/test/tree_main_test.exs` ("a main session answered past its
  trust dialog reaches idle in agents") and `apps/caf_example/test/console_test.exs` (two
  tests).
- `gate-test` 2: `apps/caf_mains/test/mains_test.exs` ("a resume runs on its row's account, and
  on another only after a copy") and `apps/caf_example/test/tree_main_test.exs` ("a main
  session started through Mains on the whole tree reaches idle, then ends").
- `gate-test` 3: `apps/caf_mailbox/test/mailbox_typed_test.exs` ("a typed row with no user line
  past the take bound is due again") and `apps/caf_mains/test/mains_test.exs` (the same resume
  test, and "resume_main resumes a stopped main session under a lease of its own").

The load averages were 60 to 80 on 15 cores the whole time. None of the failed tests is new in
this unit, and none runs an interrupt.

Why: not measured. The refused config is refused before any part starts, so `Mains`' new
`inlet:` is not reached. The `{:instance_running, "t"}` failure looks like an instance named `t`
still running from the test that timed out.

What I did: reran each failed file alone. `surface_test` (41 of 41), `mains_test` (33 of 33),
`mailbox_typed_test` (11 of 11) and `tree_main_test` (2 of 2) passed. `console_test` timed out
once more in "bin/caf-example starts the app with the stand-in and reaches the console" (load
79), then passed alone (load 61). `bin/check-model` passed. I did not change any test.

What the design should change: size the test bounds to the load, as the stand-in's bounds are,
or run the gates on a machine that is not shared. Give each console test an instance name of its
own, so one slow test does not fail another.
