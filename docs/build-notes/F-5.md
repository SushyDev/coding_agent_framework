# F-5: `Move.tla`

## What was built

- **`model/tla/Move.tla`**: a parent session on two accounts, with its turns, background
  commands and delegates, each account's allowance, and the Mover. One action per event:
  `UsageRises` (to 90 %, then the limit), `PromptSent`, `TurnEnds`, `BgStarted`, `BgEnds`,
  `DelegateStarted`, `DelegateEnds`, `ReportDelivered`, and the move's `Drain`, `Cleared`,
  `EndAsked`, `ProcessExits`, `Copied`, `Resumed` and `SessionEndArrives`. Its header names
  `Usage`, `Mover`, `Sessions` and `Parents`, none built yet, and what it leaves abstract.
- **Configurations**: `Move_Design` and six `Break_Move_*` in the fast set; `slow/Move_Large`.
- **`bin/check-model`** reads `TLC_WORKERS` (default `auto`), so a busy machine can run the gate
  on few cores.
- **`model/tla/READING.md`** reads `Move.tla` in the order of a move; **`docs/design.md`** notes
  under "The model" what the spec settles.

## The model

Invariants: `OneAccountAtATime`, `NothingLost`, `TranscriptKept`, `LateEndNeverEndsMoved`,
`TypeOK`. Step property: `NoStartWhileDraining`. Liveness: `DrainedParentMoves`.

| Configuration | Removes | TLC reports |
|---|---|---|
| `Break_Move_NoDrain` | the drain's refusal of new starts | `NothingLost` |
| `Break_Move_NoTurnWait` | the wait for the turn to end | `NothingLost` |
| `Break_Move_LateEndEndsNew` | the pid check on `SessionEnd` | `LateEndNeverEndsMoved` |
| `Break_Move_ResumeBeforeEnd` | the wait for the old process to exit | `OneAccountAtATime` |
| `Break_Move_CopyBeforeEnd` | copying after the end | `TranscriptKept` |
| `Break_Move_ReportDuringMove` | holding a report until a parent process runs | `NothingLost` |

No guard is defense in depth. A scratch copy without the resume's fairness fails
`DrainedParentMoves` (exit 13), so the liveness check is not vacuous.

## What I ran into

- `[][phase \in {…} => …]_vars` does not parse: `[phase \in` opens a function constructor. The
  condition needs parentheses.
- A `/\` list inside `[][…]_vars` does not parse either; the spec uses one parenthesized `/\`.
- `Break_Move_ReportDuringMove` first passed with no prompts: a delegate starts only in a turn,
  so the break was never reached. It needs one prompt.
- No invariant of the design failed while writing the spec.

## Findings

### new-1. The move must also wait for background commands to end

What happened: the design's steps wait for the turn to end and the input box to be empty, then
end the session. A background command is a child of the session's process and ends with it, and
it runs on after the turn has ended. `Break_Move_NoDrain` loses one in 7 steps: the Mover reads
none running, a prompt starts a turn that starts one, the turn ends, and the end cuts it off.

Why: the drain only stops new starts; the ones already running must still finish.

What I did: the spec's Mover reads that no background command runs (`Cleared`) after the drain,
and the drain keeps that reading true until the end.

What the design should change: add to step 2 "and no background command runs", and say the
check is read after the drain began, so nothing can start after it.

### new-2. Copy the transcript after the old process ended, not before

What happened: the design copies (step 3) before it ends the session (step 4). A prompt sent
through Remote Control between the two adds a turn the copy misses. `Break_Move_CopyBeforeEnd`
fails `TranscriptKept` in 7 steps.

Why: the drain stops the framework's own starts, but not the user's prompts.

What I did: the spec ends, waits for the exit, then copies and resumes.

What the design should change: order the steps as end, wait for the process to exit, copy,
resume.

### new-3. Delegates do not hold a move; their reports wait for a live parent

What happened: "Count a parent's delegates as work still going for it" and "At a hard limit,
only the parent's own state counts" leave open whether a move waits for running delegates. In
the spec it does not, and nothing is lost: a delegate runs in its own process and survives the
parent's end. What can be lost is its report, if it is sent while no parent process runs
(`Break_Move_ReportDuringMove`).

Why: a move ends only the parent's process; the delegates' link to the parent is its session,
which the move keeps.

What I did: `Cleared` waits for background commands only, and `ReportDelivered` waits for a live
parent process that is not ending and whose turn has ended.

What the design should change: say that a move, at any level, waits only for the parent's own
turn and background commands, and that a delegate's report is held by session until a parent
process runs. `Delegate.tla` should keep that hold across restarts of the framework.

### new-4. Whether 90 % moves the parent by itself is not stated

What happened: "Moving it is one press" and "1. Drain: at 90 %" read either as a press that
drains, or as a drain that 90 % starts on its own.

What I did: the spec has both: `Drain` may come from a press at any level, and is fair once the
account reaches 90 %, so a parent at 90 % drains and moves without a press.

What the design should change: say that reaching 90 % starts the move on its own, and that a
press starts it at any level.

### new-5. The end needs the turn check in the same step as the end

What happened: the spec ends the process in one step with the check that the turn has ended
(`EndAsked`). Read and acted on in two steps, a prompt arriving between them would be cut off,
and no drain can stop the user's prompt.

What I did: the header says the end is typed through `Control`'s checked write, which types only
when the turn has ended and the input box is empty, and leaves the screen abstract, as
`Agent.tla` does.

What the design should change: say the Mover ends the session through `Control`'s checked write
(`/exit` when the input box is empty), not by a separate check and stop.
