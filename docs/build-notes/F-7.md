# F-7: `Registry`, with the framework's first table

## What was built

- **`Registry`**: a `GenServer` the caller's tree starts, one per `{host, account}`, with no
  name. `read/2` reads the account's `<config>/sessions/*.json` through `Shell` with one
  `/bin/sh` script (the listing and every file's bytes, each after a NUL marker no JSON text
  holds), so a host over ssh is read the same way. It checks every pid with one `ps`, writes
  only the rows that changed in one transaction, and deletes the row of a file that is gone.
  `rows/2` answers `:unread` before the first read. An optional `interval:` reads on a timer;
  without it, reads happen only when asked.
- **`Registry.SessionFile`**: a pure, total parser. `pid` (a positive integer) and `sessionId`
  are required; the other known keys (`cwd`, `name`, `nameSource`, `status`, `version`, `kind`,
  `entrypoint`, `procStart`, `startedAt`, `statusUpdatedAt`, `updatedAt`) are optional, and one
  of the wrong type is `nil` with the key named in `problems`. Unknown keys are kept in `extra`.
  A file that cannot be parsed keeps its row's last good data and names why in `problem`
  (`:not_json` for a half-written file, `{:missing, key}`, `{:wrong_type, key}`,
  `:not_an_object`, `:unreadable`); it is counted in the read's `problems`, never dropped.
- **`Registry.Liveness`**: Claude Code records `procStart` as `LC_ALL=C TZ=UTC ps -o lstart= -p
  <pid>`, trimmed (read from Claude Code's own code, not from any session file's values). One
  `ps -o pid=,lstart= -p <pids>` with the same environment judges each `{pid, procStart}`:
  `:live`, `:replaced` (the pid was reused), `:gone` (a clean `ps` does not list it; `ps` exits
  1 with no output when it lists none), or `:unknown` (`ps` failed, timed out, could not start,
  answered a line it could not read, or the file has no `procStart`). No process is found by
  name. The answer is stored in the row's `alive` column.
- **`Registry.Table`**: the first tables, in one SQLite file the caller names:
  `registry_sessions` (host, account, file, the parsed fields, `extra` as JSON, `problem`,
  `alive`, `written_at`) and `registry_reads` (when each `{host, account}` was last read, and
  what it counted). A `{host, account}` with no read row is `:unread`. Any process may open the
  file and read (`rows/3`, `rows_by_id/2`); WAL mode lets it while the writer writes.
- **The cue**: after a write that changed rows, or the first read, `notify` is called with
  `%{topic: "registry:<host>:<account>", ids: ids}`, the ids of the rows put or deleted, never
  their data. It is a plain function, not `Phoenix.PubSub`: the library then needs no Phoenix,
  each instance gets its own, and a host app passes `&Phoenix.PubSub.broadcast(MyPubSub,
  &1.topic, &1)`.
- **SQLite through `exqlite` 0.43 directly**, not `ecto_sqlite3`: an Ecto repo is a module
  configured through the application environment and started under a name, which the
  constraints rule out; the `Exqlite.Sqlite3` NIF API opens a connection per path and starts no
  process. `stream_data` 1.4 is the test-only dependency for the property tests.
- **Tests** (`test/registry_test.exs`, generators in `test/support/session_files.ex`, every
  value synthetic): `:unread` before the first read and an empty read after it; live, replaced,
  gone and no-start-time by a real `ps` on the test VM's own pid and a pid that has exited; a
  failing `ps`, a `ps` past its timeout and a missing `ps` all answer `:unknown`; a half-written
  file keeps the last good data with its problem, comes back clean, and a removed file deletes
  its row; a restarted `Registry` resumes from its table; two accounts in one file stay apart.
  Properties: parsing is total over good, odd (an optional key of the wrong type) and bad files
  (a required key missing or mistyped, a file cut short, not an object, random bytes); unknown
  keys are kept; over three generations of generated directories, each read counts every file
  and every problem, a row the cue does not name is unchanged, a new row is named, and the cue
  holds only the topic and the ids.

## What I ran into

- My first `Liveness` keyed its answer by pid, so three files naming one pid with different
  start times got the last one's answer. It is keyed by `{pid, procStart}` now.
- `map_of` over a handful of keys made `StreamData` give up on duplicates; `optional_map/1`
  fits "some optional keys left out".
- Hex was not installed in this worktree's `MIX_HOME`; `mix local.hex --force` installed it
  under `.devenv/state/mix`, which git ignores.
- The unit is about 850 changed lines apart from `mix.lock` and this note: 550 of library code
  with its docs, 290 of tests. It could be split: `Registry.Liveness` and its tests (about 120
  lines) are a part of their own, and `Registry.Table` with the reads row could have come first.

## Findings

### new-1. No spec for `Registry`; pid reuse belongs in one later

What happened: the rules say a protocol is checked in `model/tla/` before its code. `Registry`
is a reader: it reads files and writes rows, and its state rules are property tests, as the
design says for readers ("State that never lags or lies"). `Agent.tla` leaves the registry
abstract.

Why: the one part of it with an order over time is pid reuse: a pid read here can be taken by
another process before something ends it by pid.

What I did: no spec. Every row carries `procStart` and `alive`, and `:replaced` names a reused
pid.

What the design should change: say that whatever ends a held agent by pid checks `{pid,
procStart}` in the same shell command as the kill, as a write checks its pane's tag, and model
that check where the kill is built.

### new-2. A file's last good data outlives a broken read

What happened: a half-written file is invalid JSON for a moment. Dropping its row would show
the agent gone and back, which a view would show as so.

What I did: the row keeps its last good data and names the problem; the read counts it.

What the design should change: "Unread is not empty" could add that a reader keeps a row's last
good data when its source cannot be read, and marks it, rather than removing it.

### new-3. `procStart` is a `ps` string in UTC and the C locale

What happened: Claude Code records a process's start as the text `ps -o lstart=` prints, in
UTC and the C locale. A check on another host's `ps` must print the same text; a `ps` whose
`lstart` format differs answers `:replaced` for a live process.

What I did: `Liveness` asks `ps` with `LC_ALL=C TZ=UTC`, through `Shell`, so a remote host's
`ps` answers. It is shown on macOS only.

What the design should change: the "Claude Code" rules could name `procStart` and its format,
and `Screen`'s per-release fixtures could include a session file's shape per release.
