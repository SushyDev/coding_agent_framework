# F-71: the code's docs use the design's words

## What was built

F-68 fixed two words in `docs/design.md` ("Concepts"). This unit puts them in the code's docs. It
changes only `@moduledoc` and `@doc` texts and comments in `apps/**/*.ex` and `apps/**/*.exs`: no
behavior, name, function or test assertion changes. 24 lines in 16 files.

- **"host app" is "embedding app".** *Host* names only machines. The Elixir application that runs
  the framework's parts is the embedding app. "A host app" became "an embedding app".
- **"parent session" is "main session", and `Parents` is `Mains`.** The top agent is a main
  session, and the part that will hold it is `Mains`. *Parent* stays where it names the link
  between two levels: a delegate's parent.

Found with `grep -rn -i -E 'host app|host application|parent session|Parents' apps --include='*.ex'
--include='*.exs'`: 21 lines. All 21 are changed. The same grep now finds nothing.

## Findings

### new-1. The role atom and the settings file still say "parent" for a main session

What happened: the docs now say "main session", but the code still names the kind `:parent`: the
`ClaudeCLI` role (`:parent | :delegate`), `Sessions` options and doctests that pass it,
`Account.settings.parent`, the file `parent.settings.json` an account writes under
`<config>/framework/`, and one test name. A reader who reads the design and then the code meets
two words for one thing.

Why: this unit may not change a name, a function or a test assertion, and renaming an atom changes
a pattern match; renaming a file on disk changes what an existing account directory holds.

What I did: left them, and named the atom in the one doc that mentions it
(`claude_cli.ex:12`, "role `:parent`") so a reader can find it.

What the design should change: when `Mains` is built, decide the new name of the role (`:main`
beside `:delegate` reads well) and of the settings file (`main.settings.json`), and rename them in
the same unit, with a step that writes the new file name and removes the old one from an account
that already has it. Until then, "`:parent`" in a doc means a main session.
