# F-290: a model check on a busy host leaves its cores to others

## What was built

`bin/check-model` ran TLC with `-workers auto`, every core, unless `TLC_WORKERS` named a number.
On a shared host that is wrong. One builder's full model check took about six cores, and the host's
CPU pressure (some avg60 63%) then made the scheduler refuse every other heavy lease until it ended.

Now each configuration's workers are chosen from the 1-minute load read as it starts:
- `TLC_WORKERS` when set, a number or `auto`;
- else every core (`auto`) while the load is under half the cores;
- else 2.

The 30 s rule for a fast configuration is judged only on a run on every core, since it measures a
configuration's size, not a slow run. Each time line now names its workers.

## What was measured

`Agent_Writes` at load 29.8 on 12 cores: 2 workers by default, 30 s, `ok`. With `TLC_WORKERS=1`
the run was over 30 s and printed "not judged", `ok`.

## Findings

### new-1. A full model check could take the heavy lease

The test suites run under the scheduler's heavy lease when the embedding app's `caf-run` is
there; the model check does not. Taking the lease would queue it behind other heavy work instead
of sharing the cores. It needs `caf-run` on the path and a bound on the wait, so it is its own unit.

### new-2. The 30 s rule is judged only on a quiet host

On a busy host the rule is never judged, so a configuration that grew past 30 s shows only on a
quiet host's run. A builder's note should state a quiet run's times when it adds or grows a
configuration.
