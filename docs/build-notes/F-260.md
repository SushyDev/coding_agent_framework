# F-260: a conversation's messages through a facade

## What was built

- `CodingAgentFramework.conversation(instance, agent, opts)` in `caf_surface`. It finds the agent's
  row on any host of the config, computes its transcript's path from the row's account, working
  directory and session, reads the rows still `queued` or `sending` to it from the store
  (read-only), and then asks the host's `Transcripts` for the entries. It answers
  `{:ok, %{entries, next, queued, reset}}`. Its refusals are `:no_instance`, `:unknown_agent`,
  `{:no_session, status}`, `:no_file` and `{:bad, key}`, and `{:unknown, {:host, reason}}` covers
  a host whose shell fails or that has no reader.
- `Transcripts.conversation/3`, a call on the host's reader. It reads the file from the cursor
  with the host's `tail` and `head` through `Shell`, so over ssh on another host, and only the
  bounded bytes cross. The cursor is opaque: per file (the main one, and each subagent's), the
  offset of whole lines read, the last 64 bytes before it (a seam, as the fold keeps), whether a
  too-long line is being passed over, and the calls still open. A cursor whose seam no longer
  matches starts the file again with `reset: :rewritten`. A cursor of another path starts the
  new path with `reset: :new_file`.
- `Transcripts.Fold.entries/2`, the entries of whole lines. The user line's reading (tool result,
  task notification, meta, prompt) is now one private function, `user_kind/2`, which both
  `take/2`'s fold and `entries/2` use. Interrupts use the fold's own texts. A call's result that
  comes in a later read gives the call again under its id, with its name and start from the
  cursor's open calls, so its `duration_ms` is still known.

## Bounds

- At most `limit` entries per call (default 100, at most 1000). A line's entries are never
  split.
- At most `max_bytes` per file per call (default 1 MB, the reader's `first_read`).
- A line longer than `max_bytes` gets one `system` entry, `unread_line`, and is passed over
  across calls.
- Tool results are cut at 20,000 characters. The cursor keeps at most 100 open calls.

## What was measured

- `caf_transcripts`: 39 tests in 2.8 s, the 7 new ones among them, on a load of about 55 on 15
  cores.
- `caf_surface`'s new test, a whole tree: 1.0 s.

## What I ran into

- No facade call ran on another host before this. `docs/design.md` ("Hosts") says agents run
  only on the workstation, and the tree starts one `Transcripts`, the workstation's. The read
  itself works on any host, since `Transcripts` reads through its host's `Shell`. The new test
  shows this with a stand-in for ssh, including a dropped host answering `{:unknown, {:host, _}}`.
  The facade routes by the row's host and refuses a host that has no reader.
- My first long-line check also fired on a line that began after a passed-over line ended in
  the same read. The rule is now: only a line that begins the read and fills it is too long.
- No TLA+ spec: the call is a stateless read with no protocol over time. Its only state is the
  caller's cursor.

## Findings

### new-1. A session on a second host has no reader in the tree

What happened: the facade finds the agent's host from its row, but the tree starts a
`Transcripts` only on the workstation. Why: "Hosts" puts every agent on the workstation. What I
did: a row on another host answers `{:unknown, {:host, {:no_reader, host}}}`. The read path
itself is host-neutral and tested over ssh. What the design should change: when sessions run
on a second host, the tree starts one `Transcripts` per host that runs agents. It also needs a
rule for where an account's config directory is on that host. Today the path comes from the
workstation's `Accounts`, under the home.

### new-2. A tool result read after its call carries no input

What happened: when a call's result is in a later read, the call comes again by id without its
`input`. Why: keeping every open call's input in the cursor would make the cursor as large as
the inputs. What I did: the entry has `input: nil` and its name and start from the cursor. An
app merges entries by `id`. What the design should change: nothing, unless an app needs the
input on the later entry. Then the reader could re-read the call's line by its offset.

### new-3. Subagent files are read after the session's own, within one limit

What happened: with `subagents: true`, a busy main file can use the whole `limit`, and the
subagents' entries wait for later calls. Why: one bound per call keeps reads small. What I
did: documented it. Each entry carries `agent`, and entries come in file order, not time
order. What the design should change: decide whether an app wants a merged time order. If so,
it sorts by `at`.
