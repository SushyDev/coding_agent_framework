# F-166: a start whose caller gave up never runs later

F-164's new-1, as decided: when a `Delegates` start's call of `Sessions` times out, or
`Delegates` restarts, the request can still wait in `Sessions`' mailbox. `Sessions` took it
later, with a deadline of its own from that moment, and ran a process under a row `Delegates`
had already refused, which nothing ended. Now the caller's deadline travels with the request,
and `Sessions` refuses a start it takes past it, `{:refused, :caller_gone}`, with nothing made.

## What was built

- **The model first, `Delegate.tla`.** A call of `Sessions` is now two things: `call`,
  `Delegates`' wait in memory, and `queue`, the request in `Sessions`' mailbox, with `late`, its
  caller's deadline passed. `Request(d, kind)` makes both (in `StartAsked`, `StartAgain` and
  `KillSeen`). The queue survives `FrameworkDies` (`Sessions` is another process); it goes with
  `RestartAgent`, as a mailbox goes with its process. New steps: `CallerLate` (the caller's
  deadline passes while the request waits) and `CallGivesUp` (the call answers unknown after
  that deadline, with the request still queued). `Called` takes the request whether `Delegates`
  runs or not: in time it writes `Sessions`' row as before; late it writes nothing, and a call
  still waiting is answered refused (`CallAnswered`'s new case). `Settled` refuses a row with no
  `Sessions` row only when no request of it waits in time, which stands for the row's deadline
  coming after the caller's. `TypeOK` adds that a queued request has no `Sessions` row yet.
  The header's "Not implied" note on `RefusedHoldsNothing` is replaced by what is now checked.
- **`Break_Delegate_TakeStale`**: `Called` takes a late request as one in time. TLC fails
  `RefusedHoldsNothing` by the race itself, in a trace of eight states: `PromptSent`, `StartAsked`, `CallerLate`,
  `CallGivesUp`, `Settled` (refused), `Called`, `SessionsDecides` (a process held).
- **`Sessions`**: `start/5` and `resume/6` take `:caller_deadline`, wall-clock ms on the
  `clock:` `Sessions` is given. It travels in the request, and the first step of the start's
  `handle_call`, before any read, act or row, refuses it at or past that time
  (`in_time/3`), with one `Logger.debug` line. A deadline that is not an integer is refused
  `{:bad, :caller_deadline}`. With none, a start is taken whenever it comes, as before.
- **`Delegates`** passes `caller_deadline: row.deadline - @slack` (the row's deadline less its
  120 s slack, so the lease's time plus 30 s plus the setup's timeout) on every start and resume
  (`call_sessions/7`). A start taken in time writes its agent row within seconds (the steps
  before it are table reads, the memory file, `claude --version` for an interactive one under
  5 s, and the act), long before the row's deadline, at which `Settled` reads no agent row as
  "never reached `Sessions`". The task's own wait, 100 s plus the setup, ends after the caller's
  deadline, so a start taken in time has a caller still waiting unless `Delegates` restarted.
- **Tests.** `sessions_headless_test.exs`, "a start taken past its caller's deadline makes
  nothing": `Sessions` suspended, a headless start sent with a deadline, the test waits until
  the call is in `Sessions`' mailbox, moves the clock past the deadline, kills the caller and
  resumes `Sessions`. A read queued after it answers `{:refused, :no_session}`: no row, no
  `Stream` row, no process. A caller still waiting is told `{:refused, :caller_gone}`, and a
  start in time then starts the name. With the check removed it fails at that read (the late
  start had made its row). `delegates_test.exs`, "a start Sessions takes past its caller's
  deadline is refused and makes nothing": the same through `start_delegate/6`, with the clock
  moved to the row's deadline less 120 s; the start answers `{:refused, :caller_gone}`, the row
  is `refused`, no agent row, no process, and past the row's own deadline nothing more is made.
  With `Delegates` passing no deadline it fails (`{:ok, …}`: the start went on).
- **Docs**: the design's "A row a restart left starting" says why its reading is true, and the
  lease's end no longer says a start may reach `Sessions` after its row was refused. The module
  docs of `Sessions` and `Delegates` say the same.

## What I ran into

- **Which deadline the request carries.** Passing the row's own deadline would leave the race at
  its edge: `Sessions` reads its clock just before the deadline, takes some seconds before its
  row is written, and `Delegates`, at the deadline, reads no row and refuses. So the caller's
  deadline is the row's less the slack, and the gap between the take and the row write is
  covered by a margin of 120 s, not by one atomic step. The model keeps that order as an
  assumption (`late` before `Settled`'s refusal), not as a clock.
- **A test must see the take, not wait for it.** A suspended `Sessions` and the mailbox read
  (`Process.info/2`'s `:messages`) show the call is queued; a call after `:sys.resume/1` is
  answered only after the late start was taken, so no sleep is needed. `Stream.rows/1` answers
  `:unread` until a first `Stream.read/1`.

## Findings

### new-1. `Mains` reads the absence of its start's agent row the same way

What happened: `Mains` settles a start a restart cut by the agent row of its call, and with none
by the row's deadline refuses it `interrupted` (`mains.ex:927`), while its call of `Sessions`
(`mains.ex:858`, `timeout: @call`) carries no caller's deadline. A main session's start queued
in `Sessions` past that refusal would run under a refused `Mains` row, as a delegate's did.
Why: this unit decided the rule for `Delegates`, whose model is `Delegate.tla`; `Mains`' start
is modeled elsewhere, and the model comes first.
What I did: nothing in `Mains`. `Sessions.start/5`'s `:caller_deadline` is there for it.
What the design should change: give `Mains`' start the same queued request in its spec and pass
`caller_deadline: row.deadline - @slack` from `Mains`. The `Mover`'s resume reads `Sessions`'
row, not an absence at a deadline, but while a resume that timed out still waits in the mailbox
its agent row is free, and the next cue resumes again (`mover.ex:333`); the first then runs, and
the second meets a name that is not free. I did not check that path further.

### new-2. F-165's end-time test races the first settle of the `Sessions` it shares a table with

What happened: the first `devenv test` failed `caf_sessions`' "a row's end time is its first
done status's, kept by later writes" (`apps/caf_sessions/test/agents_test.exs:117`): the row it
wrote `starting` straight into the table was `refused`, reason `interrupted`, with its end time
the time of that write, not the 7 the test set.
Why: as far as I can read, the setup's `Sessions` settles every row once after `init`
(`handle_continue(:adopt)`, `settle(state, :all, true)`), and `start_supervised!` returns before
that settle runs. A `starting` row the test writes with no deadline and no socket is past its
deadline and dead, so that settle refuses it, if it runs after the test's write. This branch
changes only the start's `handle_call`, which the test does not call.
What I did: left the test as it is.
What the design should change: nothing; the test should write its rows where no `Sessions`
settles them, or wait for that settle first (a read call of `Sessions` answers after it).
