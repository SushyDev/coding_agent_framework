# F-22: `TmuxSampler`, which joins a host's panes with its held sockets

## What was built

- **`TmuxSampler`**: a `GenServer` the caller's tree starts, one per host, with no name, given
  the host's `Tmux` server, its `Holder` (on the same host, or it does not start) and a SQLite
  path. A sample (`sample/2`, or every `interval:` ms) reads `Tmux.list_panes/1`, then
  `Holder.list/1`, joins them, and writes the rows that changed in one transaction, then cues
  `tmux:<host>:<server>` with the row ids, as `Registry` does. `rows/2` answers the last good
  sample with its `age`, or `:unread` before one. A failed read answers `{:unknown, reason}`,
  writes no row, and records `failed_at` and `problem` beside the last good sample. It acts on
  nothing.
- **`TmuxSampler.Join`**: the pure join (`Agent.tla`, `SamplerReads`). A held socket is `:viewed`
  (with its panes), `:unviewed` (the model's `unviewed`), `:no_server`, `:stale` or `:unknown`.
  A tagged pane is `:live`, `:stale`, `:gone` (no socket) or `:unknown` by its tag's socket. A
  pane or held entry of no known shape is a `:problem` row. Each server start is a generation,
  and a pane's key is `viewer:<generation>:<pane id>`, so no pane id is matched across a restart.
  A new generation is seen by a new `start`, by a read with no server before it, or by a new id
  no higher than the last read's highest.
- **`TmuxSampler.Table`** (`tmux_samples`, `tmux_sample_reads`) and
  **`Tracker.TmuxSamplerSource`** (kind `:viewers`).
- **`Tmux.list_panes/1`** gives each pane `start`, `<server pid>@<start time>` in the CLI, and a
  line it cannot read is `{:malformed, line}`, where it raised before. The fake counts its starts.
- **Tests** (`test/tmux_sampler_test.exs`, real tmux 3.8 and dtach, a `cat` stand-in): a held
  agent with a viewer, then the viewer killed (`:unviewed`); the server killed (`:no_server`),
  then a new server whose `%0` is another session's (a new key, the old one deleted), and a
  second restart with no sample between; a stale socket with a pane tagged for it; a failed read
  that keeps the last good rows, their age, and a `Tracker` view of them with the problem. Two
  properties of the join: total, each bad entry a problem, every status as expected; a new start
  is a new generation and shares no key with the last.

## What I ran into

- `start_time` alone is in seconds: a server killed and started again within one second keeps
  it, and its new `%0` can match an old `%0`. The server's pid is added to it.
- The CLI's `list_panes` raised a `MatchError` on a line with too few fields.

## Findings

### new-1. The `Tracker`'s scope is `{host, account}`, and a tmux server has no account

What happened: `Fold` groups a source's rows by `{host, account}`, and a sampler is per host and
server.

What I did: the scope is `{host, "tmux:<server>"}`, which an account named `tmux:…` would meet.

What the design should change: name the scope of a host-wide reader (`Holder`'s sockets, the
sampler), for example `{host, :host}`, so a view of one host finds them.

### new-2. A source cannot answer rows and a problem at once

What happened: `Fold.read/4` takes rows or `{:unknown, reason}`. A `Tracker` that starts while
the newest sample failed shows no rows, only the problem, until a good sample, though the table
holds the last good rows and their age.

What I did: the source answers `{:unknown, {:sample_failed, at, problem}}` while the newest
sample failed; a running `Tracker` keeps the rows it had.

What the design should change: let a source answer its rows with a problem, so "keeps the last
good sample" holds across a `Tracker`'s restart too.

### new-3. The two reads are not one instant, and the model reads them as one

What happened: `SamplerReads` reads panes and sockets in one step. The code reads panes, then
sockets. An agent held between the two reads, whose viewer is not open yet, reads `:unviewed`
for one sample; a viewer that closes between them shows on the next.

What I did: noted it in the moduledoc. `Recoveries` reopening on such a reading meets tmux's
refusal of a second session of that name, so it does no harm there.

What the design should change: say whether `Recoveries` acts on one `:unviewed` reading or on
two in a row, and model the two reads as two steps if it acts on one.

### new-4. Untagged panes and a pane whose tag differs from its session are not reported

What happened: a viewer is a pane tagged with a session, so the join looks only at tags.

What I did: untagged panes are left out of the rows; their ids still count for a restart.

What the design should change: say whether an untagged pane on the framework's own server, or a
tag that names another session than the pane's, is a broken state for `Recoveries`.

### new-5. `Agent.tla`'s header still says `TmuxSampler` is not built

What happened: other builders are changing `model/`, so this unit did not touch it.

What the design should change: the header should name `TmuxSampler` as built in F-22, and its
`epoch` as the sampler's generation.
