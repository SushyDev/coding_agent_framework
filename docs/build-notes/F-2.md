# F-2: the host layer

## What was built

- **`docs/design.md`** takes F-1's findings: "Writes to panes" says the tag check and the send
  are one tmux command, and every pane written to is tagged as it opens, an untagged one refused
  (new-1); the parts table names `TmuxSampler` as the part that joins held sockets with panes
  (new-3) and `Recoveries` as the part that starts a host's tmux server again when it reopens a
  lost viewer (new-4), owners only; "The model" says a guard that cannot fail on its own is
  named as defense in depth in the spec's header (new-2). `Agent.tla`'s header names the built
  modules, those owners, and its one defense-in-depth guard. The spec's actions are unchanged.
- **`Host`**: a host's name and how it is reached, `:local` or `{:ssh, ssh_path, destination}`.
- **`Shell`**: the one module that starts programs, by absolute path, through a port with a
  timeout; a program past it is killed by its own pid and the outcome is `{:unknown, {:timeout,
  ms}}`. It sets and unsets environment variables, and over ssh quotes every word for the
  remote shell.
- **`Programs`**: the absolute paths of tmux, dtach, claude, git and gh on a host, found once by
  the host's `/bin/sh` (`command -v`), or given outright.
- **`Tmux`**: the contract (an Elixir behavior module) and the checks of its arguments, shared by both
  implementations; **`Tmux.CLI`** on a real server (`-L name` or `-S path`, `-f /dev/null` by
  default); **`Tmux.Fake`**, an `Agent` the caller starts. Calls: `new_session` (opens and tags
  the pane in one tmux command), `list_panes`, `write`, `kill_session`, `kill_server` (which
  removes the socket file). Each key is `{host, server}`.
- **`Holder`**: dtach on a host, in a directory it owns: `hold` (`dtach -n`, removing a stale
  socket first, refusing a live one), `state` (`:live`, `:stale`, `:absent`), `remove_stale`,
  `list`, and `viewer_argv` (`dtach -a`). The held process runs without `CLAUDECODE`,
  `CLAUDE_CODE_*`, `TMUX` and `TMUX_PANE`.
- **Tests**: `test/tmux_contract_test.exs` runs one contract on the CLI and the fake; the CLI's
  server is on a socket the test owns in this VM's own directory (`<tmp>/caf-<os pid>/`).
  `test/holder_test.exs` holds a stand-in on real dtach sockets. `test/shell_test.exs` covers
  `Shell` and `Programs`. Doctests run for every module. `test/support/test_host.ex` has the aids.

The write, as `Tmux.CLI` runs it:

```
tmux -S <socket> -f /dev/null if-shell -F -t %3 \
  '#{&&:#{==:#{pane_id},%3},#{==:#{@caf_session},alpha}}' \
  "send-keys -t %3 -l -- '<text>' ; display-message -p sent" \
  "display-message -p -t %3 'refused<TAB>#{pane_id}<TAB>#{@caf_session}'"
```

The contract tests show on tmux 3.8: a write to the right pane arrives literally (quotes, `$`,
`~`, `#{…}`, a backslash and a trailing `;`); a write to a pane tagged for another session is
`{:refused, {:tagged_for, other}}`; to an untagged pane `{:refused, :untagged}`; to a missing
pane `{:refused, :no_pane}`; to a dead server `{:refused, :no_server}`. The model's scenario runs
for real: alpha's pane is `%0`, the server is killed, the new server gives beta `%0`, and the
write with alpha's kept `%0` is refused as tagged for beta. Each "sends nothing" is shown by
order: a later accepted write to the same pane, after which the pane's file holds only that one.

## What I ran into

- `if-shell -F -t %99` with no such pane does not fail in tmux 3.8: it runs the else branch with
  an empty `#{pane_id}` and exits 0. See new-1.
- My first escape of a trailing `;` doubled the backslashes before it, and the contract test
  showed `a\;` arriving as `a\\;`. tmux 3.8 turns only the trailing `\;` into `;`. See new-2.
- A probe `dtach -n` whose pid file I read too early left a dtach and its child running; I found
  both by their socket's path and ended them by pid.
- The unit is about 1,480 changed lines (about 800 of library code with its docs, 450 of tests,
  the rest docs), over the 500 the instructions aim for. Design item 2 names the four parts as
  one unit; `Holder` and its test, about 330 lines, could have been a unit of their own.
- A bare `quote/1` cannot be defined in Elixir (it is a special form); the shell quoting is
  `Shell.shell_quote/1`.

## Findings

### new-1. The write's check names the pane id as well as the tag

What happened: `if-shell -F -t <pane>` with a pane id that does not exist runs its else branch
and exits 0; the format sees no pane.

Why: tmux resolves `if-shell`'s target leniently, so the target alone does not prove the pane
exists.

What I did: the condition is `#{&&:#{==:#{pane_id},<pane>},#{==:#{@<tag>},<session>}}`, and the
else branch prints `#{pane_id}`, so a missing pane is refused as `:no_pane`, apart from an
untagged one. The contract test covers it.

What the design should change: the example command in "Writes to panes" should compare
`#{pane_id}` with the target as well as the tag.

### new-2. How an argument ending in `;` is escaped

What happened: tmux 3.8 reads an argument ending in `\;` as the same argument ending in `;`, and
changes nothing else in it. An argument ending in a bare `;` ends the command.

Why: the design's rule says to escape every argument but not how.

What I did: `Tmux.CLI.escape/1` puts one backslash before a trailing `;`. A contract test passes
`x;`, `y;z`, `a\;`, `p\`, `#{pane_id}` and `$HOME` to a pane's program and reads them back whole.
Text sent to a pane goes inside tmux single quotes in the `if-shell` command, with `'` written
as `'\''`.

What the design should change: the tmux rule could say "put a backslash before an argument's
trailing `;`".

### new-3. A host reached over ssh cannot yet clear `CLAUDE_CODE_*`

What happened: removing every `CLAUDE_CODE_*` variable needs the names, which `Shell` reads from
this VM's environment. Over ssh it would need the remote environment, so `Shell` refuses it
(`{:refused, {:unset_prefix_over_ssh, prefixes}}`), and `Holder.hold/4` on a remote host is
refused with it.

Why: `env -u` takes exact names only.

What I did: nothing more; the refusal is named and tested.

What the design should change: say how a remote held agent's environment is built, for example
`env -i` with an explicit list of what it keeps, which also covers the local case.

### new-4. dtach gives no pid for a held process

What happened: `Holder` tells live from stale by connecting to the socket (`dtach -p` with empty
input), which works on any host through `Shell`. dtach never says the held process's pid, so
`Holder` cannot "hang up" or "list a socket's children", which the parts table gives it.

Why: dtach's master forks the child and reports nothing.

What I did: `Holder` builds hold, state, list, remove_stale and the viewer's command, not hang-up
or children. The tests learn pids from a stand-in that writes them.

What the design should change: say where a held agent's pid comes from (the session's file in
`<config>/sessions/`, which `Registry` reads, or a wrapper that records it), and give hang-up to
the part that knows it.

### new-5. A socket path has a length limit

What happened: macOS cuts a unix socket path at 104 bytes, and a long temporary directory plus a
session id can pass it.

What I did: `Holder` refuses a path over 103 bytes as `{:socket_path_too_long, path}`.

What the design should change: say each host's dtach directory is short, and session ids used as
socket names have a bound.
