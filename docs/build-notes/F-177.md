# F-177: a resume on its row's account; an import that refuses on any running Claude Code

An app is about to move its conversations onto the framework with `bin/caf-import` (F-156)
and resume them. A conversation lives only in the account it ran on or was imported into, but
`Mains.resume_main/3` picked the account with the most allowance left, so with two accounts a
resume could run `--resume <id>` where Claude Code has no such conversation. This unit takes up
F-156's new-1, new-2, new-4 and new-5. No test or step of it started the real Claude Code.

This branch is stacked on `framework/f-156-import` (its two commits), not on `main`: F-156 is
not merged, and three of the four items change its `Mains.Import` (new-1 below).

## What was built

- **The model first** (`Move.tla`, where the copy already is). A constant `Resumes`: the
  session's process may end by itself while no move runs (`EndsAlone`, counted with the
  crashes), and `Mains`' resume takes the stopped row up: on the row's account while it is not
  refused (`ResumeHere`); else the picked account first takes a copy (`CopyAsked`,
  `ResumeCopy`), then the resume runs there (`ResumeCopied`); a copy refused or cut by a
  restart leaves the row stopped on its own account (`CopyRefused`). An account is refused when
  its windows have no room (`Refused(a)`; a refused login is the same refusal, left abstract).
  `TranscriptKept` is now an action property: each new process, a move's or a resume's, starts
  from the whole transcript of the account the row named. It holds of the move as before, and
  still catches `Break_Move_CopyBeforeEnd`. New `CopySettles` (liveness). `Move_Resume`
  checks it all; `Break_Move_ResumeOnPicked` (the resume runs on the account picked by
  allowance, with no copy) fails `TranscriptKept`. Every earlier configuration, the slow
  `Move_Large` included, sets `Resumes = FALSE` and lists `TranscriptKept` under PROPERTIES.
- **A resume on its row's account** (`Mains.resume_main/3`). It runs on the account the agent
  row names. That account is refused when `Accounts.ready/2` refuses it (not prepared), when
  `Accounts.login/2` answers `logged_out` (Claude Code never ran there; one whose login is not
  readable from files may be logged in, so it is not refused), or when the new option
  `allowance:` answers `{:spent, retry_at}`: the `Scheduler`'s own gate function, which the
  app's tree now hands `Mains` too, through a connection of its own
  (`Usage.Allowance.check/3`). Then the resume goes to the account with the most allowance left
  among the others not refused (`Usage.pick/4`), and the start's task first copies the
  conversation there, in the checkout's encoded path, then resumes under the same session id.
  The copy is an act `copy` in `Acts` (target `agent:<name>`, `verified` or `failed`, with
  `from`, `to`, the session id and why the row's account was refused). A copy refused leaves
  the agent row stopped on its account and refuses the start `{:copy, reason}`; with no other
  account the resume is refused `{:account, account, reason}` before any start row.
- **One copy** (`Transcripts.Copy`): the `Mover`'s private `copied/2` and its helpers, moved
  as they were into `caf_transcripts` (the transcript, the directory beside it and
  `session-env/<id>`, each whole under a temporary name, the size checked), so the `Mover`
  and `Mains` copy with one mechanism. Its temporary suffix is `.copying` (was `.moving`).
- **The import refuses on any running Claude Code** (F-156's new-4). Besides the agent rows,
  it reads the account's and the source's `sessions/<pid>.json` with the new
  `Registry.running/3`: the `Registry`'s own shell read and `SessionFile.parse/1`, then one `ps`
  by pid and start time (`Holder.Process.liveness/3`), nothing written. A live pid refuses
  `{:refused, {:running, pids}}`. A pid `ps` lists whose start time is not known (a file half
  written, read by its name `<pid>.json`, or one naming no `procStart`) refuses `{:may_run,
  pids}`; a read that failed refuses `{:sessions_unread, reason}`. `run/1` takes `programs`
  (sh, cat, env, ps); `main/2` builds them from devenv's `CAF_<NAME>` variables. `caf_mains`
  now depends on `caf_registry` at run time, not only in its tests.
- **Settings that name a missing path** (F-156's new-5). A copied `settings.json` is kept as
  it is. Each absolute path a setting of it names that does not exist on this host is a line
  of the report: `settings: settings.json keeps <key>, naming <path>, not on this host`, the
  key as its place in the JSON (`hooks.Stop[0].hooks[0].command`,
  `permissions.additionalDirectories[1]`). `Import.missing_paths/2` finds them, a doctest.
- **`--db <path>`** (F-156's new-2): optional, by default `<home>/caf.db`; `parse/1` fills it.
- **Tests**. `mains_test.exs`: a stopped row of `work` resumes on `work` though `spare` has
  more allowance left; with `work`'s windows spent and `spare` never logged in, the resume is
  refused `{:account, "work", {:allowance, _}}`; with `spare` logged in and the transcript
  gone, refused `{:copy, {:no_transcript, :enoent}}`, the row stopped on `work`; then the
  copy (the transcript and its directory) and the resume on `spare` under the same session id,
  and the two `copy` acts, failed then verified. The F-156 import test now also refuses on a
  live and on a half-written session file in the source and in the account, refuses an absent
  `--db` file, and names a missing additional directory while keeping the settings file
  whole. `registry_test.exs`: `running/3` over live, half-written, reused, gone and missing.
  Doctests for `Transcripts.Copy`, `Import.missing_paths/2` and `parse/1`'s `--db`. The Mains
  suite's account now has a `.claude.json`, as an account Claude Code ran in does.
- **Docs**: `docs/design.md` ("A resume", "An import", `Move.tla`'s settled points),
  `README.md` (Status, step 4 of the example), `bin/caf-import`'s usage, and the moduledocs of
  `Mains`, `Mains.Import`, `Mover`, `Registry` and `Transcripts.Copy`.

## What was measured

- `Move_Resume`: 34 743 distinct states, depth 33, 9 s. `Break_Move_ResumeOnPicked`: 201
  distinct states, 3 s, `TranscriptKept` violated: the resume on `a2`, whose transcript is
  empty, of a session whose `a1` transcript holds a turn. A throwaway invariant `phase #
  "copied"` failed within 345 states, so the copy path is reached.
- The gates: see "Gates".

## What I ran into

- `TranscriptKept`, a state invariant `phase = "moved" => resumedWith = transcript[Home]`,
  fails once a resume on `Home` lets that transcript grow; written as the action property over
  each new process, it says the same of the move and holds of the resume.
- A test assertion of mine refuted any report line naming the test directory; the import's
  lines name the checkout, which is under it. It now refutes only a line naming that directory
  as missing.
- The test output carries lines `erl_child_setup: failed with error 32 on line 284` in suites
  this unit does not touch as well; no test fails on them.

## Findings

### new-1. F-177 needs F-156, which is not on `main`

What happened: the brief says to branch from `main`, but `Mains.Import`, `bin/caf-import` and
the imported rows are only on `framework/f-156-import`, finished (its gates passed) and with no
pull request yet. Why: the brief was written as if F-156 had merged. What I did: this branch
starts at F-156's last commit, `5838dae`, and this unit's work follows it. What the design should
change: merge F-156 first; this branch then goes onto `main` with `git rebase --onto main
5838dae`.

### new-2. "Its login refused" is read from which files exist

What happened: the only check that reads no credential is `Accounts.login/2`, which knows
`logged_out` (no `.claude.json`) and otherwise `looks_logged_in` or `login_not_readable`; on
macOS the login is in the Keychain, so it is never readable there. Why: the framework reads no
credential. What I did: a resume leaves its row's account for `not_prepared` and `logged_out`
only. An account whose login expired or was revoked still takes the resume, which then waits
on Claude Code's own login screen. What the design should change: say whether a login refused
should be read another way (`claude auth status`, which the example console's stand-in answers)
before a resume or a start.

### new-3. A start picks by allowance alone

What happened: `start_main/5` still picks the account with the most allowance left, never asking
whether it is logged out or its five-hour window spent; the `Scheduler` then refuses a spent
one `{:lease, {:allowance, _}}` instead of the start going to another. Why: the brief names the
resume. What I did: nothing; the resume's `usable/2` check is there for a start to share. What
the design should change: say whether a start picks among the accounts not refused, as a resume
that leaves its account does.

### new-4. A session file whose process cannot be judged refuses the import

What happened: the brief names `{:refused, {:running, pids}}` for a live pid. A file half
written, or naming no start time, while `ps` lists its pid, cannot be judged by its start time.
What I did: it refuses `{:may_run, pids}`, since a count of a live process as gone is what the
check is there to prevent, and a read that failed refuses `{:sessions_unread, reason}`. What the
design should change: confirm both, or name them.

### new-5. Which paths a setting names

What happened: a setting names a path as a whole value (`additionalDirectories`) or as a word of
a command (a hook). What I did: every string of `settings.json` is read for words that start
with `/` (not `//`, so a URL is none), each checked with `File.exists?/1` on this host. A path
written `~/…` or `$HOME/…` is not read, since the library reads no environment, and the
copied `agents/`, `commands/` and `skills/` files are not read. What the design should change:
confirm, or name the keys and forms a check reads.

### new-6. A resume's copy leaves the conversation in two accounts

What happened: the copy is a copy, as a move's is, so the row's old account keeps its files, and
a copy on the picked account from an earlier move or resume is replaced whole. Why: the
`Mover` copies so, and only the row's account is ever resumed. What I did: nothing more. What
the design should change: nothing, unless the old account's copy should be removed once the
resume runs, which the move does not do either.

### new-7. The shared copy's temporary suffix changed

What happened: `Transcripts.Copy` names its temporary files `.copying`; the `Mover`'s were
`.moving`. A `.moving` file a restart cut before this build stays in that account's
`projects/` as a stray file; the next copy of that session writes its own. What I did: nothing
more. What the design should change: nothing, unless a stray temporary file should be a state a
view shows.
