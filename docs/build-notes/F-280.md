# F-280: a remote host takes work, its programs found when work first goes there

## What was asked

An embedding app runs on a Linux workstation and declares a second host, a Mac reached over ssh,
for jobs, services and heavy commands. Before this unit none of that could work. The app built
the remote host's `Programs` once, at the tree's start, with no paths, so every job or service
there was refused `{:no_program, …}`. A host away at the start stayed unusable until the app
restarted. The heavy-slot lease counted the workstation's slots only.

This unit builds items 1, 2 and 4 of the brief. Item 3 (heavy slots per host) is left for a unit
of its own: items 1 and 2 alone come to 368 changed lines outside the model and tests, before
this note, and item 3 changes the `Scheduler`'s resources, `Runs`' wrapper and its plug.

## What was built

- **The model first**: `model/tla/Host.tla`, one host that goes down and comes up at any time, an
  operator who adds its missing programs once, and two works placed on it again and again.
  `Host_Design` checks `NotPlacedAway` (no work is placed on a host down for the placement's
  whole span), `AwayOnlyDown`, `MissingOnlyLacking` and `Answered` (every placement is answered).
  Four Break configurations each fail: `KeptReady` (a host kept ready takes work with no find:
  the brief's config that places work on a host that is away), `StickyAway`, `KeepLacking` and
  `Wait` (a find with no bound).
- **`Hosts`**, a new app `caf_hosts` with one process per tree. It keeps each declared host's
  state: `unknown`, `ready`, `away` or `lacking`. `Hosts.reach/4` with `:place` finds the host's
  programs over ssh (`Programs.find/3`, bounded by the placement's start timeout), checks that its
  rsync is 3.1.3 or later, keeps the answer, and answers at once:
  - `{:ok, entry}`, the host as `Copies.Held` reads it;
  - `{:refused, {:no_program, host, names}}`, every program missing named;
  - `{:refused, {:old_rsync, host, line}}`, `line` the first line of its `--version`;
  - `{:refused, {:host_away, host}}`, no answer within the bound.

  `:reach`, for work already placed, takes the programs kept while the host is ready. The find
  runs in the caller's process, so a host that hangs never holds up another.
- **`Copies.Held.context/4`** takes a mode: an entry `%{hosts: server}` is read from `Hosts`. A
  `Jobs.run/6` places (`:place`) before it writes the job's row or asks for a lease, so a refused
  host leaves nothing behind. `Services`' start and restart place too, and their row reads
  `refused`. Every other read (a log, a settle, an end) uses `:reach`. The forward's ssh reads its
  host through `Held.host/4`.
- **The tree** starts `Hosts` before `Copies`, in a tree with agents and in one without, and
  hands `Jobs` and `Services` `%{hosts: pid}` for each declared host. `Config` checks `hosts`:
  `{:bad, :hosts, {:not_a_host, name}}` for an entry that is not `%{host: %Host{reach: {:ssh,
  …}}, dir: "/…"}` under its own name, and `{:workstation, name}` for the workstation's name.

## What the app sets

```elixir
mac =
  CodingAgentFramework.Host.ssh("mac", ws_ssh, "me@mac.local", ws_kill,
    options: CodingAgentFramework.ToolHome.ssh_options(home))

CodingAgentFramework.Config.new(
  ...,
  hosts: %{
    "mac" => %{
      host: mac,
      dir: "/Users/me/caf",
      # optional: what every program held there runs in, and a forward's ssh
      env: [{"PATH", "/opt/homebrew/bin:/usr/bin:/bin"}],
      ssh_env: []
    }
  }
)
```

`ws_ssh` and `ws_kill` are the workstation's own ssh and kill. The Mac's programs are looked up,
when work is placed there, on the `PATH` ssh gives a command there, not on the entry's `env`
(new-4). It needs `Hosts.needs/1`: sh, mkdir, rm,
flock, rsync (3.1.3 or later), dtach, env, ps, kill, sleep, tail, head, wc and nc. macOS has no
flock or dtach and its `/usr/bin/rsync` is openrsync, so the first placement there names them:
`{:refused, {:no_program, "mac", [:flock, :dtach]}}`, then `{:old_rsync, "mac", "openrsync: …"}`
until a newer rsync comes first on that `PATH`. A job is placed with `where.host` set to `"mac"`.
Heavy slots per host are item 3, not built here.

## Measured

- `bin/check-model` on the five new configurations, at a load of 25 on 12 cores: `Host_Design`
  1 138 distinct states, depth 12, 2 s; each Break 1 s.
- The stand-in host answers a find in milliseconds. A host that never answers (`hang`) is refused
  `host_away` at the placement's 300 ms bound, under 2 s with the test's margin.
- On a real host, a placement costs one more ssh connection than before (the find), and one more
  the first time for the rsync's version. Not measured against the Mac: no test here reaches it.

## Tests

- `caf_hosts/test/hosts_test.exs`: a host with every program is ready and a `:reach` read costs
  no ssh; a ready host that stops answering refuses new work and joins once back (`NotPlacedAway`);
  a host that never answers is refused at the bound (`Answered`); two missing programs are named
  and found once added (`MissingOnlyLacking`); an openrsync is refused with its line; an
  undeclared host is refused by name.
- `caf_surface/test/remote_host_test.exs`: the whole tree with `agents: false` and a remote host
  in its config, on a stand-in ssh with the host's own `PATH`. A job runs there; a job on the host
  without dtach is refused `{:no_program, "mac", [:dtach]}` with no row, and the next runs once
  dtach is back; a job on the host away is refused `host_away` within its 2 s start bound with no
  row, and the next runs once it is back, with no restart.

The brief's fourth test, two heavy runs on a remote host with two slots and a third queued, goes
with item 3.

## Findings

### new-1. Only a find tells that a ready host still answers

What happened: the brief asks for a host away to be refused within a stated bound, and for its
programs to be kept. A kept `ready` host that went to sleep would take new work, and the work
would then fail late, at the sync's 60 s timeout. The model's `Break_Host_KeptReady` shows it.

Why: nothing else reads the host between placements. ssh here opens one connection per command,
with no shared connection to watch.

What I did: every placement finds again, bounded by its start timeout; the programs kept serve
only reads of work already placed. This is one ssh connection per placement.

What the design should change: nothing, I recommend, unless a placement's cost is measured to
matter on the Mac. A shared ssh connection per host (`ControlMaster`) would make the find cost
a round trip, and is a mechanism of its own to decide.

### new-2. An app that names a part only in tests cannot declare it

What happened: a `Jobs` test of a host found by `Hosts` declared `caf_hosts` for `caf_jobs`. The
deps gate refused it as unused by the code, and Mix refused `only: :test` because `caf_copies`
declares it for every environment.

What I did: the tests of a job on a remote host are the tree's, in `caf_surface`, which uses both
apps in its code and so also covers the config and the wiring.

What the design should change: nothing.

### new-3. The rsync check keeps the first answer for a path

What happened: a host found ready with an rsync at a path is not asked that rsync's version again,
so a placement costs one ssh. A host refused for an old rsync is not ready, so its next placement
asks again, and an upgrade in place (Homebrew keeps one path across versions) is seen. Only an
older rsync put at the same path of a ready host is not seen until the tree restarts.

What the design should change: nothing, I recommend.

### new-4. The find reads the PATH ssh gives, not the host's `env`

What happened: `Programs.find/3` runs `/bin/sh` over ssh, so it looks programs up on the `PATH`
sshd gives a command. On macOS that is `/usr/bin:/bin:/usr/sbin:/sbin` unless the account's
shell setup read for a command (zsh's `~/.zshenv`) adds more. Homebrew's `/opt/homebrew/bin` is
not on it, so programs added there are refused as missing. The entry's `env` `PATH` is used only by
programs held there.

What I did: nothing more; the refusal names each program, so the operator sees it at once.

What the design should change: I recommend the find take the entry's `env` `PATH` when it names
one, so one declaration says where the host's programs are. Until then, the operator adds
Homebrew's directory to `~/.zshenv` on the Mac.

### new-5. A tree test's instance name is held by the VM

What happened: `remote_host_test` first named its instance `"t"`, as `surface_test` does. In
one of three gate runs it was refused `{:instance_running, "t"}`, since both modules run at once.

What I did: the test names its instance `remote-<unique integer>`, as `conversation_test` does.

What the design should change: nothing.
