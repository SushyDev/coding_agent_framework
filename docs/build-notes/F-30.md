# F-30: headless delegates (design)

## What was built

Design only, no code. The owner decided that delegates run headless and parents stay
interactive (`--remote-control` starts only an interactive session). `docs/design.md` gains a
"Headless delegates" section and changes to match:

- A delegate runs `claude -p` with stream-json input and output, `--replay-user-messages` and a
  `--session-id` the framework chose. dtach holds a wrapper that keeps its stdin pipe open and
  appends its stdout to an event log, so it outlives the framework.
- Writes to a delegate are JSON lines on stdin through the host's one writer; turns end with the
  `result` event; a delivered message is seen as its replay in the log; permissions come as
  events and are answered on stdin; there is no trust dialog.
- A new part, `Stream`: a delegate's stdin and event log. `Screen` reads only a parent's screen,
  from fixtures a person captures once per release with a script.
- A delegate's viewer renders its event log. Its start is confirmed by its first event naming
  the chosen session id.
- Open: whether the stream's events carry rate limits; until then only interactive sessions feed
  `Usage`.

The code built so far assumes interactive delegates in places (`ClaudeCLI`, `Sessions`' start
confirmation by name, `Control`'s typed writes). The units after this one change them, model
first.
