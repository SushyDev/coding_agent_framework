# F-40: process groups and test files, from F-35's and F-39's findings (design)

## What was built

Design only, no code. The "dtach" rules take F-35's findings:

- A kill never reaches a reused id, with one stated assumption: no reuse within the reaper's
  half-second grace after a caller's death. On a host with a small `pid_max`, the reaper sends
  TERM only (new-5).
- A child that ignores TERM and outlives its command keeps running; a program that must not
  leave such children is held as a service (new-3).
- The host app starts each reaper before what runs commands with it, under one supervisor that
  restarts them together, since a reaper's death ends every group it holds (new-6).
- A delegate's claim runs with no reaper, so it outlives the VM (new-1).

From F-39: a row still starting keeps an unknown hold's reason (new-2), and "Tests" says a file
a started process may read is written whole and renamed (new-1). F-39's new-3 (`erl_child_setup:
failed with error 32`) waits for its own unit.

F-35's new-2 (dash as the host's shell) and new-4 (the grace does not end early) need no change
now that no shell starts per command.
