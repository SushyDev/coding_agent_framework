# F-25: `Sessions` does what `Start.tla` checks

## What was built

- **`Sessions`** closes F-21's findings new-1 to new-7. Each place names the `Start.tla` action
  it does.
  - The row keeps the start's deadline, and later the stop's, in wall-clock milliseconds
    (`deadline`, from a `clock:` option). The call's own wait reads the same deadline.
  - `Adopt`: a starting row with no call under way is read when `Sessions` starts, once at its
    deadline (one timer, not a poll), and at each `Registry` cue. It becomes running when its
    file names its live process. Past the deadline, a live socket becomes `orphan` with reason
    `no_session_file`, and only a socket read as dead becomes `refused{interrupted}`.
  - A failed read (the `Holder`, a missing or dead `Registry`, an unread one, a liveness `ps`
    that failed) is `{:unknown, _}` and decides nothing.
  - `ReRead`: an unknown row becomes running when its file names its live process, and
    stopped when its socket is dead.
  - `StopSettled` with no call under way: by pid and start time, stopped when gone. A row
    whose process lives becomes running after a restart, unless its stop was late.
  - `RowWritten` takes a name only over `stopped` or `refused`.
  - `Held`: only a refused hold ends the start. A hold that answers unknown opens the viewer
    and waits for the file like any other start.
- **New-9.** A stop whose process lives at its deadline answers `{:unknown, {:no_exit, typed}}`
  as before. Its row now stays `stopping`, with reason `no_exit` and the stop's deadline.
  `Sessions` never kills.
- **`Sessions.cue/2`**, a new public function. The host app wires a `Registry`'s `notify` to
  it. The other public functions keep their names and answers.
- **`Sessions.Table`** gains the `deadline` column (added to a file made before it) and the
  `orphan` status.
- **`Start.tla`**: `StopTimedOut` now leaves the row `stopping` and marks it `late`.
  `StopSettled` does not set a late row back to running. `Kill` is `Recoveries`' step and
  takes only a late row. `READING.md` says so.
- **`docs/design.md`**: the `Recoveries` row and the start paragraph now say who kills and how,
  and record the rules above.
- **Tests**: one per finding, on the test's own clock. Run against the old `sessions.ex`, each
  one fails.

## What I ran into

- Running the new tests against the old code made 9 of 11 fail. The clock was part of why,
  since the old code waits on monotonic time. Each test's own assertion also fails on the
  behavior it names.
- To make a stop late without a sleep, the test stops the stand-in with `kill -STOP` by its
  pid, then continues it.
- A dtach that holds and then exits 3 makes `Holder.hold/4` answer unknown with a live process.
  It is a wrapper in the test's directory, given through `Programs`.

## Findings

### new-1. The main agent's stop rule changed `Start.tla`

What happened: in `Start.tla`, `StopTimedOut` wrote `unknown`, and `ReRead` could then set the
row back to running. The rule that `Recoveries` kills a process that did not exit by its stop's
deadline needs the row to stay `stopping`.

What I did: added `late` to the spec, the code's `reason: "no_exit"`. Every fast and break
configuration runs as before.

What the design should change: nothing more. The start paragraph now says this.

### new-2. A dead socket with no file change gives no `Registry` cue

What happened: `Registry` cues only when its rows change. An unknown row whose process never
wrote a file and then exits changes no file. `ReRead` then waits for some other change.

What the design should change: let `TmuxSampler`'s held-socket sample cue `Sessions` too, or
name the cue that carries a socket's death.

### new-3. A restart in the middle of a stop sets a live row back to running

What happened: as the spec says, a stopping row whose process lives is set back to running
after a restart. `/exit` may already have been typed, and the process may exit a moment later.
Nothing then reads a running row whose process is gone.

What the design should change: say who notices a running row whose process is gone (likely
`Recoveries`, from `Registry`'s liveness).

### new-4. A failed read at a starting row's deadline waits for the next cue

What happened: after a restart there is one timer per starting row, at its deadline. If the read
at that moment fails, nothing reads the row again until a `Registry` cue comes. This follows
the rule that no hidden retry is added.

What the design should change: nothing, unless a row must settle without a cue. In that case,
name the cue.

### new-5. `erl_child_setup: failed with error 32` printed once

What happened: one of three `gate-test` runs printed this line in the middle of its dots. All
114 tests passed and the run exited 0. I did not find its cause. Error 32 is a broken pipe. The
tests kill a `Sessions` in the middle of a call, so a port's child may write after its port has
closed.

What the design should change: nothing yet. If it shows up again, find which test prints it.

### new-6. A reader that opens `Sessions.Table` also adds the column

What happened: `Table.open/1` adds the `deadline` column to a file made before this unit, and
ignores the error when the column is already there. Readers open the table with the same
function, so they run this write too, as they already run `CREATE TABLE IF NOT EXISTS`.

What the design should change: nothing for now. Say how a table's schema changes once more
than one part writes schema.
