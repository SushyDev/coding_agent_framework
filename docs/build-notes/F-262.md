# F-262: caf-login makes the home's git folder before the gh step

Built by the main session.

## What happened

On a Linux host, `bin/caf-login --setup <home> <accounts>` passed both accounts. At its GitHub
step, the device login completed, then gh failed with "failed to run git: error: could not lock
config file <home>/git/config: No such file or directory", and setup stopped. The home held only
`accounts`, `checkouts`, `gh` and `xdg`.

## Why

caf-login sets `GIT_CONFIG_GLOBAL=<home>/git/config`, so that git's state stays in the home.
`gh auth login` writes git's global config itself (its git credential setup). The gh step made
`gh` and the `xdg` folders, but not `git`, and the folder is otherwise made only by `--git`,
which runs after the gh step.

## What was built

- The gh step makes `<home>/git` with the other folders.
- The login test's gh stand-in writes `$GIT_CONFIG_GLOBAL` at `auth login`, as gh does. Without
  the fix, two of the login tests fail (5 of 7 pass); with it, all 7 pass.

## Findings

None.
