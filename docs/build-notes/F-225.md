# F-225: a headless session's viewer ends with it

## What was built

When a headless session's row turns `stopped` or `ended`, `Sessions` ends its viewer's tmux
session (`close_viewer/3`, called from `write/3`, which every status change goes through). An
interactive session's viewer is `dtach -a`, which ends with the process. A headless one's is
`tail -F` of the event log, which never does. The kill is best effort: the viewer is only a
person's window, and a viewer already gone or a server that is down changes nothing. A resume
opens a new viewer.

The headless stop test now checks that the viewer is there before the stop and gone after. It
fails without the change.

## What was measured

The macOS end-to-end run (2026-11-23, step 14, e2e-15) ended six delegates. The three headless
ones' viewer sessions (`tail -F` of `events.jsonl`) were still on the home's tmux server after
their rows read `ended`. Each event log ended with the framework's end-session
`control_response`, so the processes had ended. Only the viewers stayed.
